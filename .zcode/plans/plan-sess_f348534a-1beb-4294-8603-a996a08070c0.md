# 实施计划:计划展示优化 + 本轮文件卡片去主题色 + 流式渲染性能优化

## 需求1:计划内容改为消息流内联折叠卡片 + 轻量审批浮层

### 现状
- `PlanApprovalPrompt` 是悬浮在 composer 上方的大卡片,含完整 plan Markdown 渲染 + 编辑 + 审批,占据输入区视野。
- 计划文本已在 `plan_draft` DB 列持久化 + `hydrateCapsule` 恢复,但 turn.done 会把 `planBySession` 清成 `{plan:"",phase:"cleared"}`,导致计划在 turn 结束后从 UI 消失。

### 改动

**A1. 新增 `PlanStreamBlock` 组件** — `apps/desktop/src/renderer/components/chat/PlanStreamBlock.tsx`
- 渲染在消息流末尾、TurnFilesCard 之前(同为 turn 尾部卡片)。
- 显示条件:`planBySession[sid].plan` 非空且 phase 为 `drafting`/`ready`,或 `pendingPlanApproval` 存在。
- 折叠态:标题行 "计划" + 状态标签(草拟中/已就绪) + 字符数摘要 + 展开箭头。默认折叠(plan 长度 > 200 时)。
- 展开态:完整 plan 的 `<Markdown>` 渲染,max-h 限制 + overflow-auto。
- 样式:中性 token(`bg-surface-muted/40 border-edge text-content-muted`),不用 accent。
- 编辑功能不在此组件——保持纯只读展示。

**A2. ChatPane 嵌入 PlanStreamBlock** — `ChatPane.tsx`
- 在 `renderItems.map(...)` 之后、TurnFilesCard 之前插入:
  ```tsx
  {(plan.plan && plan.phase !== "cleared") || pendingPlanApproval ? (
    <PlanStreamBlock plan={pendingPlanApproval?.plan ?? plan.plan} phase={plan.phase} hasApproval={!!pendingPlanApproval} />
  ) : null}
  ```

**A3. 精简 `PlanApprovalPrompt`** — `PlanApprovalPrompt.tsx`
- 移除完整 plan body 的只读 Markdown 区(那个 max-h-64 的滚动区域)。
- 默认态:单行紧凑条 —— "计划已就绪 · 请审阅" + [批准并执行] [拒绝] [编辑]。
- 编辑态:textarea 展开(仅此时占空间),编辑完点"完成编辑"回到紧凑态。
- 拒绝态:展开理由输入(保持现有逻辑)。
- 这样浮层始终轻量,不挡用户查看消息流中的计划卡片。

**A4. turn.done 不清空已批准的计划** — `sessionStore.ts`
- turn.done 分支(L1477-1486):`planBySession` 的清理改为条件式 —— 若 phase 为 `ready` 且 plan 非空,保留(让计划卡片留存到下一轮);仅在 phase 为 `drafting`/`cleared` 时清空。
- 这样已批准计划在 turn 结束后仍显示在消息流;下一轮 sendPrompt 时新 turn 自然覆盖。
- 持久化已由 RuntimeManager.emit 拦截 `plan.update` 写 `plan_draft` 列 + hydrateCapsule 恢复,无需改。

## 需求3:流式渲染性能优化(四项)

### B1. Delta 批量合并(核心)— `sessionStore.ts`
- 在 `ingestEvent` 的 `text.delta`/`thinking` 分支前增加缓冲层:
  - 模块级 `deltaBuffers: Map<messageId, { text: string; thinking: string }>` 累积增量。
  - 用 `queueMicrotask` 或 `requestAnimationFrame` 调度 flush(浏览器环境用 rAF,~16ms)。
  - flush 时一次性追加累积文本到对应消息的 block,触发一次 setState。
- 效果:5000 字符级输出从 ~5000 次 setState 降至 ~60 次/秒。
- 终止事件(`turn.done`/`error`/`message.complete`)强制 flush 残留缓冲。

### B2. 流式期用纯文本 — `Markdown.tsx` + `MessageBlocks.tsx`
- `Markdown` 用 `React.memo` 包裹,自定义比较:仅当 `children` 字符串引用变化才重渲染(已完成消息的 text 引用稳定,不重解析)。
- `BlockView` 的 text 分支:当 block 属于流式尾部(`isStreamingTail`)时,渲染廉价 `<div className="whitespace-pre-wrap">` 纯文本;流式结束(block 完成 / turn.done)后切换到 `<Markdown>`。
- 需要把 `isStreamingTail` 传递到 BlockView 层级(MessageRow → MessageBlocks → BlockView)。

### B3. 消息行 memo 化 — `ChatPane.tsx` + `MessageBlocks.tsx`
- `MessageRow` 用 `React.memo` 包裹,比较 `msg` 引用 + `isStreamingTail` + `isLastCompletedAssistant` + `beforeMap`。
- 因 store 的 `next.map` 仅替换变更消息,历史消息引用不变,memo 后跳过重渲染。
- `MessageBlocks` / `BlockView` 同样 `React.memo`。

### B4. 滚动节流 — `ChatPane.tsx` + `MessageTimeline.tsx`
- ChatPane 自动滚动 effect(L454-459):改用 rAF 合并;流式期 `behavior:"auto"`,仅手动 `jumpToBottom` 用 `"smooth"`。
- `updateJumpState` effect(L448-451)合并到同一 rAF。
- MessageTimeline:`computeActive` 用 rAF 节流;effect 依赖去掉 `messages`(滚动监听只绑一次,不随 messages 重订阅)。

## 风险
- **Delta 批量合并**:若 flush 时序有 bug 可能丢字。终止事件强制 flush + 原子 Map 操作兜底。
- **流式纯文本**:流式期无 Markdown 格式(代码块/列表不渲染),完成后才切。视觉有一瞬切换,可接受。
- **MessageRow memo**:需确保 beforeMap 引用稳定(已是 useMemo),否则 memo 失效。
