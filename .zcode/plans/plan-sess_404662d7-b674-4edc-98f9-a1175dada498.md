## 架构

```
Renderer                         Preload              Main
────────                         ───────              ────
TerminalPanel                    api.terminal.*       TerminalManager
 ├─ session tabs                 api.on.terminalData    Map<terminalId, IPty>
 ├─ TerminalView (xterm)         api.on.terminalExit    spawn/write/resize/kill
 │    FitAddon + 主题                                   cwd 必须 ∈ project root
 └─ projectPath from store
        │ write/resize                 │
        └──── invoke ─────────────────►│
        ◄──── push data/exit ──────────┘
```

- **cwd**：默认 `activeProject.path`（与 Files/Git 一致）
- **生命周期**：切换 right tab 时 **不杀 PTY**；xterm 实例按 terminalId 保留（hide/show 或抬到 tab 外），避免丢输出
- **切项目**：旧项目 terminals dispose；新项目按需创建
- **安全**：`cwd` 必须落在已知 `Project.path` 内（复用 files/git 的 `pathWithin` 思路）；不接受任意路径 spawn

## 实现步骤

### 1. 依赖与原生模块

在 `apps/desktop`：

- **renderer**: `@xterm/xterm`, `@xterm/addon-fit`（新 scope；避免旧 `xterm` 包）
- **main**: `node-pty`
- dev：`@electron/rebuild`（或 `electron-rebuild`）
- scripts 示例：
  - `"rebuild:native": "electron-rebuild -f -w node-pty"`
  - `postinstall`（desktop 包）在有 electron 时 rebuild

`electron.vite.config.ts`：

- main 侧确保 `node-pty` **external**（不要打进 bundle；native addon 需运行时加载）
- renderer 正常打包 xterm CSS（`TerminalPanel`/`TerminalView` 里 `import '@xterm/xterm/css/xterm.css'`）

Windows 注意：

- 需能编译/下载 node-pty prebuild（对应 Electron 33 ABI）
- shell 启动用完整可执行路径或 `where`/`command -v` 探测；避免 spawn ENOENT
- 可选：后续 package 时 `asarUnpack: "**/node_modules/node-pty/**"`（P6；dev 先跑通）

文档：在 `docs/tech-stack.md` 补一小节「node-pty 引入与 rebuild」。

### 2. Contracts（`packages/contracts/src/ipc.ts`）

在现有 `TerminalDataMessage` 旁补全：

**RPC input schemas（zod）**

- `terminal.create` → `{ projectPath: string; cwd?: string; cols?: number; rows?: number; shell?: string }`  
  → `{ terminalId: string; pid: number; cwd: string; shell: string }`
- `terminal.write` → `{ terminalId: string; data: string }` → `{ ok: boolean }`
- `terminal.resize` → `{ terminalId: string; cols: number; rows: number }` → `{ ok: boolean }`
- `terminal.kill` → `{ terminalId: string }` → `{ ok: boolean }`
- `terminal.list`（可选但推荐）→ `{ projectPath?: string }` → `{ terminals: TerminalInfo[] }`
- `terminal.clear` **不必走 main**（xterm 本地 clear 即可）

**Push**

- 保留 `terminal:data`：`{ channel, terminalId, data }`
- 新增 `terminal:exit`：`{ channel: "terminal:exit"; terminalId; exitCode: number | null }`  
  → 加入 `MainToRendererMessage` + `IPC.TERMINAL_EXIT`

**RpcMap + IPC 常量** 同步登记（与 git 段同风格）。

可选设置 key（不必第一版 UI 很重）：

- `terminal.shell` — 用户覆盖默认 shell  
  经现有 `setting.get` / `setting.set` 即可，无需新通道。

### 3. Main：`TerminalManager` + IPC

新建：

- `apps/desktop/src/main/terminal/TerminalManager.ts`
- `apps/desktop/src/main/ipc/terminal.ts`
- 在 `apps/desktop/src/main/ipc/index.ts` 注册
- `before-quit` / `window-all-closed` 时 `TerminalManager.disposeAll()`（`apps/desktop/src/main/index.ts`）

**TerminalManager 职责**

- `create({ cwd, cols, rows, shell? })` → `node-pty.spawn(shell, args, { name: 'xterm-256color', cols, rows, cwd, env })`
- env：基于 `process.env`，补 `TERM=xterm-256color`；Windows 可设 `COLORTERM`
- `onData` → `sendToRenderer(IPC.TERMINAL_DATA, { channel, terminalId, data })`
- `onExit` → `sendToRenderer(IPC.TERMINAL_EXIT, …)` 并从 Map 删除
- `write` / `resize` / `kill`（`pty.kill()`）
- id：`crypto.randomUUID()`

**路径守卫**（与 files/git 一致，可小范围抽 `pathWithin` 到 `main/lib/pathGuard.ts` 去重，可选）：

- `projectPath` 必须对应已持久化 Project
- `cwd` 若提供，必须 `pathWithin(projectPath, cwd)`；否则 `cwd = projectPath`

**Shell 解析**（`resolveDefaultShell()`）：

| 平台 | 顺序 |
|------|------|
| win32 | setting → `pwsh.exe` → `powershell.exe` → Git `bash.exe` → `cmd.exe` |
| darwin/linux | setting → `process.env.SHELL` → `/bin/bash` → `/bin/zsh` → `/bin/sh` |

Windows 参数：

- powershell: `['-NoLogo']`
- cmd: `['/K']` 或默认
- bash: `['--login']`（若用 Git Bash）

错误策略：create 失败返回 `{ ok:false }` 或 throw 由 handler 转成结构化错误；**不要**让未捕获异常打崩 main。与 git 一样 degrade gracefully。

### 5. Renderer UI

#### 5.1 挂载

`RightPanel.tsx`：Placeholder → `<TerminalPanel />`

#### 5.2 新组件

`apps/desktop/src/renderer/components/ide/TerminalPanel.tsx`

- 解析 `projectPath`（同 FilesPanel/GitPanel）
- 无项目 → empty state
- 顶栏：会话 tabs + `+` + 关闭 + 清屏 + 杀进程/重开
- body：当前 active 的 `TerminalView`

`apps/desktop/src/renderer/components/ide/TerminalView.tsx`

- 挂载 xterm + FitAddon
- `open` 后 `terminal.create`，拿到 `terminalId`
- `onData` → `api.terminal.write`
- 订阅 `api.on.terminalData` / `terminalExit`（按 id 过滤）
- `ResizeObserver` + tab 可见时 `fit()` → `api.terminal.resize`
- dispose：组件真正卸载且要杀会话时 `kill`；仅切 right tab 时尽量 **keep-alive**

**Keep-alive 推荐实现（避免切 tab 丢终端）**：

- `RightPanel` 对 terminal 用 CSS 隐藏而非卸载：  
  `hidden={tab!=='terminal'}` 仍挂载 `TerminalPanel`  
  或 `TerminalPanel` 内部用 display 控制  
- Files/Git 可保持条件渲染（现状）

#### 5.3 主题

仿 `FileEditor` 的 `useMonacoTheme`：

- `useXtermTheme()` 观察 `html.dark`
- 映射 zinc/emerald token 到 xterm `ITheme`（hex，不能靠 Tailwind class）
- background 用 surface-muted / surface，foreground 用 content，cursor 用 accent

#### 5.4 状态

**V1 不进 sessionStore**（store 已很大）：

- `TerminalPanel` 本地 state：`sessions[]` / `activeId`
- 也可用模块级 `Map` 在 StrictMode 双 mount 下更稳

若后续要「从文件树打开终端」，再升到 store + `ideFocusNonce` + `setRightPanelTab('terminal')`。

#### 5.5 布局修复（xterm 关键）

`ThreePaneLayout` 右栏现为 `overflow-y-auto`，会破坏 fit：

- 右栏容器改为 `overflow-hidden`（或 `min-h-0 overflow-hidden`）
- Files/Git **内部**已有 `overflow-y-auto`，不受影响
- Terminal host：`h-full min-h-0 flex flex-col`，xterm 容器 `flex-1 min-h-0`

### 6. 设置（轻量，可第二刀）

- Settings 增加「默认 Shell」文本框或选择，写入 `setting` key `terminal.shell`
- 无 UI 时仅智能默认也可合并 MVP

### 7. 验证清单

1. `pnpm` 安装 + `rebuild:native` 成功（Win）
2. `npx tsc --noEmit -p apps/desktop/tsconfig.json`
3. 手动：
   - 开项目 → Terminal tab → 看到 prompt
   - 输入 `echo hi` / `dir` 有输出
   - 缩放窗口 / 折叠右栏再打开 → fit 正常、无乱行
   - 多 tab 互不串输出
   - 切 Files 再回 Terminal → 会话仍在
   - 切项目 → 旧 PTY 清理，新 cwd 正确
   - 主题切换 → xterm 颜色更新
   - 退出进程（`exit`）→ UI 显示已退出，可点重开
4. 安全：伪造 cwd 到项目外 → main 拒绝

- 左右/上下 split pane
- 终端滚动历史持久化 / 重启恢复 PTY
- 链接点击、图形成像协议
- Claude 工具输出自动 pipe 到终端
- 文件树右键 “在终端中打开”（建议 follow-up，半小时级）

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| node-pty 在 Win + Electron 33 编译失败 | prebuild + electron-rebuild；文档写明 VS Build Tools 需求；失败时 UI 明确报错而非白屏 |
| StrictMode 双 mount 双开 PTY | create 幂等 / ref 守护；kill 仅在真实卸载 |
| 切 tab 丢终端 | RightPanel keep-alive 挂载 TerminalPanel |
| 输出风暴卡 UI | xterm 自带性能尚可；必要时 main 侧批量（V1 可不做） |
| 360px 过窄 | 单列 shell + 紧凑 toolbar；resize 右栏仍属 P5 |

## 建议实施顺序

1. contracts + preload 类型面  
2. TerminalManager + ipc + rebuild 跑通「create/write/data」无 UI（可临时 log）  
3. TerminalView 最小 xterm  
4. TerminalPanel 多会话 + keep-alive + 主题 + 布局 overflow  
5. 退出/重开/清屏打磨 + typecheck + 手动验收  
6. （可选）shell 设置项 / Open in Terminal follow-up

按此顺序可先验证原生模块，再堆 UI，避免 UI 写完却 spawn 失败。
