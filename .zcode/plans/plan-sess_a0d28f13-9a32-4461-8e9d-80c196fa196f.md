## 功能：计划审批弹框点「编辑计划」→ 在编辑器中打开 Monaco 编辑 → 保存回填

### 背景

当前 `PlanApprovalPrompt`（审批弹框）的「编辑计划」按钮展开的是一个内联 `<textarea>`，编辑后点「批准(已编辑)」把 `editedPlan` 回传 SDK。用户希望改成：点「编辑计划」→ 在右侧编辑器列用 Monaco 打开 → 编辑 → 保存 → 回填计划内容。同时 `PlanViewer`（查看历史计划）也支持编辑。

### 用户已确认的决策

1. **保存语义**：编辑器保存后回填到审批弹框（draft），用户仍需在弹框点「批准并执行」才真正提交给 SDK。编辑器保存 ≠ 批准。
2. **编辑入口**：审批弹框 + PlanViewer 查看器都能进入编辑。

---

### 实现步骤

#### 1. sessionStore：新增「审批草稿」字段与 action

**文件**：`apps/desktop/src/renderer/stores/sessionStore.ts`

在 state 接口（~L368 后）和初始值（~L1783 后）新增：
```ts
/** Per-session edited draft of a pending plan approval. When the user edits
 *  the plan in the Monaco editor (opened from the approval prompt), the
 *  edited text is staged here so PlanApprovalPrompt can pick it up as its
 *  draft and the user still confirms via 批准并执行. Cleared on
 *  submitPlanApproval / closePlanDrawer. */
planApprovalDraftBySession: Record<string, string>;
```

新增 action（接口 ~L661 附近 + 实现 ~L3731 附近）：
```ts
/** Stage an edited plan draft (from the Monaco editor) for a pending
 *  approval. PlanApprovalPrompt reads this as its initial draft. */
setPlanApprovalDraft: (sessionId: string, draft: string) => void;
/** Update the plan text shown in the plan tab (PlanViewer). For viewing
 *  history edits this updates the local view model only. */
updatePlanDrawerPlan: (sessionId: string, plan: string) => void;
```

- `setPlanApprovalDraft`：写入 `planApprovalDraftBySession[sid] = draft`。
- `updatePlanDrawerPlan`：写入 `planDrawerPlanBySession[sid] = plan`（若已为 null 则不设置）。

在 `submitPlanApproval` 成功分支（~L3686）、`closePlanDrawer`（~L3714）、`resetSession`（~L2536）里清除 `planApprovalDraftBySession[sid]`。

> **边界说明**：历史（已冻结）计划的编辑只更新 `planDrawerPlanBySession` 本地视图，不回写消息流中的冻结 plan block、不持久化。原因：已冻结计划无 SDK 回传路径，回写需要走 `SESSION_SAVE_MESSAGES` 且语义复杂；本次聚焦用户描述的审批场景，保持简单。PlanViewer 编辑历史计划时，保存仅影响当前查看态。

#### 2. PlanApprovalPrompt：改「编辑计划」为打开编辑器，读取 store draft

**文件**：`apps/desktop/src/renderer/components/chat/PlanApprovalPrompt.tsx`

- 移除内联 `editing` / `draft` textarea 逻辑。
- `draft` 初始值改为从 store 读取：`const draft = useSessionStore(s => s.planApprovalDraftBySession[sessionId] ?? plan)`（需传入 `sessionId` prop）。
- 「编辑计划」按钮 onClick：调用 `onEditPlan()`（新 prop），由 ChatPane 负责打开编辑器并激活计划 tab。
- `edited` 判定：`draft.trim() !== plan.trim()`。
- `handleApprove`：`onApprove(edited ? draft : undefined)`（逻辑不变，draft 现在来自 store）。
- 新增 prop：`sessionId: string`、`onEditPlan: () => void`。

#### 3. ChatPane：连接审批弹框与编辑器

**文件**：`apps/desktop/src/renderer/components/chat/ChatPane.tsx`（~L1150 渲染处）

`PlanApprovalPrompt` 调用改为传入：
```tsx
<PlanApprovalPrompt
  sessionId={sessionId}
  plan={pendingPlanApproval.plan}
  onEditPlan={() => {
    // 打开计划 tab 并进入编辑模式：用 pending plan（或已有 draft）作为内容
    const draft = useSessionStore.getState().planApprovalDraftBySession[sessionId];
    openPlanDrawer(sessionId, draft ?? pendingPlanApproval.plan);
  }}
  onApprove={(editedPlan) => void submitPlanApproval(pendingPlanApproval.requestId, true, editedPlan)}
  onReject={(reason) => void submitPlanApproval(pendingPlanApproval.requestId, false, undefined, reason)}
/>
```

需要从 store 取 `openPlanDrawer`（ChatPane 内已有 `openPlanDrawer` 引用，见 L958）。

#### 4. PlanViewer：增加编辑模式（Monaco）

**文件**：`apps/desktop/src/renderer/components/chat/PlanViewer.tsx`

扩展 props 与内部状态：
```tsx
export function PlanViewer({
  plan,
  sessionId,
  isApprovalPending,   // 是否处于审批中（决定保存目标）
  onClose,
}: { ... })
```

- 头部加「编辑」/「完成编辑」按钮（`IconPencil` / `IconCheck`），与关闭按钮同行。
- `editing` 状态：false = 渲染 Markdown（现状）；true = 渲染 Monaco `<Editor>`。
- Monaco 用法复用 FileEditor 的 EditPane 模式：
  - `import { Editor } from "@monaco-editor/react"`、`import { useMonacoTheme, languageForExt } from "../ide/FileEditor.js"`。
  - `language="markdown"`、`theme={useMonacoTheme()}`、`path="__plan__.md"`（唯一 model）。
  - 内部 `draft` state 初始为 `plan`；`onChange` 更新 draft 并计算 dirty（`draft !== plan`）。
  - **Ctrl+S**（`editor.addCommand(monaco.KeyMod.CtrlCmd | monaco.KeyCode.KeyS, ...)`）触发保存。
  - options 同 FileEditor：minimap 关、wordWrap on、fontSize 12、lineNumbers on、automaticLayout。
- 保存逻辑（保存按钮 + Ctrl+S）：
  - 调 `updatePlanDrawerPlan(sessionId, draft)` 更新查看态文本。
  - 若 `isApprovalPending`：额外调 `setPlanApprovalDraft(sessionId, draft)` 回填审批弹框。
  - 显示「已保存 ✓」toast（复用 FileEditor 的 saveState 模式：idle/saving/saved/error）。
  - 保存后可切回只读态（`setEditing(false)`）或留在编辑态（我倾向于留在编辑态，让用户自行切换，保存后 dirty 清除）。
- 取消编辑：放弃 draft 改动，`setEditing(false)`。
- **懒加载 Monaco**：用 `React.lazy(() => import("@monaco-editor/react").then(m => ({default: m.Editor})))` + `<Suspense>`，与 FileEditor 一致（FileEditor 整体已被 App.tsx 用 lazy/Suspense 包裹）。PlanViewer 本身在 EditorColumn 内同步渲染，所以编辑态内部用 lazy 加载 Editor。

#### 5. App.tsx EditorColumn：给 PlanViewer 传入新 props

**文件**：`apps/desktop/src/renderer/App.tsx`（~L308）

```tsx
{showPlan ? (
  <PlanViewer
    plan={planText!}
    sessionId={activeSessionId!}
    isApprovalPending={!!pendingPlanApproval}
    onClose={() => activeSessionId && closePlanDrawer(activeSessionId)}
  />
) : ...}
```
需要在 EditorColumn 内额外订阅 `pendingPlanApprovalBySession[activeSessionId]` 以传 `isApprovalPending`。

#### 6. OpenTabsBar：计划 tab 显示 dirty 指示（可选增强）

**文件**：`apps/desktop/src/renderer/components/ide/OpenTabsBar.tsx`

当计划编辑中且有未保存改动时，计划 tab 显示 dirty 圆点（复用 `ideDirtyTracker`，用 `PLAN_TAB_KEY` 作为 key）。此为增强项，可在主体功能完成后补充。**本次先不做**，避免 dirty tracker 跨 plan/file 语义混淆；PlanViewer 内部已有保存状态指示。

### 验证

- `cd apps/desktop && npx tsc --noEmit -p tsconfig.json` 通过。
- 手动验证流程：
  1. 进入 plan mode，模型产出计划 -> 审批弹框出现 -> 点「编辑计划」-> 右侧编辑器列打开 Monaco 计划编辑器。
  2. 编辑计划文本 -> Ctrl+S 保存 -> 回到审批弹框，draft 已更新（「已编辑」标记）-> 点「批准并执行」-> SDK 用编辑后的计划继续。
  3. 查看历史计划 -> PlanViewer 点「编辑」-> 编辑保存 -> 查看态文本更新。
