## 修复方案:自定义模型 (DeepSeek) 在实时 turn 中失败

### 根因诊断(基于新证据)

经过深入调查,推翻了之前重构基于的错误前提。**关键证据**:

1. **连接测试成功**(用 Sonnet 角色,模型 `deepseek-v4-flash`),但**实时 turn 失败**(用 Fable 角色,模型 `deepseek-v4-pro`)。
2. 两次失败日志显示二进制内部把 `[1M]` 规范化为 **小写 `[1m]`** —— 这其实是 **DeepSeek 的官方规范形式**(文档里写的就是 `deepseek-v4-pro[1m]`)。之前注释里"DeepSeek 把 `[1M]` 小写后无法路由"的说法**完全错误**。
3. SDK 深度调查证实:claude 二进制**同时读 `ANTHROPIC_MODEL` 环境变量和 `--model` CLI 参数**,错误来自**网关返回的 HTTP 404**(服务器端拒绝),不是客户端模型名校验。
4. **`ANTHROPIC_MODEL` 是 DeepSeek 官方文档明确要求设置的环境变量**,我之前的重构把它删了——这是错的。

### 之前的重构错在哪

- ❌ 删掉了 `ANTHROPIC_MODEL`(DeepSeek 文档要求设置)
- ❌ 用 `[1M]` 大写并声称"DeepSeek 不认小写"(实际相反,小写才是规范)
- ❌ 改用 `options.model` (`--model` flag) 覆盖 —— 但二进制本来就读 `ANTHROPIC_MODEL`,两套机制并存只会制造不一致
- ❌ 把 tier env var 的 `[1m]` 后缀也剥掉了

### 新方案:对齐 DeepSeek 官方规范配置

DeepSeek 官方文档的 Claude Code 配置(已验证可用):
```
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
ANTHROPIC_AUTH_TOKEN=<key>
ANTHROPIC_MODEL=deepseek-v4-pro[1m]
ANTHROPIC_DEFAULT_OPUS_MODEL=deepseek-v4-pro[1m]
ANTHROPIC_DEFAULT_SONNET_MODEL=deepseek-v4-pro[1m]
ANTHROPIC_DEFAULT_HAIKU_MODEL=deepseek-v4-flash
```

### 改动(4 个文件,全部是回退 + 修正)

#### 1. `customEnv.ts`(核心)
- **恢复 `ANTHROPIC_MODEL` 赋值**:设为选中角色的模型,**带 `[1m]` 小写后缀**(当 `supports1m` 时)。
- **`[1m]` 大小写修正**:把 `with1MSuffix` 从 `[1M]` 改成 `[1m]`(DeepSeek 规范)。函数名保留 `with1MSuffix`(语义不变,只是输出小写)。
- **恢复 tier env var 的 `[1m]` 后缀**:选中角色的 tier env var 也带后缀(对齐官方文档);非选中 tier 用 bare 名(后台请求短上下文)。
- **保留** `resolveActiveModel` 导出(probe 仍用它解析模型),但 live turn 不再用它覆盖 `options.model`(见下)。
- **重写顶部注释**:纠正关于 `[1m]` 大小写、`ANTHROPIC_MODEL`、`options.model` 的所有错误描述。

#### 2. `ClaudeAgentSdkProvider.ts`
- **移除 `options.model = resolveActiveModel(...)` 覆盖**:让二进制从 `ANTHROPIC_MODEL` 环境变量自己解析(这是它设计的工作方式,也是 probe 能成功的原因 —— probe 其实也不该传 `model`,但它传了相同的值所以碰巧工作)。
- 保留 `resolveActiveModel` 的 import(给 probe 用)。
- 诊断日志里把 `__optionsModel` 字段改回 `ANTHROPIC_MODEL`(现在信息源又变回 env)。
- 修正注释:解释为什么对自定义配置走 `ANTHROPIC_MODEL` 而非 `--model`。

#### 3. `customModel.ts`(probe)
- **保留** `resolveActiveModel` 用法(probe 仍需显式传 `model`,因为它不设 `ANTHROPIC_MODEL` —— probe 的 cfg 只绑一个角色,直接传 model 更直接)。
- 但由于 `with1MSuffix` 现在输出小写 `[1m]`,probe 和 live turn 会自动一致。

#### 4. `RuntimeManager.ts`
- 注释回退到接近原版("env pins ANTHROPIC_MODEL via buildCustomEnv"),因为现在确实又走 env 了。

### 为什么这次会work

1. **`ANTHROPIC_MODEL` 重新设置**,且用 DeepSeek 规范的 `[1m]` 小写 —— 与官方文档完全一致。
2. **不再有 `--model` 和 `ANTHROPIC_MODEL` 两套机制打架** —— 只走 env 这一条路(二进制原生支持)。
3. **`[1m]` 小写**匹配二进制内部规范化和 DeepSeek 网关期望。
4. **tier env var 带后缀**(选中角色)—— 对齐官方文档 `ANTHROPIC_DEFAULT_OPUS_MODEL=deepseek-v4-pro[1m]`。

### 关于 authMode 的提示(不在本次改动范围)

日志显示 `mode=api_key`,但 DeepSeek 官方文档用 `ANTHROPIC_AUTH_TOKEN`(Bearer)。这**可能**是次要因素(网关可能对 x-api-key 返回 404 而非 401 来隐藏端点存在)。但既然 probe 用同样的 api_key 能成功,authMode 大概率不是主因。改动里不强制改用户的 authMode 选择,但在 UI 的认证方式下拉旁边加一行 hint,提示 DeepSeek 推荐 Bearer。
