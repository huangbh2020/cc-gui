## 修复计划审批弹框不触发 + 计划文件保存到全局 .claude 的问题

### 根因（已通过二进制分析、会话 jsonl、日志三方确认）

**Bug 1 — 审批弹框不触发：`supportedDialogKinds` 声明的 kind 全是错的**

claude.exe v2.1.218 中，ExitPlanMode 工具的审批对话框真实 `dialogKind` 是 **`permission_exit_plan_mode_v2`**（二进制偏移 243300318，在 `LBy` 路由表里通过 `KUe({matches:(e)=>e===oz, dialog:fcr, build:qZu})` 绑定，`fcr.kind = "permission_exit_plan_mode_v2"`）。

当前 `ClaudeAgentSdkProvider.ts:343-347` 声明的是：
```js
const EXIT_PLAN_DIALOG_KINDS = new Set(["exit_plan_mode", "ExitPlanMode", "plan_approval"]);
```
这三个**没有一个**匹配真实值。CLI 的门控逻辑（偏移 238712969）是 `ewt() && !(twt() ?? []).includes(dialogKind)` —— 声明的 kinds 不含目标 kind 时 **fail-closed，根本不发出 dialog**。所以 `onUserDialog` 永远不被调用（日志里没有任何 `onUserDialog` 行），ExitPlanMode 拿不到审批通道，turn 结束，tool_result 记录 `is_error: true, "Tool permission request failed: AbortError: Stream closed"`。

**Bug 2 — 计划文件保存到全局 `~/.claude/plans/`：未配置 `plansDirectory`**

claude.exe 在 plan 模式下强制模型先把计划写入 plan 文件再调用 ExitPlanMode（`No plan file found at ${l}. Please write your plan to this file before calling ExitPlanMode.`）。plan 目录由 `Eb()` 解析：读 `plansDirectory` 设置（必须在 project root 内），否则回退到 `~/.claude/plans/`。应用从未传 `plansDirectory`，所以落到全局目录。

### 改动

#### 改动 1：修正 `supportedDialogKinds`（核心修复）
**文件**：`apps/desktop/src/main/providers/claude-sdk/ClaudeAgentSdkProvider.ts`

- 把 `EXIT_PLAN_DIALOG_KINDS` 改为 `["permission_exit_plan_mode_v2"]`（真实 kind）。
- 保留旧的三个值作为**兜底**（防御未来 SDK 版本变更 / 回退），放在数组后面，`has()` 判断仍命中真实值即可。
- 更新注释：把"open union, 候选值"的猜测性措辞改为"已通过 claude.exe v2.1.218 二进制分析确认真实 kind 为 `permission_exit_plan_mode_v2`"，并说明发现方法（`LBy` 路由表 + `fcr.kind`），方便后续 SDK 升级时复核。

```js
const EXIT_PLAN_DIALOG_KINDS = new Set([
  "permission_exit_plan_mode_v2", // 真实值（claude.exe v2.1.218 二进制确认）
  // 兜底：防御 SDK 版本变更
  "exit_plan_mode",
  "ExitPlanMode",
  "plan_approval",
]);
```

#### 改动 2：`onUserDialog` 读取正确的 payload 字段
**文件**：同上，`onUserDialog` 处理函数（348-384 行）

当前只读 `payload.plan` / `payload.input.plan`。真实 payload（`qZu` 构造）字段为 `{requestId, toolName, permissionResult, plan, planFilePath, usage}`。改为优先读 `payload.plan`，兜底 `payload.input?.plan`（保持兼容）。`planFilePath` 目前不透传给 renderer（renderer 用自己的 plan 文本编辑器，不需要文件路径），后续若要做"打开 plan 文件"可再加。

#### 改动 3：配置 `plansDirectory` 指向项目内目录
**文件**：同上，`startTurn()` 构造 `options` 处

在 `options` 里加 `settings`（flag-settings 层，最高用户优先级），设 `plansDirectory` 为项目内相对路径：

```js
options.settings = {
  ...(options.settings as object ?? {}),
  plansDirectory: ".claude/plans",
};
```

这样 plan 文件会写到 `<project>/.claude/plans/<random>.md`（项目内、git 可忽略），而不是全局 `~/.claude/plans/`。需注意：只在 `apiConfig` 分支里设了 `settingSources: ["project","local"]`，默认分支不设。但 `settings`（flag 层）优先级最高，无论 `settingSources` 如何都会生效，所以在两个分支都加即可（放在 `options` 构造的公共部分，`apiConfig` 判断之前）。

#### 改动 4：`canUseTool` 的 ExitPlanMode 兜底分支保留但加日志
**文件**：同上，262-298 行

旧版 SDK 走 `canUseTool`，新版走 `onUserDialog`。当前兜底分支已有 `ctx.log.info("canUseTool: ExitPlanMode fallback path hit ...")`。**保留不动**——它是防御性的，不影响新版流程。日志能帮确认实际走了哪条路径。

### 验证方式

1. `cd apps/desktop && npx tsc --noEmit -p tsconfig.json` —— 类型检查通过。
2. `pnpm dev` 启动，在 plan 模式下让模型生成计划：
   - 日志应出现 `onUserDialog: dialogKind=permission_exit_plan_mode_v2 ...`（之前完全没有）。
   - 审批弹框 `<PlanApprovalPrompt>` 应出现，批准/拒绝可正常返回。
   - ExitPlanMode 的 tool_result 应为成功（非 `is_error`）。
3. 检查 `<project>/.claude/plans/` 下生成 plan 文件，`~/.claude/plans/` 不再新增。

### 不做的事

- 不改 `SdkMessageAdapter` 的 EnterPlanMode/ExitPlanMode tool_use 处理（802-849 行）——它读 `input.plan` 是对的，tool_use 块里确实有 `plan` 字段。
- 不把 `planFilePath` 透传给 renderer——当前 plan 编辑器基于内存文本，不需要文件路径；后续若要做"在 IDE 中打开 plan 文件"再说。
- 不动 `canUseTool` 兜底分支的逻辑，只依赖它已有的日志。
