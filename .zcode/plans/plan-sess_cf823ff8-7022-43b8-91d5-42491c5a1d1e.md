# 本轮修改内容卡片：移入消息流（按 turn 展示 + 持久化）

## 目标
把「本轮修改内容」卡片 (`TurnFilesCard`) 从「固定在消息流末尾的会话级单例 footer」改造为「内嵌在消息流中、按 turn 归属、随消息持久化」的尾部 block。每个产生文件改动的 turn 在自己的消息流末尾冻结一张卡片，新 turn 产生新卡片，历史卡片永不删除。重开线程时所有历史卡片从 DB 还原。

**沿用上一轮计划卡片 (plan block) 的同款模式**——这是已被验证的范式，最大化代码一致性。

---

## 用户确认的三个决策
1. **历史卡片只读**：非最新一轮的卡片隐藏「撤销本轮」按钮（仅展示文件列表 + 增删统计 + diff 预览）。只有最新一轮保留可点击的撤销按钮，沿用现有内存快照回滚机制，行为不变。
2. **Write 卡片 diff**：用消息流里 turn-files 块记录的 `before` 内容构建 `beforeMap`（取每个文件最近一次记录）。
3. **无文件改动的 turn 不显示卡片**：纯问答 / 只读 turn 不插入任何卡片。

---

## 核心设计：新增 `kind: "turn-files"` block（与 plan block 同构）

**为什么不新建 DB 表 / 新增 session 列**：messages 表的 `content` 列已经把整个 `blocks` 数组 JSON 序列化持久化（`toRecords`/`fromRecords`），新 block 类型自动 round-trip。每张卡片归属于自己 turn 的尾部 assistant 消息，天然随消息存取，无需额外 schema 迁移。

### 1. 数据模型：`apps/desktop/src/renderer/stores/sessionStore.ts` Block 联合 (lines 29-50)

在 `Block` 联合新增变体：
```ts
| {
    kind: "turn-files";
    /** Stable id within the turn — "current" while live, stays after freeze.
     *  Same pattern as the plan block's planId. */
    filesId: string;
    /** Files touched in this turn (filePath / kind / adds / dels / before).
     *  Mirrors TurnFileEntry verbatim — the same shape crosses the turn.files
     *  event, the persisted block, and the TurnFilesCard props. */
    files: TurnFileEntry[];
    /** True only on the LATEST turn's card — gates whether the 撤销本轮
     *  button renders. Flipped to false on all older cards + on any new turn
     *  opening (the previous latest demotes to read-only). */
    isLatestTurn?: boolean;
  }
```
`TurnFileEntry` 已在 line 14 导入。

### 2. Store helpers（紧挨现有 plan block helpers，line ~510 附近）

新增三个纯函数，与 plan block 的 `upsertLivePlanBlock` / `freezeOrPrunePlanBlocks` 完全同构：

- **`LIVE_FILES_ID = "current"`** —— 单 turn 内唯一 live 块的稳定 id。
- **`upsertLiveTurnFilesBlock(messages, files)`**：在当前 turn 尾部 assistant 消息上 upsert `kind: "turn-files"` 块（复用 `findOpenTurnTrailingAssistant`，无消息则按 plan block 同款「new turn」启发式新建）。同时把已有 turn-files 块的 `isLatestTurn` 维护好。
- **`demotePreviousLatestTurnFiles(messages)`**：把消息流里所有 `kind: "turn-files"` 块的 `isLatestTurn` 置 false。在**新 turn 开始时**调用（即第一次收到新 turn 的 text.delta/tool.use/plan.update 时），让上一轮卡片降级为只读。
- **`freezeOrPruneTurnFilesBlocks(messages, endedAt)`**：在 turn.done 时，把本 turn 的 live turn-files 块冻结（保留，标记 `isLatestTurn=true`，因为它就是当前最新轮）。**注意**：与 plan 不同，turn-files 块一旦有内容就**总是保留**（用户已确认「无文件改动不显示」——无内容时根本不会创建块，所以无需 prune）。但要把更早 turn 的块 `isLatestTurn` 降级为 false。

> 关键差异 vs plan block：plan 块在 turn.done 时会 prune 掉 drafting/cleared；turn-files 块**永不 prune**（每个有改动的 turn 都保留）。降级 (`isLatestTurn=false`) 是唯一的状态变化。

### 3. Store handler 改写

#### `turn.files` handler (sessionStore.ts ~1693)
当前是 REPLACE `turnFilesBySession`。改为：
- **保留** `turnFilesBySession[sid] = e.files`（最新轮的 in-memory 镜像，用于撤销 IPC 的 `rewindTurn` 判空 + `beforeMap` 即时可用，直到该轮 turn-files 块冻结）。
- **同时**调用 `upsertLiveTurnFilesBlock(messages, e.files)` 把块写入当前 turn 尾部消息。

#### `turn.rewound` handler (sessionStore.ts ~1700)
当前清空整个 `turnFilesBySession[sid]`。改为：
- 清空 `turnFilesBySession[sid]`（保留——撤销 IPC 后的即时清理）。
- **同时**移除当前 turn 的 live turn-files 块（撤销了就抹掉这张卡片）。新增 `removeLiveTurnFilesBlock(messages)` helper（同 `removeLivePlanBlock` 模式，空消息一并删除）。历史块不动。

#### `turn.done` handler (sessionStore.ts ~1825 附近，紧跟 `freezeOrPrunePlanBlocks` 调用之后)
新增调用 `freezeOrPruneTurnFilesBlocks(next, endedAt)`：冻结本 turn 的 turn-files 块（标记 `isLatestTurn=true`，因为它现在是最新轮），并降级所有更早 turn 的块为 `isLatestTurn=false`。

#### 新 turn 开启时降级（关键）
在 `text.delta` / `thinking` / `tool.use` / `plan.update` 任一 handler **首次检测到新 turn**（即「没有 open turn assistant 消息」）时，调用 `demotePreviousLatestTurnFiles(messages)`，把上一轮卡片的撤销按钮收掉。具体落点：复用各 handler 里已有的 `isNewTurn` 判定分支，在创建新 turn 消息后追加一次降级扫描。
- 最简实现：把降级逻辑统一塞进 `upsertLiveTurnFilesBlock` 和 `upsertLivePlanBlock` 的「需要新建 turn 消息」分支——因为这两个 helper 是新 turn 真正创建第一条 assistant 消息的地方。新增一个 `demotePreviousLatestTurnFiles` 调用即可。

#### `rewindTurn` action (sessionStore.ts ~2125)
**不改签名**（仍 `() => Promise<void>`，撤销最新轮）。用户已确认仅最新轮可撤销。逻辑不变：判空用 `turnFilesBySession[activeSessionId]`，调 `api.claude.rewindTurn`，等 `turn.rewound` 事件回流清块。

### 4. 持久化：**零 DB schema 改动**

- `turn.files` 块作为普通 JSON block，经 `toRecords` (line 303) 写入 messages 表的 `content` 列，`fromRecords` (line 313) 还原。重开线程时历史卡片自动回来。
- **保留** `Session.turnFiles` 列 + `RuntimeManager` 的 `SessionRepo.updateTurnFiles` 持久化（line 71-79）+ `hydrateTurnFiles`（line 491）——它们仍服务于「最新轮撤销」的内存镜像，不动。实际上 `turnFilesBySession` 仍是最新一轮的权威来源（给撤销 IPC 用），turn-files 块只是它的「历史快照展示层」。
- 不新增 IPC、不改 contracts、不改 main 进程。

### 5. 渲染

#### `apps/desktop/src/renderer/components/chat/MessageBlocks.tsx` (BlockView switch, line ~201)
新增 `case "turn-files":`，渲染 `<TurnFilesCard>`，传入 `isLatestTurn` 控制撤销按钮：
```tsx
case "turn-files":
  return (
    <TurnFilesCard
      files={block.files}
      isLatestTurn={block.isLatestTurn}
      onRewind={() => void rewindTurn()}
    />
  );
```
**问题**：`BlockView` 是纯展示组件，拿不到 `rewindTurn` action。两个选项：
- **(A)** 给 `BlockView` / `MessageBlocks` 加一个可选 `onRewind?: () => void` prop，从 ChatPane 一路透传（跟 `beforeMap` 同款透传路径）。
- **(B)** 在 `TurnFilesCard` 内部直接 `useSessionStore((s) => s.rewindTurn)` 取 action。

选 **(B)**——更简单，TurnFilesCard 本就是 turn-files 专用组件，自取 action 符合「组件自治」；`isLatestTurn=false` 时它根本不渲染按钮，也就不会误触发。省掉一路 prop 透传。

#### `apps/desktop/src/renderer/components/chat/TurnFilesCard.tsx` (lines 33-39, 98-113)
- props 新增 `isLatestTurn?: boolean`。
- 默认展开改为按生命周期：最新轮 → 默认展开（看改动 + 可撤销）；历史轮 → 默认收起（只读快照）。
- 撤销按钮区块 `{isLatestTurn && ( ... 撤销本轮 ... )}`——历史卡片只保留「收起」按钮，无撤销。
- 组件内 `const rewindTurn = useSessionStore((s) => s.rewindTurn);` 自取 action。

#### `apps/desktop/src/renderer/components/chat/ChatPane.tsx`
- **从 `listFooter` 彻底移除 `TurnFilesCard`**——footer 现在彻底空了，可以直接让 `listFooter` 返回 `null`（或删掉 `ListFooterComponent` prop）。
- **`beforeMap` 改造**（line 329-333）：从「读 `turnFilesBySession`」改为「扫消息流里所有 `kind: "turn-files"` 块，按 filePath 取最近一次 `before`」。这样 Write 卡片 diff 仍能工作，且涵盖历史轮的 before（用户确认的「用该轮卡片记录的 before」）。
  ```ts
  const beforeMap = useMemo<BeforeContentMap>(() => {
    const m: BeforeContentMap = new Map();
    for (const msg of messages) {
      for (const b of msg.blocks) {
        if (b.kind === "turn-files") {
          for (const f of b.files) m.set(f.filePath, f.before);
        }
      }
    }
    return m;
  }, [messages]);
  ```
  （后写覆盖先写 → 每个文件保留最近一次 before，正是 Write diff 想要的。）
- 移除现在不再被 footer 用的 `turnFiles` / `rewindTurn` selector（但确认 `rewindTurn` 是否在别处仍用——实际只 footer 用，可删；`turnFiles` 仍驱动 `beforeMap` 旧实现，改完后也可删）。**保留 `EMPTY_TURN_FILES` 导出**（其他模块可能引用，typecheck 会告诉）。
