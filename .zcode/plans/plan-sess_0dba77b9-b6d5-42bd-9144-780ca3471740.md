## 目标

git 面板的 pull / push / commit / sync 等操作因网络等外部原因报错时，用户能在一个固定的地方看到对应的报错日志（含完整错误信息），且不会被静默吞掉。

## 现状结论

- pull/push/commit 业务失败：main 返回 `{ ok: false, error }`（含 git 真实 stderr），前端在卡片内显示**一行红色横幅**。问题：切标签/收起卡片/重新操作成功就消失；多步操作（sync）多个错误只保留最后一个；IPC 层异常被 `try/finally` 吞掉、用户完全看不到。
- main 进程把每次失败写进了 `userData/logs/main.log`，但**应用内无任何入口**能查看。
- 项目无全局 toast / 通知系统，无日志面板。

## 方案

在 **GitRepoCard 卡片内部**（每仓库一份）新增一个可折叠的「操作日志」区，记录最近 N 次操作的成败与完整错误，失败的条目可展开看详情。同时给所有 git 操作补 `catch`，兜住 IPC 层异常，确保任何报错都不会无声丢失。

落点选 GitRepoCard 内部而非 GitPanel 容器层，理由：与现有「每仓库独立、状态全本地」（GitRepoCard.tsx:43 注释）的设计范式一致，用户在哪个仓库操作就在哪个卡片看日志，符合直觉。

### 改动清单

**1. 新建 `apps/desktop/src/renderer/lib/time.ts`** — 抽取时间格式化工具
- 从 `GitHistoryView.tsx`（431-456 行）把模块私有的 `formatRelativeTime` / `formatFullTime` 原样搬过来并 `export`。
- `GitHistoryView.tsx` 改为从 `@renderer/lib/time.js` 导入，删掉本地私有定义（DRY，复用同一套「刚刚 / N 分钟前」中文相对时间风格）。
- 日志区将用：相对时间作正文，完整时间作 hover title（与 GitHistoryView 现有用法一致）。

**2. 改造 `GitRepoCard.tsx`** — 核心改动

- **新增日志条目类型与状态**（模块内定义，不放 store）：
  ```ts
  type GitOpLogEntry = {
    id: string;
    op: "pull" | "push" | "commit" | "sync" | "stage" | "unstage" | "discard";
    status: "success" | "failure";
    message?: string;   // 完整错误信息（failure 时），成功时省略
    timestamp: number;  // Date.now()
  };
  ```
  - 状态：`const [logs, setLogs] = useState<GitOpLogEntry[]>([])`，用一个 `prepend` 辅助函数写入并限制最近 20 条（`slice(0, 20)`）。
  - 这是**会话内有效**的本地 state（重启清空），符合 GitRepoCard「全本地 state」范式，避免持久化导致 JSON 无限膨胀。日志是临时操作流水，跨重启保留价值低。

- **改造所有 git 操作 handler**（handleCommit / handlePush / handlePull / handleStageAll / handleUnstageAll / handleSingleStage / handleSingleUnstage / handleDiscard）：
  - 每个 handler 都在现有 `try { ... } finally { setBusy(null) }` 上**补 `catch`**，捕获 IPC 层异常（main 崩溃 / preload 桥断），写入日志（`status: "failure", message: err.message`），避免无声丢失。
  - 业务失败（`!res.ok`）和成功都写入日志：成功记 `status: "success"`，失败记 `status: "failure"` + `res.error`。
  - 多步操作（sync：pull 后 push）两步分别记日志，不再只保留最后一个错误。
  - 保留现有 `setError(...)` 逻辑和红色横幅（作为「最近一次失败」的醒目瞬时提示），日志区作为历史沉淀，两者职责不重叠。

- **新增日志区 UI**（插入点：GitRepoCard.tsx 第 320 行 Body 的 `)}` 之后、第 322 行 Discard 对话框之前）：
  - 仅在 `!collapsed` 时渲染，与 error 横幅 / Body 的展开收起行为一致。
  - 结构：可折叠标题条「操作日志 (N)」+ 右侧「清空」按钮；展开后是日志列表。
  - 每条一行：状态图标（✓ 绿 / ✗ 红）+ 操作名（拉取/推送/提交/同步/暂存/取消暂存/放弃）+ 相对时间（hover 显示完整时间）；失败条目可点击展开看完整 `message`（`break-words` 换行，复用现有 `text-danger` 配色）。
  - 日志列表内部 `max-h-[160px] overflow-y-auto`，防止单卡片日志过长吞掉整个可视区滚动（约束来自 RightPanel 的滚动链，第 6 项探索结论）。
  - 无日志时不渲染该区（避免空态噪音）。
  - 复用现有语义 token 与间距规范：`[font-size:var(--right-panel-font-size)]`、`border-edge`、`text-content-muted` 等，新 class 一律用 `cn()`。

**3. 不需要改动的部分**
- main 进程 `ipc/git.ts`：现有 `{ ok: false, error: msg }` 返回结构已够用，`log.warn` 落盘逻辑保留。不动。
- contracts `ipc.ts`：不新增 IPC 通道，日志纯前端 state。不动。
- preload：不动。

## 验证

- `cd apps/desktop && npx tsc --noEmit -p tsconfig.json` 通过。
- 手动验证（可选，由你决定）：构造一次失败的 pull（如临时断网或指向不存在的 upstream），确认卡片内出现红色横幅 + 日志区记录一条 ✗ 拉取失败条目，点击可展开看完整错误；再正常 push 一次，确认日志区追加一条 ✓ 推送成功。

## 注意事项

- 日志为会话内本地 state，重启应用后清空。若你后续需要跨重启保留，可参照 `collapsedGitRepos` 的 store+settings 持久化范式补做（需加条数上限裁剪），本次不做。
- 不引入全局 toast 系统——按你选择，聚焦 git 面板内日志区即可。
