## 实现方案:窄输入框折叠 chip 簇 + 总图标入口

### 需求
输入框缩窄时,模型/思考级别/权限模式/上下文环 四个 chip 一起隐藏,改为显示一个 `IconAdjustmentsHorizontal` 总入口图标;点击弹出浮层面板,内含原 4 个 chip(复用现有组件,行为完全一致)。

### 架构决策(已确认)
- **复用而非重写**:浮层内直接挂载现有 `ComposerToolbar`(它已渲染 Model/Effort/Permission/ContextRing 四件套),不重新实现任何下拉。行为与宽模式 100% 一致。
- **用 base-ui Popover**(`@base-ui/react/popover`,项目已装 v1.6.0,尚未使用但 API 与已用的 Menu 同构):`Popover.Root` + `Popover.Trigger`(挂在入口图标按钮上)+ `Popover.Portal` + `Popover.Positioner side="top" align="start"` + `Popover.Popup`。Portal 保证浮层不受输入框卡片 `overflow-hidden` 裁剪。
- **纯 CSS 控制显示切换**:不引入 JS 宽度测量/`useEffect`。用一条容器查询 `@container (width < 30rem)`,`.composer-chips{display:none}` + `.composer-chips-toggle{display:inline-flex}`。宽模式下 toggle 反过来 `display:none`。与已有的窄模式间距规则共用同一断点,行为统一、零 JS。

### ModelDropdown 裁剪问题的处理
`ModelDropdown` 的弹出层是 `absolute bottom-full left-0`(非 Portal,相对自己的 `relative` 包裹)。若浮层 popup 设了 `overflow:hidden` 会被裁。解决:浮层 popup 类名只给 `overflow-visible`(或不设 overflow),让 ModelDropdown 的子弹层正常向上溢出渲染。Effort/Permission 用 `Menu.Portal`(真 portal),本就不受影响。ContextRing 是 hover tooltip,也不受影响。

### 改动文件(共 3 个)

**1. 新建 `apps/desktop/src/renderer/components/chat/ComposerToolbarToggle.tsx`** (~40 行)
- 一个 `ComposerToolbarToggle` 组件:base-ui `Popover` 包一个 `IconAdjustmentsHorizontal` 图标按钮(样式与现有 chip 一致: `composer-chip` class + `h-8 w-8` + 同款 hover 动效),popup 内挂 `<ComposerToolbar />`(横排,`gap-2`)。
- 图标从 `@renderer/lib/icons.js` 导入 `IconAdjustmentsHorizontal`。
- popup: `Popover.Positioner side="top" align="start"`,popup className `"overflow-visible rounded-xl border border-edge bg-surface p-2 shadow-2xl"`,内部 `<ComposerToolbar />` 包一层 `flex items-center gap-2`。
- 根容器带 `composer-chips-toggle` class(供 CSS 默认隐藏)。

**2. 改 `apps/desktop/src/renderer/components/chat/ChatPane.tsx`**
- 在 chip 簇(`<ComposerToolbar />` 之后,约 1643 行)紧挨着渲染 `<ComposerToolbarToggle />`(与 ComposerToolbar 平级,都作为 `.composer-chips` 的子元素)。两者由 CSS 互斥显隐:宽模式 ComposerToolbar 显示、toggle 隐藏;窄模式反之。
- 顶部 import 新组件。

**3. 改 `apps/desktop/src/renderer/styles.css`**(在现有 `@container (width < 30rem)` 块附近)
- 宽模式(默认,无媒体查询):`.composer-chips-toggle { display: none; }`
- 窄模式(`@container (width < 30rem)` 内追加):`.composer-chips > .composer-chips-root { display: none; }`(隐藏原 ComposerToolbar,需给 ComposerToolbar 根 div 加 `composer-chips-root` class)+ `.composer-chips-toggle { display: inline-flex; }`(显示总入口)。

**4. 改 `apps/desktop/src/renderer/components/chat/ComposerToolbar.tsx`**(1 处)
- 根 div className 追加 `composer-chips-root`(作为 CSS 显隐钩子)。其余不变。

2. 启动 `pnpm dev`,宽模式下确认入口图标不显示、原 chip 正常;拖窄输入框(打开左右边栏)到 < 480px,确认 chip 消失、滑块图标出现,点击图标弹出浮层,浮层内 4 个 chip 各自可正常展开下拉/tooltip。
