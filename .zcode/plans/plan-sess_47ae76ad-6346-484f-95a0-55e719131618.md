# 体验优化:发送后立即显示"开始x用时x"+ loading 图标

## 问题
用户发送消息后,`TurnStatRow`("开始 HH:MM:SS · 用时 x" + 旋转图标)**只在第一个 assistant 内容块到达时才出现**。因为 `turnMeta.startedAt` 是在 4 处 `isNewTurn` 检测点(flushDeltas / tool.use / upsertLivePlanBlock)创建 assistant 消息时才打戳的。在"发送"到"首个 token"之间(模型可能在"思考",几百ms到数秒),用户看不到任何运行反馈,只有 composer 被锁定。

## 方案:渲染层合成 + `runningTurnStartedAt` 时间锚

**核心思路**:不往消息流里塞占位 assistant 消息(会污染序列化、与 4 个 `isNewTurn` 检测点冲突、留下空消息)。改为在**渲染层**(`groupMessagesForRender`)**合成一个临时的运行态行**,数据来源是一个新的、不持久化的会话级时间戳 `runningTurnStartedAt[sid]`,在 `sendPrompt` 同步打戳。当真正的第一个 assistant 块到达、turnMeta 出现时,合成行自动消失,真实行接管——为避免计时跳变,让 3 处 `isNewTurn` 打戳点**回退采用** `runningTurnStartedAt` 作为 `startedAt`,保证计时连续。

## 改动清单

### 1. `sessionStore.ts` — 新增 `runningTurnStartedAt` 状态切片
- **声明**(~L264 `runningBySession` 旁):`runningTurnStartedAt: Record<string, number>;` —— 发送时刻打戳,用于在首个 token 到达前渲染合成行。注释说明不持久化、随 `turn.done`/`error`/`interrupt`/删除会话清理。
- **初始值**(~L1559 `runningBySession: {}` 旁):`runningTurnStartedAt: {}`。

### 2. `sessionStore.ts` — `sendPrompt` 打戳(~L2536-2542)
在现有同步 `set` 里追加 `runningTurnStartedAt: { ...s.runningTurnStartedAt, [sessionId]: Date.now() }`。与 `runningBySession` 同一刻打,作为时间锚。
- **补充**(防卡死):`sendTurn` 的 `await`(~L2552)用 `try/catch` 包裹;catch 里清 `runningBySession[sid]=false` 和删 `runningTurnStartedAt[sid]`(修一个既有 bug——IPC reject 时 running 标志不会清,合成行会卡住)。

### 3. `sessionStore.ts` — 终止/中断/删除时清理 `runningTurnStartedAt`
- `turn.done`(L2835 `set` 块 L2917)、`error`(L2825)、`interrupt`(L2578)、删除会话(L2302):都加上 `delete runningTurnStartedAt[sid]` / 删 key,与 `runningBySession` 同步清理。

### 4. `sessionStore.ts` — 3 处 `isNewTurn` 打戳点回退采用 `runningTurnStartedAt`
保证真实 turnMeta 出现时 `startedAt` 与合成行一致,计时无跳变:
- **flushDeltas**(L1424-1434):已有 `sid`(外层 `for [sid, ...]`)。改为 `const startedAt = useSessionStore.getState().runningTurnStartedAt[sid] ?? Date.now();` 并用于 `turnMeta: { startedAt }`。
- **tool.use**(L2779-2793,`set` 回调内,`sid` 在闭包作用域):同样 `const startedAt = get().runningTurnStartedAt[sid] ?? Date.now();`(已在 `set(s => ...)` 中,用 `s.runningTurnStartedAt[sid]`)。
- **upsertLivePlanBlock**(L1041-1051):函数只收 `messages`。**最小侵入**:给 `upsertLivePlanBlock` 加可选第 5 参 `startedAt?: number`,由两个调用点(L2609、L2684)传入 `s.runningTurnStartedAt[sid] ?? Date.now()`;函数内 `turnMeta: { startedAt: startedAt ?? Date.now() }`。
  - 第 4 处 `upsertLiveTurnFilesBlock` 的 `targetIndex===-1` 兜底分支**不打 turnMeta**(原设计如此,见 L1191 注释),不动它。

### 5. `ChatPane.tsx` — 渲染层合成运行态行
- **`groupMessagesForRender`**(L212)签名增加 `runningTurnStartedAt?: number` 形参(由 L333 调用处传入)。
- 函数末尾:当 `isRunning && runningTurnStartedAt != null` 且**当前没有任何 assistant 消息带未结束 turnMeta**(即真实行还没出现)时,`items.push` 一个新的 `RenderItem` 变体 `{ kind: "pendingTurn", turnMeta: { startedAt: runningTurnStartedAt } }`。
- **`RenderItem` 联合**(L158):新增 `{ kind: "pendingTurn"; turnMeta: TurnMeta }` 成员。
- **`renderListItem`**(L756):新增 `pendingTurn` 分支——渲染 `<TurnStatRow meta={item.turnMeta} />`(`TurnStatRow` 内 `live` 分支自带 `IconLoader2 animate-spin` loading 图标),外加一个底部流式 spinner 与 proceduralCluster 分支一致,保持视觉统一。用 `keyExtractor`(L823)给 `pendingTurn` 一个稳定 key(如 `"pending-turn"`)。
- **`groupMessagesForRender` 调用处**(L333):`groupMessagesForRender(messages, isRunning, useSessionStore.getState().runningTurnStartedAt[sessionId])`。注意:这里直接读 `getState()` 在 `useMemo` 闭包里;为保证 `runningTurnStartedAt` 变化时重新渲染,额外用一个稳定 selector 订阅它并加入 `useMemo` deps:`const runningTurnStartedAt = useSessionStore((s) => s.runningTurnStartedAt[sessionId]);`,再传给 `groupMessagesForRender`,deps 加 `runningTurnStartedAt`。

### 6. 验证
- `cd apps/desktop && npx tsc --noEmit -p tsconfig.json`。
- 手动:`pnpm dev` → 发送一个会触发模型长时间思考的 prompt,确认"开始x用时x" + 旋转图标在发送瞬间出现、计时从 0 连续递增,首个 token 到达后无跳变地由真实行接管,turn 结束后图标消失、计时冻结。再验证 interrupt / error 路径合成行消失。

## 不改动
- 不引入 `turn.start` RuntimeEvent(动 main 进程、contracts,过重;纯渲染层方案足够)。
- 不往消息流插占位消息(避免序列化/4 处 isNewTurn 检测冲突)。
- `TurnStatRow` 组件本身不变(已支持 `live` + spinner)。
- `upsertLiveTurnFilesBlock` 兜底分支不动(原设计不打 turnMeta)。

## 影响面
3 个文件:`sessionStore.ts`(状态切片+打戳+清理+3 处回退)、`ChatPane.tsx`(渲染层合成行)。无 contracts/main 改动,无数据模型变化,无持久化影响。
