# 任务胶囊：扩展为统一 Activity Capsule（Plan + Subagent + Tasks）

## 目标
把当前 ChatPane 顶部「任务胶囊」从「只看 todos」升级为「统一活动面板」：
1. **Plan** — 计划模式全程预览当前 plan 草稿，点击展开后看到完整 Markdown 计划；批准时直接复用现有 `PlanApprovalPrompt`。
2. **Subagent** — 显示正在运行 / 已结束的子代理数量、描述、进度摘要（tokens、工具调用数、最后工具名），点击展开后看到每个子 agent 的运行状态。
3. **Tasks** — 保留现有 todo 列表（不破坏既有功能）。

设计选择（已与用户确认）：**合并成一个总胶囊**，三个分区在同一个 popover 内呈现。

---

## 实现概览

### 1. 扩展 RuntimeEvent 契约 (`packages/contracts/src/runtime.ts`)

新增两个事件类型，加到 `RuntimeEvent` 联合：

```ts
/** Plan 草稿变更（plan mode 全程）。draft = 当前模型写的 plan 文本；title 是首行（首段标题），用于胶囊摘要。 */
export interface PlanUpdateEvent {
  type: "plan.update";
  sessionId: string;
  /** Plan 文本（Markdown）。空字符串表示「暂无草稿 / 已退出 plan 模式」。 */
  plan: string;
  /** 状态：drafting = 模型还在写，ready = 等待 ExitPlanMode 审批，cleared = 已退出 plan 模式。 */
  phase: "drafting" | "ready" | "cleared";
}

/** Subagent 状态变更（基于 SDK 的 task_started/task_progress/task_updated 边沿）。 */
export interface SubagentUpdateEvent {
  type: "subagent.update";
  sessionId: string;
  /** 完整快照（REPLACE 语义）。SDK 一次只发增量，但 store 维护最新视图。 */
  agents: Array<SubagentSnapshot>;
}

export interface SubagentSnapshot {
  /** SDK 提供的 task_id。 */
  taskId: string;
  /** 发起该子 agent 的 Task tool_use id（用于把 activity feed 关联回去）。 */
  toolUseId?: string;
  /** 描述（来自 SDK task_started.description 或 Task tool_use 的 description）。 */
  description: string;
  /** 类型标签（e.g. "general-purpose", "code-reviewer"）。 */
  subagentType?: string;
  /** 生命周期状态。 */
  status: "running" | "completed" | "failed" | "killed";
  /** 累计 token 估算（来自 task_progress.usage.total_tokens）。 */
  totalTokens?: number;
  /** 累计工具调用数（来自 task_progress.usage.tool_uses）。 */
  toolUses?: number;
  /** 已运行毫秒（来自 task_progress.usage.duration_ms）。 */
  durationMs?: number;
  /** 最近一次活跃的工具名。 */
  lastToolName?: string;
  /** SDK 给的进度摘要（task_progress.summary）。 */
  summary?: string;
  /** 完成时间戳（task_updated.patch.end_time）。 */
  endedAt?: number;
  /** 错误信息（task_updated.patch.error）。 */
  error?: string;
}
```

### 2. SdkMessageAdapter 解析 SDK 事件 (`apps/desktop/src/main/providers/claude-sdk/SdkMessageAdapter.ts`)

在 `dispatch()` 的 if/else 链里加 `system` 子类型分支（当前只处理 `init`）：

- `task_started` → 推送新 snapshot，status="running"
- `task_progress` → 合并到已有 snapshot 的 usage / summary / lastToolName
- `task_updated` → 根据 `patch.status` 更新对应 snapshot

维护方式：在 `AdapterState` 加一个 `Map<taskId, SubagentSnapshot>`，每次 `dispatch` 之后用最新 map 序列化一个 `subagent.update` 事件（REPLACE 语义，匹配 SDK 的「level signal」语义）。

plan 草稿通过两条路径捕获：
- **plan mode 进入信号**：assistant 消息里出现 `EnterPlanMode` tool_use → emit `plan.update` phase=cleared + 清空（清空操作只发生一次，避免覆盖后续 drafting）。
- **plan 文本来源**：assistant 消息的 text 块和 ExitPlanMode 的 `input.plan` 参数都能拿到 plan 文本。采用保守方案：**直接解析 ExitPlanMode tool_use 的 input.plan**（已确认 SDK 在 ExitPlanMode 调用时把 plan 文本带在 `input.plan`，见 `ClaudeAgentSdkProvider.ts:165`）。在 ExitPlanMode tool_use 进入 `tool.use` emit 之后追加一个 `plan.update` event，phase="ready"。
- **退出信号**：已有 `mode.change` 到 default 即可作为「plan 已离开」的信号 — 收到 `mode.change` mode=default → emit `plan.update` plan="" phase=cleared。

注意：EnterPlanMode/ExitPlanMode 工具的 `mode.change` 事件已经在 adapter 里发出（line 477, 490），我们新增的 plan.update 是相邻但独立的事件。

### 3. sessionStore 接入 (`apps/desktop/src/renderer/stores/sessionStore.ts`)

新增两个按 sessionId 索引的 state slice（与现有 `todosBySession` 同样的模式）：

```ts
/** Per-session 当前 plan 草稿。空字符串 = 不在 plan 模式。 */
planBySession: Record<string, { plan: string; phase: PlanUpdateEvent["phase"] }>;
/** Per-session 子 agent 状态表。REPLACE 语义。 */
subagentsBySession: Record<string, SubagentSnapshot[]>;
```

在 `ingestEvent` 顶部加两个分支（仿照 `todo.update` 的现有写法）：
- `e.type === "plan.update"` → 更新 `planBySession[sid]`
- `e.type === "subagent.update"` → 更新 `subagentsBySession[sid]`

清空时机：现有 `turn.done` 已经清空 `runningBySession` 等。我们要保证 turn 切换时 plan/subagent 也清空，避免上一次 plan 残留在新 turn：
- 方案 A：在 `turn.done` handler 里同时清 `planBySession[sid] = { plan: "", phase: "cleared" }` 和 `subagentsBySession[sid] = []`。
- 方案 B：依赖 `plan.update` phase=cleared 事件来清（subagent 由 SDK task_updated 自然收尾）。

选 A 更稳健：主 agent turn 结束 → 子 agent 也肯定都结束了（subagent 是 turn 的一部分），plan 草稿也不会跨 turn 存活。

### 4. 合并胶囊 UI：新建 `ActivityPopover.tsx`，重写 `TodosPopover.tsx`

`TodosPopover.tsx` 重命名为 `ActivityPopover.tsx`（或保留旧文件作为 plan/subagent 都空时的纯 fallback），接受 `{ todos, plan, subagents }`。

布局：一个 popover 内三个可滚动 section（Plan → Subagents → Tasks），每个 section 有自己的 header（图标 + 标题 + 计数 / 状态徽标），section 之间用细分割线分开。

**Plan section**：
- 空（plan 文本=""）：隐藏整段。
- phase=drafting：header 显示 "📋 计划草稿"，右上角 "✎ 草拟中" 徽标。
- phase=ready：header 显示 "📋 待审批计划"，右上角 "⚡ 等待批准" 徽标。
- 内容：纯文本预览（截断 600 字符 + "…"），保留换行（pre-wrap）。完整 plan 留到 PlanApprovalPrompt 里看。
- footer：按钮 "查看完整计划" → 触发 `onOpenPlanApproval` 回调。

**Subagents section**：
- 空数组：隐藏整段。
- header："🤖 子代理 · N 个" + "X 运行中" 徽标。
- 每个 subagent 一行：type 标签 + description（截断）+ 状态徽标（running 用 warning 颜色 + spinner；completed 用 accent；failed/killed 用 danger）+ 可选 usage（"2.1k tokens · 5 tools · 12s"）。

**Tasks section**：就是现在的 todo 列表，不动。

### 5. ChatPane 接入 (`apps/desktop/src/renderer/components/chat/ChatPane.tsx`)

- 引入 `ActivityPopover`，把现有的 `TodosPopover` 替换。
- 引入 `planBySession`、`subagentsBySession` selector（与 todos 同样的 EMPTY 引用模式）。
- 把胶囊显示条件改为 `(todos.length > 0 || plan.plan || subagents.length > 0) || usage`。
- 胶囊按钮：保留现有的 `TaskRing`（显示 todo 完成度），但 label 改为 "Tasks N/M" — 这是最稳定的"有 todo 在跑"信号。
  - 如果 plan 存在，胶囊按钮加一个 📋 小角标（绝对定位的 8px 圆点）。
  - 如果 subagents 在跑，加 🤖 小角标 + 数字徽标。
- 点开 popover 用单一开关 `activityOpen` 取代 `todosOpen`。
- 加一个 "查看完整计划" 的回调：调用 `decideApproval` 的「直接调出 plan approval modal」目前没法走（plan.approval_request 是 canUseTool 触发的）。先以 popover 内展示为主，"查看完整计划" 按钮切换 popover 内部视图（plan section 展开成完整内容区，剩余 section 折叠到顶部 tabs）。**MVP 不打通 plan approval modal 跳板** — 用户在 ExitPlanMode 时自然会看到 PlanApprovalPrompt。

### 6. 不在范围
- 不做 ActivityFeed（chat 流内的子 agent 文本流渲染）— SDK 默认 `forwardSubagentTranscript: false`，要打开那个得改 SDK options，超出本次范围。
- 不做 plan 草稿实时跟随 assistant 文本逐字增长 — MVP 只在 ExitPlanMode 时一次性 emit（更准确，因为 plan 实际是模型在 ExitPlanMode input 里提交的）。
- 不做 subagent transcript 读取（用 SDK 的 `getSubagentMessages`）— 留给 P5。
