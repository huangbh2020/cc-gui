# 设置面板新增 Skills 管理功能

## 概述

在设置面板新增「Skills」管理板块（左侧导航加一项），支持**全局 + 项目级** skill 的**增删改查**。完整模仿 `CustomModelsPanel` 的双栏管理模式（左列表 + 右编辑区），删除确认用现成的 `ConfirmDialog`。

**编辑模式**：编辑已有 skill = 整个 `SKILL.md` 原文 textarea；新建 skill = name + description 字段 + 正文 textarea（保存时拼成标准 `---\nname: ...\ndescription: ...\n---\n\n正文`）。这样既有结构化引导（新建时不踩 frontmatter 格式坑），又保留了对已有复杂 skill 的完整编辑能力。

## 改动清单（按文件）

### 1. `packages/contracts/src/ipc.ts` — 扩展 skill 契约

在现有 `SkillInfo` / `SkillsListSchema` 基础上新增 CRUD schema 与 RPC：

- `SkillScope = "global" | "project"`（复用 `SkillSource`，语义相同；为清晰起见在 CRUD 输入里用 scope 命名）
- `SkillsReadSchema = { projectPath, source, name }` → 读单个 skill 的完整 `SKILL.md` 原文，返回 `{ content: string }`
- `SkillsSaveSchema = { projectPath, source, name, content, newName? }` → 写入 `<root>/.claude/skills/<name>/SKILL.md`（新建目录+文件，或覆盖）。`newName` 用于重命名（改名时移动目录）
- `SkillsDeleteSchema = { projectPath, source, name }` → 删除 `<root>/.claude/skills/<name>/` 整个目录（仅删 symlink 或项目自有目录；对全局真实目录需二次确认）
- `RpcMap` 加 3 个方法：`"skills.read" / "skills.save" / "skills.delete"`
- `IPC` 常量加 `SKILLS_READ / SKILLS_SAVE / SKILLS_DELETE`

**安全校验**：
- `name` 限 `[A-Za-z0-9_-]+`（zod regex），防路径穿越
- `projectPath` 复用现有 `ProjectRepo.list()` + `samePath` 校验
- 写/删操作的最终路径必须 `pathWithin(root)` 二次校验

### 2. `apps/desktop/src/main/ipc/skills.ts` — 扩展 handler（CRUD）

在现有 `skills.list` handler 基础上新增 3 个 handler：

- **`SKILLS_READ`**：`projectPath` 校验 → 解析 `source` 决定根目录（global=`~/.claude/skills`，project=`<project>/.claude/skills`）→ `name` 校验 → 读 `<root>/<name>/SKILL.md` 全文（不限 8KB，读取完整内容）→ 返回 `{ content }`。文件不存在返回 `{ content: "" }`
- **`SKILLS_SAVE`**：`projectPath` 校验 → 解析根目录 → 若 `newName` 存在且与 `name` 不同，先 `rename` 目录 → `mkdir -p <root>/<name>` → 写 `SKILL.md`（`fs.writeFile`，完整覆盖）→ 返回 `{ ok: true }`。注意 global 写操作直接落在 `~/.claude/skills`（无 projectPath 需求，但为统一仍要求 projectPath 参数——传当前活跃项目即可，仅用于校验调用者身份）
- **`SKILLS_DELETE`**：`projectPath` 校验 → 解析根目录 → 用 `lstat` 判断是 symlink 还是真实目录：
  - symlink → `fs.unlink` 删链接（不删目标，安全）
  - 真实目录 → `fs.rm(dir, { recursive: true })` 删整个 skill 目录
  - 返回 `{ ok: true }`
- 所有 IO 错误 catch 后返回 `{ ok: false, error }`，不抛到 renderer

**抽出公共 helper**：`resolveSkillRoot(source, projectPath)` → 返回根目录绝对路径，复用 `samePath` / `safeRealPath`。

### 3. `apps/desktop/src/preload/index.ts` — 暴露 3 个新方法

`api.skills` 加 `read / save / delete`：
```ts
skills: {
  list: ...,
  read: ((input) => ipcRenderer.invoke(IPC.SKILLS_READ, input)) as RpcMap["skills.read"],
  save: ((input) => ipcRenderer.invoke(IPC.SKILLS_SAVE, input)) as RpcMap["skills.save"],
  delete: ((input) => ipcRenderer.invoke(IPC.SKILLS_DELETE, input)) as RpcMap["skills.delete"],
},
```

### 4. `apps/desktop/src/renderer/components/settings/SkillsPanel.tsx` — 新建管理面板

模仿 `CustomModelsPanel` 的双栏布局：

**布局**：
```
┌─ 左：skill 列表 ────┬─ 右：编辑区 / 空态 ────────┐
│ Skills (count)      │  [来源筛选: 全部/全局/项目]  │
│ • pdf      [全局]   │  ─ 编辑已有 ──              │
│ • docx     [全局]   │  整个 SKILL.md 原文 textarea │
│ • my-skill [项目]   │  (等宽字体, 可滚动)          │
│ + 新建 Skill        │  ─ 或 新建 ──                │
└─────────────────────┤  name / description 输入框   │
                      │  + 正文 textarea             │
                      │  保存 · 取消 · 删除          │
                      └─────────────────────────────┘
```

**左列表**：
- 顶部标题 "Skills" + 计数
- 来源筛选（全部/全局/项目）的小 toggle 组（可选，简化版直接全列+标签）
- 每个 item：`<button onClick={startEdit}>` 显示 name + 截断 description + 来源标签（全局/项目 chip）
- 选中态：accent 竖条 + `bg-surface-hover`（同 CustomModelsPanel）
- `selectedId === "new"` 时显示 transient "新建 Skill" 虚线条目
- 底部 `+ 新建 Skill` 按钮

**右编辑区**（`SkillEditor` 子组件）：
- **编辑模式**（已有 skill）：加载时调 `api.skills.read({ projectPath, source, name })` 取全文 → 单个大 textarea（等宽、`min-h-[300px]`、可滚动）→ 保存时整文件覆盖写回
- **新建模式**：name 输入框 + description 输入框 + 正文 textarea（body）→ 保存时拼装成 `---\nname: <name>\ndescription: <description>\n---\n\n<body>` → 调 `api.skills.save`
- 范围选择器（新建时）：全局 / 当前项目 radio，决定存到哪个 root
- 底部操作栏：保存 / 取消 / 删除（仅编辑态）
- loading 态：读取中显示 "加载中…"；保存中按钮禁用

**状态管理**（父组件持有，同 CustomModelsPanel 模式）：
- `selected: { source, name } | "new" | null`
- `editContent: string | null`（编辑原文）
- `newForm: { name, description, body, scope }`（新建表单）
- `loading / saving / error`
- `pendingDelete: SkillInfo | null`

**关键交互**：
- `startEdit(skill)` → `setSelected(skill)` + 调 read 加载内容
- `startAdd()` → `setSelected("new")` + 初始化空 newForm
- `save()` → 调 save API → 成功后 `reloadSkills()` 刷新左列表 + 选中刚保存的
- `confirmDelete()` → 调 delete API → 成功后 `reloadSkills()` + 清空选中
- 删除用 `<ConfirmDialog>` 组件

### 5. `apps/desktop/src/renderer/components/settings/SettingsPage.tsx` — 注册新板块

- `SectionId` 加 `"skills"`
- `NAV_ITEMS` 加 `{ id: "skills", label: "Skills" }`（放在 "模型配置" 之后）
- 渲染分支加 `{active === "skills" && <SkillsPanel />}`
- import `SkillsPanel`

### 6. `apps/desktop/src/renderer/stores/sessionStore.ts` — settingsOpen 时也能查 skill

现有 `reloadSkills` 依赖 `activeProjectId`。设置面板打开时活跃项目不变，所以 skills 列表已有缓存可直接用。但新建/删除后需刷新——`SkillsPanel` 内部 CRUD 后直接调 `useSessionStore.getState().reloadSkills()` 即可（无需改 store 结构）。

唯一需要注意：设置面板刚打开时若 `skills` 为空（比如从没发过消息），需在 `SkillsPanel` mount 时主动 `reloadSkills()` 兜底。加一个 `useEffect(() => { void reloadSkills(); }, [])`。

## 关键实现细节

- **skill name 校验**：zod `z.string().regex(/^[A-Za-z0-9_-]+$/)`，前端新建表单也做同样校验，禁止空格/路径符
- **重命名**：`newName` 与 `name` 不同时，main 端 `fs.rename(oldDir, newDir)` 移动整个 skill 目录，再写新内容。前端编辑模式下 name 字段 readonly（编辑已有 skill 不改名，避免复杂度）；重命名通过新建+删除实现（MVP 不做原地改名，`newName` 字段预留但 v1 不暴露 UI）
- **symlink 删除安全**：main 端用 `lstat` 先判断，symlink 用 `unlink`（只删链接不删 gstack 仓库本体），真实目录才 `rm -r`
- **全局 skill 写权限**：global scope 的 skill 落在 `~/.claude/skills`，这是用户私有目录，应用有写权限。无需额外授权
- **大文件处理**：read 不截断（gstack skill 可达 100KB），textarea 可承载；写也是整文件覆盖
- **store 刷新**：CRUD 后统一调 `reloadSkills()`，左列表与输入框 `/` 菜单同步更新
- **typecheck**：完成后跑 `npx tsc --noEmit -p tsconfig.json`

## 风险与边界

1. **全局 skill 删除风险**：误删 `~/.claude/skills` 下的真实目录会丢失用户安装的 skill。用 `ConfirmDialog` 二次确认，弹窗文案明确标注来源（全局/项目）和 skill 名。symlink 删除是安全的（只删链接）
2. **并发写**：两个设置面板不会同时打开（同屏视图），无并发问题
3. **SKILL.md 格式自由度**：编辑已有 skill 用整文件 textarea，完全保留 frontmatter 自由格式（`allowed-tools`/`metadata` 等高级字段不丢）；新建只生成最小 frontmatter，后续可切换到编辑模式补充
4. **无活跃项目时**：`SkillsPanel` 仍可用，但只能管理全局 skill（项目级操作需要 projectPath）。若 `activeProjectId === null`，scope 选择器隐藏项目选项，仅显示全局

## 验证方式

- 打开设置 → 左侧导航出现「Skills」
- 列表显示 `~/.claude/skills/` 下的 skill（如 chrome-cdp）+ 来源标签
- 点击某 skill → 右侧加载完整 SKILL.md 原文，可编辑
- 新建 → 填 name/description/正文 → 保存 → 列表刷新出现新项，`/` 菜单也能看到
- 删除 → ConfirmDialog 确认 → skill 目录移除，列表刷新
- 切换活跃项目 → 项目级 skill 出现/消失
