## 目标

修复左侧面板项目会话列表的两个问题：
1. **收起项目后再展开，分页状态不重置** —— 点过"加载更多"后收起再展开，仍显示全部已加载记录，而非初始 5 条。
2. **最新会话没有排在项目最前** —— 列表按 `created_at DESC` 排序（创建时间），但会话行显示的是 `updatedAt`（最近活动时间），导致最近有活动的旧会话不会上浮。用户确认按"最近活动时间"排序。

## 改动一：收起项目时重置分页缓存

**文件**：`apps/desktop/src/renderer/stores/sessionStore.ts`
**位置**：`toggleProjectExpanded`（约 2477-2483 行）

当前实现只翻转 `expandedProjects[projectId]` 布尔值，不碰分页缓存。

改为：当从展开 → 收起时，把该项目的三个分页状态重置为"第一页"语义：
- `sessionsByProject[pid]` → 取当前缓存的前 `SESSION_PAGE_SIZE` 条（`slice(0, 5)`）
- `sessionsHasMoreByProject[pid]` → 重新计算为 `total > SESSION_PAGE_SIZE`
- `sessionsTotalByProject[pid]` → 保持不变（服务端总数不受分页影响）
- 若该项目是当前活动项目，同步刷新 `sessions` 别名

选择"内存 slice"而非"重新发 IPC 拉第一页"的理由：零延迟、零 IPC 开销、零闪烁；total 不变所以 hasMore 重算完全正确；用户收起后未必再展开，避免无谓网络请求。

展开（false → true）时维持原行为，不动缓存。

> 协同：改动二落地后，缓存顺序已是"最近活动优先"，`slice(0, 5)` 取到的恰好是最新 5 条会话，正是用户期望的初始状态。

## 改动二：会话列表按最近活动时间排序

### 2a. 后端 SQL 排序字段
**文件**：`apps/desktop/src/main/store/repositories.ts`
**位置**：`listByProject` 的 ORDER BY（约 261 行）

```diff
- ORDER BY created_at DESC
+ ORDER BY updated_at DESC, created_at DESC
```

加 `created_at DESC` 作为稳定 tiebreaker（两个会话 updated_at 相同时避免顺序抖动）。这一处改动同时影响活动列表（分页）和归档列表（不分页），两者按"最近活动优先"都更合理。

理由：后端各处活动写入（`updateTitle` / `updateStatus` / `updateSnapshot` / `updateTodos` 等，repositories.ts:316/322/...）都已刷新 `updated_at = Date.now()`，该字段是可靠的"最近活动"时间戳。

### 2b. 前端：发消息时把会话移到列表顶部
**文件**：`apps/desktop/src/renderer/stores/sessionStore.ts`

当前 `sendPrompt`（3128-3136）和 `editAndResendMessage`（3230-3238）用 `prevList.map(...)` **原位替换**会话行（只更新字段、不改顺序）。改为"先移除该会话，再 unshift 到列表头部"：

```ts
const rest = prevList.filter((sess) => sess.id !== updated.id);
const nextList = [updated, ...rest];
```

落点选择理由：
- `updated` 是 `sendTurn` 返回的 DB-fresh 行，`updated.updatedAt` 已被 `updateStatus("running")` 刷新为最新，与后端 `updated_at DESC` 排序一致。
- 发消息 = 会话变活跃，此时上浮最符合直觉；`turn.done` 要等整回合跑完（可能几十秒），时机偏晚。
- 不在 `token-usage.updated`（流式期间高频触发，会抖动）或 `turn.done` 重排，避免列表闪烁。

两处（sendPrompt / editAndResendMessage）对称修改。

## 不需要改动的部分
- `startSession`（2527-2528）已是 `[session, ...prevList]` 头部插入，新会话天然排最前，无需改。
- `init` 的落地目标选择（`firstSessions.find(s => !s.archived)`，2193 行）会落到"最近活动的会话"，符合预期。
- `loadMoreSessions` 的去重逻辑（seen set）和 offset 分页不受影响（unshift 只重排已有元素，不改变数组长度）。
- `scroll-to-active`（LeftBar 120-176）按 id 查找，不受排序影响。
- 归档列表显示无需额外调整（自动跟随 2a 的排序）。
