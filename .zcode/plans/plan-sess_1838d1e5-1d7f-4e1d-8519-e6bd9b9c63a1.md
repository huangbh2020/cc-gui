# 模型回复内容展示优化 — 实施计划

## 核心思路

只改一个文件：`apps/desktop/src/renderer/components/chat/MessageBlocks.tsx`。

不需要跨消息分组 —— store 在一次 turn 内会把 thinking + tool_use 都挂到「最后一条 assistant 消息」上，所以一条消息的 `blocks` 数组本身就已经包含了完整的「思考 + 工具调用」序列。`groupBlocks` 是天然的合并点。

## 改动详情

### 1. 重写 `groupBlocks`（lines 50–72）

**旧逻辑**：只收集连续的 `tool_use`，遇到非 `tool_use` 就 flush。`thinking` 会打断工具组。

**新逻辑**：收集连续的 `thinking` **或** `tool_use` 块作为「过程组」（procedural run）。遇到 `text` 或 `error` 才 flush。

```ts
type ProceduralBlock = Extract<Block, { kind: "thinking" }> | ToolUseBlock;
type Segment =
  | { kind: "single"; block: Block }              // text / error 单独渲染
  | { kind: "procedural"; blocks: ProceduralBlock[] }; // thinking + tool_use 合并
```

扫描时：
- `thinking` / `tool_use` → 累积到 run
- `text` / `error` → flush run（如果有内容，作为 procedural 组输出）→ 当前块作为 single 输出
- 末尾再 flush 一次

**阈值移除**：即使只有 1 个 tool_use（无文字）也合并 —— 因为用户的诉求是「纯模型行为内容用一个组框起来」。原来的 `TOOL_GROUP_THRESHOLD = 2` 删除。

### 2. 新增 `ProceduralGroup` 组件（替换 `ToolGroup`，lines 103–136）

**头部摘要**（折叠态显示这一行）：
- 聚合 `StatusIcon`：任一工具 running → spinner；任一 error → ✕；否则 ✓
- 计数摘要：`思考 + N 个操作`（有思考时）/ `N 个操作`（无思考）/ `思考`（无工具）
- 工具明细：`Bash ×2 · Read ×1`（保留现有 Map tally 逻辑）
- 末尾 `Chevron`

**展开态**：渲染所有子块
- `thinking` → 复用现有 `Collapsible`（折叠态，默认收起）
- `tool_use` → 复用现有 `BlockView`（`defaultOpen` 透传，但默认收起）

样式：`rounded-md border border-edge bg-surface/40`（更轻，区别于普通卡片）。

### 3. 更新 `MessageBlocks`（lines 18–37）

```tsx
{segments.map((seg, i) =>
  seg.kind === "single"
    ? <BlockView key={i} block={seg.block} />
    : <ProceduralGroup key={i} blocks={seg.blocks} />
)}
```

### 4. 极简化清理

- `WriteToolCard` 的 `defaultOpen = true` → `false`（统一所有卡片默认折叠）
- 删除未使用的 `IconChevronRight`、`IconClock` 导入
- 保留 `EditToolCard` / `WriteToolCard` / `GenericToolCard` 内部细节不变（diff、内容预览、JSON 输入/输出都在）

## 效果

**纯模型行为消息**（只有 thinking + tool_use）：
```
┌────────────────────────────────────┐
│ 🔧 进行了 3 个操作               ✓ │
│    Bash ×2 · Read ×1            ▸ │
└────────────────────────────────────┘
```
点击展开：
```
┌────────────────────────────────────┐
│ 🔧 进行了 3 个操作               ✓ │
│    Bash ×2 · Read ×1            ▾ │
├────────────────────────────────────┤
│ ▸ Thinking   正在分析文件结构…     │
│ ✓ Bash       ls -la /src        ▸ │
│ ✓ Read       src/index.ts       ▸ │
│ ✓ Bash       cat package.json   ▸ │
└────────────────────────────────────┘
```

**混合消息**（文字 + 工具调用）：文字正常 markdown 渲染在前，下方跟一个 procedural group：
```
我先读取相关文件，然后进行修改。

┌────────────────────────────────────┐
│ 🔧 进行了 2 个操作               ✓ │
│    Read ×2                     ▸ │
└────────────────────────────────────┘
```

**纯文字消息**：无变化，正常 markdown。

## 不改动的部分

- Store 的消息分桶逻辑（`ingestEvent`）—— 不动
- `Block` 类型 —— 不动
- `ChatPane` 的消息循环、copy 逻辑、streaming tail —— 不动
- 工具卡片内部（diff、内容预览）—— 不动

## 验证

`npx tsc --noEmit -p tsconfig.json` 类型检查通过。运行时手测：发起一个会触发工具调用的 turn，确认 procedural 消息折叠为单卡片、展开能看到细节；纯文字回复正常显示。
