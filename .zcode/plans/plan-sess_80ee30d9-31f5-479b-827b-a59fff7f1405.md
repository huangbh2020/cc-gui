# 浏览器功能优化：移动端侧边栏 + PC 端全屏面板

## 交互逻辑（最终确认）
1. **点击浏览器图标**：未开 → 直接在右侧栏内嵌打开（默认移动端，不弹框）；已开 sidebar → 关闭（toggle）。
2. **侧边栏移动端浏览器**：内嵌右侧栏主区域；拾取元素后**直接进输入框**（不经暂存栏）；提供「切换到 PC 端全屏」入口。
3. **PC 端全屏面板**：维持现状（暂存栏 + 点「添加」才入输入框）；提供「切回侧边栏」入口。
4. 切换模式时**标签页跟随**（同一浏览器会话，view 池跨容器存活）。

## 核心架构决策
- 把 `tabs` / `activeTabId` 从 `BrowserPanel` 组件本地 state **提升到 `sessionStore`**，使 sidebar 与 overlay 两个容器共享同一份标签页。view 池（主进程 `WebContentsView`）靠 `browserId` 跨容器存活；切换容器 = 旧组件卸载(hide active view) + 新组件挂载(show + syncBounds 新坐标)。
- 复用现有两个布局 flag 区分模式：`rightPanelTab === "browser"`（sidebar 内嵌）与 `browserPanelOpen === true`（overlay 全屏），互斥。不新增长期状态 `browserMode`。
- `pickedItems` 暂存栏保持为组件本地 state，仅 overlay 模式使用。

## view 生命周期与切换时序
- 切 sidebar→overlay：sidebar 组件卸载（cleanup effect hide active view）→ `setTab("files")` + `setBrowserPanelOpen(true)` → overlay 组件挂载（effect show active view + rAF syncBounds 新坐标）。tabs 在 store，view 池靠 browserId 存活，标签页跟随。
- 切 overlay→sidebar：对称。
- 即使 React 卸载/挂载顺序在同帧不保证，`show()` 会 `setBounds(lastBounds)`，下一帧 `syncBounds` 用新容器坐标覆盖，最终一致（可能一帧闪烁，可接受）。

## 移动端 viewport 适配说明
- sidebar 宽度通常 300-400px，可能 < iPhone 的 390。sidebar 模式让 view 占满侧边栏宽度（不收窄居中），配合 mobile device emulation（UA + 触摸 + screenPosition），多数移动端页面响应式正常。若侧边栏过窄导致显示问题，用户可拖宽侧边栏或点「展开为 PC 全屏」。主进程 `setDevice` 尺寸不改（保持 390/412），emulation 与 view 宽度的差异由页面 viewport meta 自适应。

## 不改动的部分（已就绪）
- 全部 IPC（`ipc/browser.ts`）、`BrowserManager`、`pickerScript.ts`、`browserPicker.ts` preload、`PickedElement` schema、`makeElementTag`、`enqueueChatElement`/`drainChatElementQueue` 队列、`PickedElementsBar` 暂存交互、`api.browser.*` API。

## 验证步骤
1. `cd apps/desktop && npx tsc --noEmit -p tsconfig.json` 类型检查通过。
2. `pnpm dev` 启动，点浏览器图标 → 侧边栏内嵌打开（移动端默认），地址栏输入网址可导航。
3. 侧边栏拾取元素 → 直接出现在输入框 chip（无暂存栏）。
4. 侧边栏点「展开为 PC 全屏」→ 全屏 overlay 打开，标签页保留。
5. 全屏点「切回侧边栏」→ 回到侧边栏，标签页保留。
6. 全屏暂存栏 + 「添加」流程正常。
7. 再次点浏览器图标（sidebar 开着）→ 关闭侧边栏。
8. 快捷键 `Ctrl+Alt+B` toggle 侧边栏。
9. 开机不自动开浏览器（hydrate 忽略 "browser"）。
