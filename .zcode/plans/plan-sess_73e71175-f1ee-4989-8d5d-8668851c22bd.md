## 目标
切换中间面板打开的文件时（点击 tab、点击文件树、turn-files 卡片等任意入口），右侧文件树自动展开该文件的祖先目录、滚动定位并高亮到该文件节点。

## 现状
- 文件树是自建递归组件（`FileTree.tsx`），`DirNode` 惰性加载子节点（首次展开时 `api.file.listDir`，异步）。子节点仅在 `isOpen && children` 时渲染。
- 高亮已存在：`TreeNode` 比较 `activeFile === entry.path` 给 `FileNodeRow` 传 `active`，渲染 `bg-accent/15`。但**无滚动定位、无自动展开祖先**。
- 已有可复用：`setDirExpanded(dirPath, true)`（store:2962，强制展开，已展开则 no-op）、`dirname()`（lib/path.ts:23，算祖先路径）。
- `FileNodeRow` 的 `<button>` 当前无 ref。
- `activeFile` 经两条路径更新：`openFileInIde`（文件树点击/卡片）和 `setIdeActiveFile`（tab 切换）。两者都改 `ideActiveFileByProject[pid]`，文件树已订阅它做高亮重渲。

## 核心难点
祖先目录展开是异步链：`setDirExpanded` -> store set -> 重渲 -> `DirNode` 的 `useEffect` 触发 `api.file.listDir` -> `.then` 设 children -> 子节点挂载。目标文件节点要等整条链完成才挂载。因此 `scrollIntoView` 不能在 `activeFile` 变化时同步调用，必须等节点挂载。

## 方案（仅改 `FileTree.tsx`，不改 store/FilesPanel）

### 1. 节点注册表 + Context
在 `FileTree` 根组件用 `useRef<Map<string, HTMLButtonElement>>` 持有「文件绝对路径 -> DOM button 节点」映射。创建一个 `FileNodeRegistryContext`（React Context），把 Map 的 `register(path, el)` / `unregister(path)` 函数向下传。

`FileNodeRow` 的 `<button>` 加回调 ref：
```tsx
ref={(el) => { registerRef(path, el); }}
```
其中 `registerRef` 由 context 提供，内部做 `map.set(path, el)` / `el == null && map.delete(path)`（卸载时 React 传 null）。`FileTree` 以 `key={projectPath}` 重挂载，ref Map 随之重建，无残留。

### 2. reveal effect（在 `FileTree` 根）
订阅 `activeFile`（`ideActiveFileByProject[pid]`）。当它变化且属于当前 `projectPath`（`activeFile.startsWith(projectPath)`）时：

**a. 计算祖先目录链**：从 `dirname(activeFile)` 起，逐层 `dirname` 向上，收集到 `projectPath` 为止（不含 projectPath 本身，根级已渲染）。例如 `D:/proj/src/a.ts` + projectPath `D:/proj` -> 链 `["D:/proj/src"]`。

**b. 强制展开祖先**：对链中每个目录调 `setDirExpanded(dir, true)`。已展开的 no-op，不会重置子节点缓存。

**c. 滚动定位**（rAF 轮询）：
```ts
let frames = 0;
const MAX_FRAMES = 30; // ~500ms @60fps
const tryScroll = () => {
  const node = nodeMap.current.get(activeFile);
  if (node) {
    node.scrollIntoView({ block: "nearest", behavior: "smooth" });
    return; // done
  }
  if (++frames < MAX_FRAMES) requestAnimationFrame(tryScroll);
  // else: 祖先加载超时，放弃（不报错）
};
requestAnimationFrame(tryScroll);
```
- `block: "nearest"`：只在节点不在视口内时滚动最小距离，已可见则不动。
- `scrollIntoView` 自动沿 DOM 找最近可滚动祖先（`FilesPanel` 的 `overflow-y-auto` div），无需额外滚动容器 ref。
- cleanup：`activeFile` 再次变化或组件卸载时取消挂起的 rAF。

### 3. 边界处理
- `activeFile` 为 null 或不属于当前项目：不动作。
- 目标文件在未展开的深层目录：逐层 `setDirExpanded` 触发异步加载，rAF 轮询等到节点挂载后滚动。
- 目标文件已是活动文件且节点已挂载（如首次切到该项目）：effect 仍会跑，`scrollIntoView` no-op（已可见）或轻滚，无害。
- 同一 activeFile 不重复触发：effect 依赖 `activeFile`，相同值不重跑。

## 改动范围
仅 `apps/desktop/src/renderer/components/ide/FileTree.tsx`：
- 新增 `FileNodeRegistryContext` + Provider（在 `FileTree` 根）。
- `FileNodeRow` 加回调 ref 注册节点。
- `FileTree` 根新增 reveal effect（订阅 activeFile + 祖先展开 + rAF 滚动）。
- 新增 `dirname` import（`@renderer/lib/path.js`）。
- 复用 store 的 `setDirExpanded`（无需新增 action）。

不改 `FilesPanel.tsx`（`scrollIntoView` 自动找到它的滚动容器）、不改 store、不改 IPC。

## 验证
1. `npx tsc --noEmit -p tsconfig.json` 通过。
2. 手动验证：在中间面板通过 tab 切换到一个深层目录的文件 -> 右侧文件树自动展开祖先目录、滚动到该文件并高亮；切换到浅层文件 -> 同样定位；目标文件已可见时不过度滚动。
