## 组颜色 + 组拖动排序

### 总体思路
组不是 DB 实体（只是 `Project.group` 字符串），所以组元数据（颜色、顺序）用一个 **settings 表 JSON blob**（`ui.projectGroups`）存储，复用现有 `setting.get/set`，零新 IPC。颜色入口用组标题 hover 出的调色盘按钮 → `Menu` 弹出预设色板 + 自定义色 + 恢复默认。组拖动排序：把 `GroupNode` 从 `useDroppable` 升级为 `useSortable`，组之间可拖动换序，顺序写入同一个 JSON blob。

### 数据结构
`ui.projectGroups` 的值：
```json
{ "工作": { "color": "5 150 105", "order": 0 }, "个人": { "color": null, "order": 1 } }
```
- `color`: `"R G B"` triplet 或 `null`（沿用 `userMessageColor`/`accentColor` 的格式，复用 `RGB_TRIPLET_RE` 校验、`hexToTriplet`/`tripletToHex` 转换）
- `order`: 组的显示顺序（数字越小越靠前）

### 涉及文件

#### 1. 契约层 `packages/contracts/src/ipc.ts`
新增 setting key 常量（紧挨其他 `UI_*_SETTING_KEY`）：
```ts
export const UI_PROJECT_GROUPS_SETTING_KEY = "ui.projectGroups";
```
新增 zod schema 描述组元数据（用于校验从 DB 读回的 JSON）：
```ts
export const ProjectGroupMetaSchema = z.object({
  color: z.string().nullable().optional(),
  order: z.number().optional(),
});
export const ProjectGroupsMetaSchema = z.record(z.string(), ProjectGroupMetaSchema);
export type ProjectGroupsMeta = z.infer<typeof ProjectGroupsMetaSchema>;
// → Record<groupName, { color?: string|null, order?: number }>
```

#### 2. Zustand store `apps/desktop/src/renderer/stores/sessionStore.ts`
- **State 字段**：`groupMeta: ProjectGroupsMeta`（默认 `{}`，line 297 附近）
- **init() hydration**（仿 displayMode，line 1930 区域）：读 `ui.projectGroups` → `JSON.parse` → 校验后 `set({ groupMeta })`
- **Action `setGroupColor(name, rgb)`**：更新 `groupMeta[name].color`，debounce 写回整个 blob（仿 `schedulePaneWidthPersist` 的去抖写入模式，但更简单——直接写，因为改色不是高频操作）
- **Action `setGroupOrder(orderedNames)`**：把 `groupMeta` 里所有组的 order 重写为索引，写回 blob
- **Action `renameGroupMeta(oldName, newName)`**：在 groupMeta 里把 oldName 的条目重命名为 newName（保持 color/order），写回。**重命名分组时要调它**（现有 `GroupDialog` 的 rename 提交处，LeftBar 里遍历成员 `setProjectGroup` 的同时调这个）。
- **Action `pruneGroupMeta(activeNames)`**：清理已解散的组（可选，做防御）。实际上 stale 条目无害（读时按需取），可在 dissolve 时顺带删。

#### 3. LeftBar UI `apps/desktop/src/renderer/components/layout/LeftBar.tsx`（重点）

**A. 分组顺序：让 `groupedProjects` 尊重存储的 order**
当前 `groupedProjects` 的 Map 顺序是「首次出现」（line 229-247）。改为：先按 `groupMeta[g].order` 排序已知组，再按首次出现兜底（处理 meta 里没有的新组）。
```ts
// 在 useMemo 里，构建完 grouped Map 后：
const orderedEntries = [...grouped.entries()].sort((a, b) => {
  const oa = groupMeta[a[0]]?.order ?? Number.MAX_SAFE_INTEGER;
  const ob = groupMeta[b[0]]?.order ?? Number.MAX_SAFE_INTEGER;
  return oa - ob;
});
const groupedProjects = new Map(orderedEntries);
```
`knownGroups` 跟着这个顺序。

**B. 组颜色：传给 GroupNode + 染图标**
- 调用处（line 451 的 `<GroupNode>`）传 `groupColor={groupMeta[groupName]?.color ?? null}`
- `GroupNode` 加 `groupColor?: string | null` prop，应用到 `IconStack2`：
  ```tsx
  <IconStack2 size={13} className="shrink-0"
    style={groupColor ? { color: tripletToHex(groupColor) ?? undefined } : undefined} />
  ```

- 自定义：native `<input type="color">`（仿 AppearancePanel）

- 调色盘按钮的当前色用组色显示（小圆点或图标着色），让用户一眼看出该组已设色

**D. 组拖动排序：GroupNode 用 useSortable**
把 `GroupNode` 的 `useDroppable` 换成 `useSortable`（仿 `SortableProjectNode` 的模式，但内联在 GroupNode 里）：
```ts
const { attributes, listeners, setNodeRef, transform, transition, isDragging } =
  useSortable({ id: `group:${groupName}` });
```
- ref + transform 贴在标题 `<div>` 上
- listeners 贴在标题 `<div>` 上（整行可拖，和项目行一致）
- 保留 drop-to-reassign 行为：useSortable 的元素天然也是 drop target，`onDragOver` 里 `overId.startsWith("group:")` 的分支继续工作
- 拖拽时 `opacity-50`

**E. sortableItems 加组 id**
```ts
const sortableItems = useMemo(() => {
  const ids = displayOrder.map((p) => `proj:${p.id}`);
  if (projectView === "grouped") {
    // 组也是 sortable 项，插到对应位置（组的顺序在前）
    for (const g of groupedProjects.keys()) ids.push(`group:${g}`);
  }
  return ids;
}, [displayOrder, projectView, groupedProjects]);
```

**F. onDragEnd 加 group 分支**
```ts
const onDragEnd = (e) => {
  const { active, over } = e;
  if (!over || active.id === over.id) return;
  const activeId = String(active.id);
  const overId = String(over.id);
  // 组之间排序
  if (activeId.startsWith("group:") && overId.startsWith("group:")) {
    const names = Array.from(groupedProjects.keys());
    const from = names.indexOf(activeId.slice(6));
    const to = names.indexOf(overId.slice(6));
    if (from === -1 || to === -1 || from === to) return;
    const next = arrayMove(names, from, to);
    void setGroupOrder(next);
    return;
  }
  // 项目排序（现有逻辑）
  if (!activeId.startsWith("proj:") || !overId.startsWith("proj:")) return;
  // ... 现有 arrayMove + reorderProjects
};
```
`onDragOver` 不需要改（组拖动只换序，不改组成员；项目拖到组上才改组——现有 `proj:` active 分支已覆盖）。

**G. 重命名分组时同步 meta**
现有 LeftBar 里 `GroupDialog` 的 rename 提交（line 621-633 区域）遍历成员调 `setProjectGroup`，在旁边加一句 `void renameGroupMeta(oldName, newName)`，让颜色/顺序跟着组名迁移。

**H. 解散分组时清理 meta**
现有 `onDeleteGroup`（LeftBar line 463-465）把成员 group 置 null。加一句清理 meta（可选，stale 无害，但干净起见）：在 store 的某个 action 里或就地 `setGroupColor(name, null)` + 移除 order。简单做法：解散时不主动清，读 groupMeta 时按 active 组过滤。

### 边界情况与决策
1. **新组无 meta**：新建分组时 groupMeta 里没有该组条目 → color 为 null（默认色）、order 兜底为 MAX（排到末尾）。首次拖动或设色后自动补上。
2. **重命名**：`renameGroupMeta(old, new)` 把 color/order 一起迁移；成员的 group 字段由现有 `setProjectGroup` 批量改。
3. **解散**：meta 里残留条目无害（读时按 `groupedProjects.keys()` 过滤）。可选在 `pruneGroupMeta` 里清。
4. **颜色格式**：统一用 "R G B" triplet 存储（和 userMessageColor/accentColor 一致），UI 层用 `tripletToHex` 转 hex 给 CSS/icon。
5. **预设色板**：新建 `GROUP_COLOR_PRESETS`（或复用 ACCENT_PRESETS 的子集），放在 LeftBar 顶部或 colorUtils 旁。
6. **组图标染色**：仅 `IconStack2` 用 `style={{ color: hex }}`；不染文字、不染边框（按你的选择）。
7. **图标**：调色盘按钮用 `IconPalette`（确认在 icons.tsx 里，没有则用 `IconColorSwatch` / `IconBrush`）。
8. **typecheck**：改完跑 `cd apps/desktop && npx tsc --noEmit -p tsconfig.json`。

### 实现顺序
1. 契约层（ipc.ts setting key + zod schema + 类型）
2. store（groupMeta state + init hydration + setGroupColor/setGroupOrder/renameGroupMeta actions）
