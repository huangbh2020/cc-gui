# 终端功能优化实施计划

## 需求 1：修复终端右键「复制/粘贴」菜单（当前右键无反应）

### 根因
`TerminalView.tsx` 现在用 base-ui 的 `ContextMenu.Root/Trigger` 包裹 host div。但 xterm v6 在 `term.open(host)` 时用**原生 `addEventListener('contextmenu', …)`** 在同一 host 上抢先注册了自己的右键处理器（`rightClickHandler` → `moveTextAreaUnderMouseCursor` 把隐藏 textarea 移到光标并 `select()`）。该原生监听器在 host 的**冒泡阶段**执行，先于 / 干扰 base-ui 的 ContextMenu 触发逻辑，导致菜单打不开。普通 `<button>`（如 FileTree）没有这层抢占，所以 FileTree 的右键菜单正常。

### 修复方案
放弃 base-ui `ContextMenu.*`，改用项目已验证的**受控 `Menu.Root` + 虚拟 anchor + 原生捕获监听器**模式（参考 `OpenTabsBar.tsx:545-619` 的 `FileTabContextMenu`）。

**改动文件**：`apps/desktop/src/renderer/components/ide/TerminalView.tsx`

1. **import 调整**：`ContextMenu` → `Menu`（`from "@base-ui/react/menu"`）；新增 `useMemo`。
2. **host div 解耦**：把 host 从 `ContextMenu.Trigger` 的 `render` 里拿出来，恢复为普通 `<div ref={hostRef} className=… style=… data-terminal-session=…>`（xterm 仍 `term.open(host)`）。
3. **新增右键状态**：`const [ctxMenu, setCtxMenu] = useState<{ x: number; y: number } | null>(null);`
4. **原生捕获监听器**（核心修复）：新增 `useEffect([sessionKey])`，在 `hostRef.current` 上 `addEventListener("contextmenu", handler, true)`（**捕获阶段**，先于 xterm 的冒泡监听器）。handler 内：
   - `e.preventDefault();` —— 阻止浏览器原生右键菜单
   - `e.stopImmediatePropagation();` —— 阻止 xterm 的 `moveTextAreaUnderMouseCursor`（避免隐藏 textarea 抢焦点/选区抖动）
   - `setCtxMenu({ x: e.clientX, y: e.clientY })`
   - 清理时 `removeEventListener`。
5. **虚拟 anchor**（复用 OpenTabsBar 实现）：`useMemo` 返回 `{ getBoundingClientRect: () => ({ x, y, top: y, left: x, … width:0, height:0 }) }`，让菜单定位到光标处。
6. **菜单 JSX**（受控）：
   ```tsx
   <Menu.Root open={!!ctxMenu} onOpenChange={(o) => { if (!o) setCtxMenu(null); }}>
     <Menu.Portal>
       <Menu.Positioner anchor={anchor} side="bottom" align="start" sideOffset={4}>
         <Menu.Popup className={CTX_MENU_POPUP_CLASS}>
           {/* 复制项：disabled={!hasSelection}，onClick={copySelection} —— 不变 */}
           {/* 粘贴项：onClick={pasteFromClipboard} —— 不变 */}
         </Menu.Popup>
       </Menu.Positioner>
     </Menu.Portal>
   </Menu.Root>
   ```
   `CTX_MENU_POPUP_CLASS` / `CTX_MENU_ITEM_CLASS` 这两个 className 常量沿用（它们是项目自定义样式，对 Menu 同样适用）。
7. **保持不变**：`copySelection`、`pasteFromClipboard`、`hasSelection`、键盘快捷键 `handleKeyEvent`（Ctrl+Shift+C/V 等）逻辑全部不动。

### 验证点
- 右键终端任意位置 → 菜单在光标处弹出（不再弹浏览器原生菜单）。
- 有选中时「复制」可用，无选中时灰；点击后复制到剪贴板并清选区。
- 「粘贴」读取剪贴板写入 PTY（换行规范化为 `\r`）。
- 点击菜单项或菜单外 → 菜单关闭。
- Ctrl+Shift+C/V、Cmd+C/V 键盘快捷键仍正常。

## 需求 2：运行自定义命令时新建终端并切换过去

### 方案
用户选了「新建并切过去」。当前 `runCommand` 只把命令写进当前活动终端。新增「在新终端运行」路径，并保留「在当前终端运行」作为次要入口。

**改动文件 1**：`apps/desktop/src/renderer/components/ide/TerminalPanel.tsx`

1. **新增 ref**：`const pendingCommandBySession = useRef<Map<string, string>>(new Map());`（per-session，符合 AGENTS.md 里"多 tab 并发不互相覆盖"的约定）。
2. **新增 `runCommandInNewTerminal(command)`**：
   ```ts
   const runCommandInNewTerminal = useCallback((command: string) => {
     if (!projectPath) return;
     const s = makeSession();
     const st = termsRef.current.get(projectPath);
     if (st) { st.sessions = [...st.sessions, s]; st.activeKey = s.key; }
     else { termsRef.current.set(projectPath, { sessions: [s], activeKey: s.key }); }
     keyToPathRef.current.set(s.key, projectPath);
     pendingCommandBySession.current.set(s.key, command);  // 等 PTY running 后写入
     forceRender();
   }, [projectPath]);
   ```
3. **在 `onStatusChange` 回调里消费待运行命令**（PTY 异步 spawn，需等 running）：渲染 `TerminalView` 处把 `onStatusChange` 扩展为：
   ```ts
   onStatusChange={(status, detail) => {
     updateStatus(s.key, status, detail);
     if (status === "running") {
       const cmd = pendingCommandBySession.current.get(s.key);
       if (cmd) {
         pendingCommandBySession.current.delete(s.key);
         const id = handlesRef.current.get(s.key)?.getTerminalId();
         if (id) void api.terminal.write({ terminalId: id, data: `${cmd.replace(/\r\n|\n|\r/g, "\r")}\r` });
       }
     }
   }}
   ```
   换行规范化沿用现有 `runCommand` 注释里的规则（shell 在 `\r` 提交）。
4. **传递给菜单**：`<TerminalCommandsMenu onRun={runCommand} onRunInNewTerminal={runCommandInNewTerminal} />`。
5. **保留** `runCommand`（当前终端运行）不动。

**改动文件 2**：`apps/desktop/src/renderer/components/ide/TerminalCommandsMenu.tsx`

1. **新增 prop**：`onRunInNewTerminal: (command: string) => void`。
2. **主点击改为新终端运行**：命令项的主体按钮（名字 + 命令文本区域，103-105 行）`onClick` 改为 `onRunInNewTerminal(cmd.command)`，tooltip 改为「在新终端中运行」。
3. **保留 hover 播放按钮为「当前终端运行」**：`IconPlayerPlay` 按钮（117-124 行）`onClick` 仍调 `onRun(cmd.command)`，tooltip 改为「在当前终端运行」。
   - 这样：默认点命令 = 新建终端跑（符合需求）；hover 播放图标 = 复用当前终端（保留原能力，不破坏）。
4. 其余（添加命令对话框、空态、样式）不变。

### 验证点
- 点命令名 → 新 tab 出现并自动激活 → PTY 启动后命令被自动输入并执行 → 看到输出。
- 关闭项目/切项目时，`pendingCommandBySession` 里的残留条目随 session 销毁自然失效（命令未执行也无副作用）。
- hover 播放按钮 → 仍在当前活动终端运行（原行为）。
- 多 tab 并发运行不同命令不会串（per-session 桶）。
