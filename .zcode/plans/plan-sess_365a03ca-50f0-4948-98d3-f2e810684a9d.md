# 方案 B:可安装的语言服务器(LSP)+ Monaco 跳转

## 目标
在设置页为每种语言提供"安装 / 启用 / 启动"语言服务器的能力;启动后 Monaco 编辑器获得**跳转定义、查找引用、悬停信息**(F12 / Ctrl+Click / Shift+F12 / hover)。首期语言:**TypeScript/JavaScript、Python、Go、Java**。

## 总体架构

```
Renderer (Monaco)                       Main (LspManager)
  ┌──────────────────────┐                ┌──────────────────────────┐
  │ EditPane onMount     │  lsp.request   │ LspManager               │
  │  registerDefinition  │ ──(RPC)──────► │  per (workspace,lang)    │
  │  Provider            │                │   child_process.spawn    │
  │  registerReference   │  lsp.response  │      │                   │
  │  Provider            │ ◄──(push)───── │      ▼  stdio JSON-RPC   │
  │  registerHover       │                │   tsserver/pyright/...   │
  │  setModelMarkers     │  lsp.event     │                          │
  │  (diagnostics)       │ ◄──(push)───── │  install(): spawn npm/pip│
  └──────────────────────┘                └──────────────────────────┘
        │  openFileInIde(path, line, col)
        ▼
  sessionStore.idePendingReveal ── EditPane useEffect ──► revealLineInCenter
```

**桥接方式**:手写 Provider + IPC(不引入 monaco-languageclient)。每个 LSP 能力对应一个 `lsp.request` RPC;诊断通过 `lsp:event` 推送。LspManager 内部对子进程讲 JSON-RPC 2.0,对外讲项目内既有的 zod-IPC。

### 1. `apps/desktop/src/main/lsp/languageSpecs.ts`(新)
声明式语言规格表——**这是"可扩展安装"的核心**。每种语言声明:二进制名、探测候选、安装命令、启动命令、启动参数、LSP 初始化选项。

```ts
export interface LanguageServerSpec {
  language: LspLanguageId;
  displayName: string;
  /** 用于 which() 探测的可执行名(平台相关) */
  binaryNames: string[];            // ["typescript-language-server"]
  /** 安装命令(平台分派) */
  install: { win32: string[]; darwin: string[]; linux: string[] };
  /** 启动命令(若与探测二进制不同,如 pyright-langserver vs pyright) */
  startCommand: (resolved: string) => { cmd: string; args: string[] };
  /** LSP initialize 的 initializationOptions(可选) */
  initOptions?: unknown;
  /** 文件扩展名 → 是否归此语言 */
  matchesExt: (ext: string) => boolean;
}
```

四种语言规格:

| 语言 | binaryNames | install(win32示例) | startCommand |
|------|-------------|--------------------|--------------|
| typescript | `typescript-language-server` | `["npm","install","-g","typescript-language-server","typescript"]` | `(p)=>({cmd:p,args:["--stdio"]})` |
| python | `basedpyright-langserver` | `["pip","install","basedpyright"]` | `(p)=>({cmd:p,args:["--stdio"]})` |
| go | `gopls` | `["go","install","golang.org/x/tools/gopls@latest"]` | `(p)=>({cmd:p,args:["serve"]})` |
| java | `jdtls` | win32/linux:`["curl","-L","...tar.gz"]`(*) ;darwin:`["brew","install","jdtls"]` | `(p)=>({cmd:p,args:[]})` |

(*)**Java 注意事项**:`jdtls` 无统一包管理器入口。win/linux 走"下载 eclipse.org tar.gz → 解压到 userData/lsp/java"。install 命令实际由 LspManager 用 `https` 模块下载 + tar 解压实现(不走 shell),darwin 才用 brew。计划里 Java 的 install 是一条特殊路径(LspManager 内 `installJava()` 方法),其余三种走通用 `spawn(spec.install[platform])`。**Java 还需本机有 JDK**;健康检查时若 `java -version` 失败,返回明确错误。

### 2. `apps/desktop/src/main/lsp/LspManager.ts`(新,~400 行)
模仿 `terminal/TerminalManager.ts` 的单例 + Map 管理模式。

```ts
class LspManagerImpl {
  // (workspacePath, language) → ServerHandle
  private servers = new Map<string, ServerHandle>();
  // (language) → install 进程 + 输出缓冲
  private installs = new Map<LspLanguageId, InstallHandle>();

  // —— 配置(SettingRepo 持久化)——
  loadConfig(): LspServerConfig[];          // 从 LSP_SERVERS_SETTING_KEY 读 + 补默认
  saveConfig(configs): void;

  // —— 状态查询(给 lsp.list)——
  async list(): Promise<{ languages: LspLanguageState[] }>;

  // —— 安装/卸载 ——
  async install(language): Promise<LspOpResult>;    // spawn 包管理器;流式收集 stdout/stderr 到 installLog;成功后探测 binaryNames
  async uninstall(language): Promise<LspOpResult>;  // npm uninstall -g / pip uninstall / brew uninstall / 删 java 目录
  async healthCheck(language): Promise<LspOpResult>;// which + `binary --version`

  // —— 启用/禁用 + 路径配置 ——
  async toggle(language, enabled): Promise<{ languages }>;
  async setPath(language, serverPath?, args?): Promise<{ languages }>;

  // —— 文档同步(被 IPC 调用)——
  async openDocument(workspacePath, filePath, language): Promise<void>;
  async closeDocument(workspacePath, filePath): Promise<void>;
  async didChange(workspacePath, filePath, text, version): Promise<void>;
  async didSave(workspacePath, filePath, text): Promise<void>;

  // —— 能力请求(definition/references/hover 等)——
  async request(workspacePath, language, method, params): Promise<{result}|{error}>;

  // —— 生命周期 ——
  disposeAll(): void;   // before-quit 调用,kill 所有子进程
}
export const lspManager = new LspManagerImpl();
```

**ServerHandle** 内部结构:
```ts
interface ServerHandle {
  proc: ChildProcess;
  workspacePath: string;
  language: LspLanguageId;
  nextId: number;                  // JSON-RPC id 计数器
  pending: Map<number, { resolve, reject, timer }>;
  buffer: string;                  // Content-Length 分帧缓冲
  openUris: Set<string>;           // 已发 didOpen 的文档
  initialized: Promise<void>;      // initialize 握手完成才放行 request
}
```

**JSON-RPC 收发**(手写,~80 行):
- 发:`writeMessage(proc.stdin, {jsonrpc:"2.0",id,method,params})` + `Content-Length` 头。
- 收:`proc.stdout.on("data")` 累积到 buffer,按 `Content-Length` 切帧,`JSON.parse`。有 `id` → 查 `pending` 表 resolve;无 `id` → 通知,按 `method` 分派:
  - `textDocument/publishDiagnostics` → `sendToRenderer(IPC.LSP_EVENT, {type:"diagnostics", payload})`
  - `window/logMessage` / `window/showMessage` → `sendToRenderer(IPC.LSP_EVENT, {type:"log", payload})`
  - `$/...` → 忽略

**启动流程** `ensureServer(workspacePath, language)`:
1. 查 `servers` Map;命中且进程存活 → 直接返回。
2. 读 config,`enabled` 为 false → 抛"未启用"。
3. 解析路径:config.serverPath || `which(binaryNames)`;找不到 → 抛"未安装,请先在设置页安装"。
4. `spawn(cmd, args, { cwd: workspacePath, stdio:["pipe","pipe","pipe"] })`。
5. 发 `initialize`({ processId, rootUri: `URI.file(workspacePath).toString()`, capabilities:{...} }) → 等 `initialized` 响应 → 发 `initialized` 通知。
6. 存入 Map,resolve `initialized` Promise。

**懒启动**:不在 app 启动时拉起;首次 `openDocument` / `request` 时 ensureServer。

**二进制探测**:复用 `terminal/shellResolve.ts` 的 `which()` 逻辑——为避免循环依赖,把 `which` 抽到 `lib/binaryResolve.ts`(从 shellResolve.ts 移出,shellResolve 改为 re-export),LspManager 和 shellResolve 共用。

### 2. 新模块 `apps/desktop/src/renderer/lib/lspProviders.ts`(新,~200 行)
```ts
export function registerLspProviders(monaco, language: LspLanguageId): IDisposable[] {
  const disposers: IDisposable[] = [];
  // 定义→引用
  disposers.push(monaco.languages.registerDefinitionProvider(language, {
    provideDefinition: async (model, pos) => {
      const r = await api.lsp.request({ workspacePath, language, method:"textDocument/definition",
        params:{ textDocument:{uri: uriOf(model.uri)}, position: toLspPos(pos) } });
      return r.result ? toMonacoLocation(r.result) : null;
    }
  }));
  // 同理 registerReferenceProvider (textDocument/references)
  //      registerHoverProvider      (textDocument/hover)
  return disposers;
}
```
辅助:`uriOf(monaco.Uri)` = `uri.toString()`(已是 `file://`);`toLspPos`/`toMonacoRange`/`toMonacoLocation` 做坐标转换(LSP 0-based ↔ Monaco 1-based)。

## 八、安全 / 边界(遵循 AGENTS.md)

1. **zod 校验**:所有 `lsp.*` 入参在主进程 handler 里 `Schema.parse(raw)`,不直接用 raw。
2. **路径校验**:`workspacePath` / `filePath` 在 LspManager 里过 `isKnownProjectPath` / `pathWithin`(从 `lib/pathGuard.ts`)——只允许已注册项目内的文件进 LSP。防止 renderer 传任意路径让 server 读敏感文件。
3. **CSP**:LSP 全走 IPC,不引入 CDN/外网;`vscode-uri` 是纯本地 bundle,不触发 CSP。
4. **进程清理**:`before-quit` → `lspManager.disposeAll()` 杀全部子进程;`disposeAll` 对每个 proc `proc.kill()` + 等退出 + swallow error。
5. **崩溃恢复**:ServerHandle 监听 `proc.on("exit")`;非主动关闭时记 log + 从 Map 移除 + 推 `stateChanged{running:false}`;下次 request 自动 ensureServer 重启。
