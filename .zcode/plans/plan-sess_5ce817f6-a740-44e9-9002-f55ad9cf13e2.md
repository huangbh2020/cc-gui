## 目标

消息流渲染改为"只看最终输出":每个回合(text/输出)的过程数据——所有 thinking + 全部 tool_use(含 Edit)——聚合为**一个默认折叠的大卡片**;text / error / plan / turn-files / attachment 等用户可见内容正常渲染。

预期效果:
```
[user] 请重构这个模块
[过程大卡片·折叠] ▸ 思考 + 6 个操作 · Bash ×3 · Edit ×2   ← 展开可看全部 thinking/工具调用/Edit diff
[assistant] 重构完成,核心改动如下:...                      ← 最终输出正常展示
```

## 改动文件(2 个)

### 1. `ChatPane.tsx` — 重写 `groupMessagesForRender`(按回合 hoisting)

- 新增辅助:
  - `hasProcessBlocks(msg)` — blocks 是否含 thinking/tool_use
  - `stripProcessBlocks(msg): ChatMessage` — 克隆消息,blocks 只保留非过程块(同一 id,供 keyExtractor / 时间轴使用)
- 重写分组算法:
  - 遍历 messages,以 **user 消息为回合边界**
  - 回合内所有 assistant 消息的过程块(thinking/tool_use 含 Edit)收集进该回合的 `proceduralCluster`(一个折叠卡片)
  - 非过程块克隆为 `single` 项;`isTurnTail`(复制按钮)按原消息下标计算
  - 卡片插入位置 = 回合内**第一个过程块出现处**(通常即回合开头)
  - **统计行每回合只渲染一次**:回合起始消息(turnMeta)若贡献了过程块 → turnMeta 移到卡片上,克隆 single 剥掉 turnMeta;否则文本 single 保留
  - **流式 spinner 唯一**:构建完 items 后,若 running 且末条为 assistant,把 `isStreamingTail` 设到 items 中最后一个 assistant 内容项(单条或卡片)
- 保留 `flattenCluster`、`pendingTurn` 合成、`userMsgToRenderIndex`(user 消息仍为独立 single,时间轴不受影响)
- 删除不再需要的 `isProceduralMessage`

### 2. `MessageBlocks.tsx` — `groupBlocks` 移除 Edit 特判

- 删除 `isInlineEditBlock` 及其分支:Edit 并入过程运行(与 hoisting 后 single 不再含过程块保持一致,兜底正确性)

## 不改的部分

- `renderListItem` / `MessageRow` / `ProceduralGroup` 基本不变(ProceduralGroup 本就是默认折叠态,满足"并且折叠")
- plan 卡片、turn-files 卡片不是过程数据,保持正常可见
- 存储层不动——只是渲染层聚合,持久化数据不变

## 验证

- `npx tsc --noEmit -p tsconfig.json`
- 逻辑走查:统计行每回合一次、流式底部 spinner 唯一、时间轴索引不变、pendingTurn 正常、复制按钮仍在最终文本上
