# 左侧栏改造：树形布局 + 归档/删除 实现计划

## 目标

把左侧栏从「Projects + Sessions 两个平铺列表」改成 **「项目 > 线程」树形布局**，每个项目和线程支持 **归档（软删）** 和 **删除（硬删）**，并支持同时管理多个项目。

三个已确认的设计决策：
1. **归档 = 软删**（archived 标志，从主列表隐藏，可恢复）；**删除 = 硬删**（级联 DELETE，不可恢复）
2. **树形嵌套**：项目为父节点（可折叠），线程为子节点
3. **启动全量预加载**：所有项目的会话一次性加载并按项目缓存

---

## 已确认的现状（基于精读）

- `LeftBar.tsx`：两个平铺 section（Projects/Sessions/Tasks 存根），项目 `<li>` **无 onClick**（无法切换项目）
- `sessionStore`：只有 `sessions: Session[]`（单一数组，只存当前项目的），无 `selectProject` / delete / archive action
- 契约层 `Project`/`Session` **无 archived 字段**
- `ProjectRepo` 只有 create/list/get；`SessionRepo` 无 delete/archive
- DB 外键已配 `ON DELETE CASCADE`（projects→sessions→messages）+ `PRAGMA foreign_keys = ON`，**硬删基础设施现成**，只是没有调用入口
- `addColumnIfMissing` 范式已建立（向后兼容加列）
- IPC/delete 可参考 `customModel.delete` 现成模式

---

## 实现方案（4 层，自底向上）

### 第 1 层：契约层

**`packages/contracts/src/session.ts`**：
- `Project` 加 `archived: boolean`
- `Session` 加 `archived: boolean`

**`packages/contracts/src/ipc.ts`**（照 customModel.delete 模式）：
- 加 schema：`DeleteProjectSchema`、`ArchiveProjectSchema`（含 `archived: boolean`）、`DeleteSessionSchema`、`ArchiveSessionSchema`
- 加 `RpcMap` 条目：`project.delete / project.archive / session.delete / session.archive`
- 加 `IPC` 常量：`PROJECT_DELETE / PROJECT_ARCHIVE / SESSION_DELETE / SESSION_ARCHIVE`
- `project.list` / `project.sessions` 的返回类型不变（renderer 侧自己过滤 archived，方便"已归档"视图切换）

### 第 2 层：持久化层

**`db.ts`** migrate（用 addColumnIfMissing，老库自动迁移）：
- `projects` 加 `archived INTEGER NOT NULL DEFAULT 0`
- `sessions` 加 `archived INTEGER NOT NULL DEFAULT 0`

**`repositories.ts`**：
- `ProjectRow` / `SessionRow` 加 `archived` 字段，`rowToProject`/`rowToSession` 转成 boolean
- `ProjectRepo` 加：`delete(id)`（DELETE，级联自动）、`setArchived(id, archived)`、`list()` 不变（返回含 archived 的全量，让 renderer 决定过滤）
- `SessionRepo` 加：`delete(id)`（级联删 messages）、`setArchived(id, archived)`
- `SessionRepo.create` 写入 `archived: 0`

### 第 3 层：IPC + preload

**`main/ipc/projects.ts`** 加 4 个 handler（project.delete/archive、session.delete/archive），每个先 zod parse 再调 repo。session 的两个 handler 可放 projects.ts 或新建 sessions.ts（倾向放 projects.ts，量小）。

**`preload/index.ts`**：
- `api.project` 加 `delete / archive`
- `api.session` 加 `delete / archive`

### 第 4 层：store + UI（核心）

**`sessionStore.ts`** —— 重构会话缓存结构（影响最大）：

当前 `sessions: Session[]` 只存当前项目的。改成 **按项目缓存**：
```ts
sessionsByProject: Record<string, Session[]>;  // projectId → 该项目所有会话
```
保留 `sessions` 作为**当前活跃项目会话**的派生视图（= `sessionsByProject[activeProjectId]`），或直接让组件从 `sessionsByProject` 取。倾向后者（少一份冗余）。

新增 state：
- `archivedProjects: Project[]`、`archivedSessionsByProject: Record<string, Session[]>`（或合并到上面，用 archived 字段过滤）—— 倾向**合并**：`projects` 含全部（含 archived），组件按 `p.archived` 分组显示
- `expandedProjects: Set<string>`（树形折叠态，内存态不持久化）
- `showArchived: boolean`（是否显示已归档项）

新增 actions：
- `selectProject(projectId)`：设 activeProjectId + 从 sessionsByProject 取（已预加载则无 IO）+ 自动选最新会话。把现有 `init` 里"取 sessions + 选最新"的逻辑抽成此 action 复用
- `deleteProject(id)`：调 api → 从 projects 移除 + 删 sessionsByProject[id] → 若删的是 active，切到第一个剩余项目
- `archiveProject(id, archived)`：调 api → 更新本地 projects 里该条的 archived 字段
- `deleteSession(id)` / `archiveSession(id, archived)`：同理，操作 sessionsByProject 对应数组 + 若删的是 active 会话则切到同项目下一个
- `init` 改成：加载所有 projects → **循环为每个 project 调 `project.sessions`** 填充 sessionsByProject → 选首个未归档项目 + 其最新未归档会话

**`LeftBar.tsx`** —— 重写成树形：

```
EXPLORER                    [+ 添加项目]
─────────────────────────────────────
▾ 📁 my-claude-gui        ⋯(hover→归档/删除)
    💬 P2会话持久化
    💬 自定义模型        ✓(active)
    💬 颜色主题
▸ 📁 blog-site            ⋯
▸ 📁 todo-app             ⋯
─────────────────────────────────────
[显示已归档 (3)]   ← 折叠的归档区,点开列出
```

- 项目行：📁 图标 + 名字 + 折叠箭头(▾/▸) + hover 出 `⋯` 菜单(归档/删除/重命名可选)；点项目名 = 展开/折叠 + selectProject
- 会话行：缩进一级，💬 + 标题；hover 出 `⋯`(归档/删除)；点 = selectSession；右上"+ 新建会话"按钮挂在当前 active 项目下
- 归档区：底部折叠列表，显示 archived 的项目和会话，支持"恢复"（再点归档 = 取消）
- 空项目：显示"暂无线程，+ 新建"
- 确认对话框：删除用 `confirm()`（硬删不可恢复，必须确认）；归档不确认（可恢复）

**交互细节**：
- 删除项目：confirm("删除项目「X」及其所有线程?此操作不可恢复")
- 删除会话：confirm("删除线程「X」?")
- 归档：静默执行，可在归档区找回

## 关键风险与边界

1. **sessionStore 重构影响面**：`sessions` 改成 `sessionsByProject` 后，所有读 `sessions` 的地方（selectSession、sendPrompt、ingestEvent 里更新 session 字段、ChatPane 取 active session 等）都要适配。这是最大工作量，需仔细 grep 所有 `s.sessions` / `get().sessions` 引用点。
2. **ingestEvent 里的 session 更新**：流式事件中要更新某 session 的 title/status/snapshot 等，现在要从 `sessionsByProject[sessionId所属项目]` 里找。需要保证 sessionId→projectId 的反查（可从 session 对象本身取 projectId）。
3. **active session 删除后的切换**：删掉当前会话，要切到同项目下一个未归档会话；同项目全空则停留在空态；删项目则切到下一个项目。
4. **Tasks 存根**：LeftBar 底部的 Tasks section 是死的，重写时一并清理掉（不属于本需求但挡路）。
5. **不持久化展开态**：`expandedProjects` / `showArchived` 是纯 UI 态，放 store 但不落盘（刷新重置，可接受）。

## 验收路径

1. 添加 3 个项目 → 树形显示，可分别展开折叠
2. 每个项目下新建多个线程 → 缩进显示在该项目下
3. 点项目名 → 切换 active 项目，会话列表正确切换
4. 线程 hover → 归档 → 从主列表消失，进归档区 → 可恢复
5. 线程删除 → confirm → 永久删除（DB 里 messages 也级联没了）
6. 项目归档/删除 → 同理，删除级联清掉其下所有线程+消息
7. 重启应用 → 数据一致（归档态保留、活跃项目/会话恢复）
8. `npx tsc --noEmit -p tsconfig.json` 通过

## 实现顺序

1. 第 1-3 层（契约 + 持久化 + IPC + preload）—— 打通数据通道，typecheck
2. 第 4 层 store 重构 —— sessionsByProject + 全量预加载 + selectProject，**先不改 UI**，让现有 LeftBar 在新 store 上能跑（可能要临时适配）
3. 第 4 层 UI —— LeftBar 重写成树形 + 归档/删除
4. 联调 + typecheck

每层结束 typecheck 一次。store 重构是关键节点，要 grep 全部 `sessions` 引用确保无遗漏。
