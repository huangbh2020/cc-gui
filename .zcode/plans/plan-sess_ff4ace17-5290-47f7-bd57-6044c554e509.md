## 目标回顾

把 composer 的 `<textarea>` 换成 Tiptap 富文本编辑器,使 `/` 选中的 skill 成为**内联胶囊**(像 Slack 的 @mention):在输入框里与文字在一起、退格整体删除;发送后在消息流用户气泡里也以**内联胶囊**形式在文字原位渲染。文件(@mention)和粘贴保持现有「chip 在输入框上方」的行为不变,以控制改动范围。

## 依赖

新增(pnpm add 到 `apps/desktop`):
- `@tiptap/react` — React 集成(`EditorContent` + `useEditor`)
- `@tiptap/starter-kit` — 基础节点(Paragraph/Text/History 等)
- `@tiptap/extension-mention` — 内联 mention 节点(用作 skill 胶囊的原子节点骨架)
- `@tiptap/suggestion` + `tippy.js`(Mention 扩展的浮动 UI 依赖)—— 实际上我们会**自定义 Suggestion 的 render**,直接复用现有 `SlashCommandPicker`,所以 `tippy.js` 可不引入(见下)。

Tiptap 已确认支持 React 19(`@tiptap/react` changelog 明确加了 React 19 ref 支持)。

## 核心架构

```
Tiptap Editor (contenteditable)
  ├── 文档结构: <p> 文本… <span data-skill="pdf"> ✦/pdf </span> …文本 </p>
  │                 └── skill 节点 = Mention 扩展的 node,isEditable=false,原子删除
  ├── /  触发 → Suggestion 插件 → 渲染现有 SlashCommandPicker(不引入 tippy)
  │            选中 → editor.commands.insertContent 插入 skill 节点(替换 /query 文本)
  ├── @  触发 → 读取 editor 文本 + 光标 → 复用现有 FileMentionPicker → 文件 chip(行为不变)
  ├── onInput → 同步纯文本镜像到 React state(value)+ 检测 @/ 触发
  └── Enter(无 Shift)→ 发送;Shift+Enter 换行

发送时序列化:
  prompt    = editor.getHTML/text 中 skill 节点 → /name,其余纯文本(按位置)
  displayText = 同上(给消息流渲染)
  skillsUsed = [从文档提取的 skill 节点 name 列表]  ← 新增,传给 store
```

## 改动清单(5 个文件 + 1 个新增)

### 1. 新增 `components/chat/ComposerEditor.tsx` — Tiptap 编辑器封装
封装成受控友好的组件,对外暴露:
- `value` / `onChange(text)` — 同步纯文本镜像(给 `value` state,供现有逻辑如空态判断、enqueue 重建用)
- `ref` API:`focus()`、`getEditor()`(供父组件插入 skill 节点、清空、读取序列化结果)
- 内含:`/` 的 Suggestion 插件(配置 `char: "/"`、`allowedPrefixes`),render 回调返回一个最小 controller `{ onStart, onUpdate, onExit, onKeyDown }`,把 `{ query, range, clientRect }` 透传给父组件传入的 `onSuggestion(query, open, close)` 回调——父组件据此开关 `SlashCommandPicker`。
- skill 胶囊渲染:用 `ReactNodeViewRenderer` 自定义 Mention 节点视图 = `IconSparkles` + `/name` + accent 样式,`contentEditable=false`(原子,退格整删)。
- 自动调高:Tiptap 本身不限制高度,外层 `<EditorContent>` 套 `max-h-72 overflow-y-auto`,监听 editor `update` 事件无需手动算 scrollHeight(contenteditable 内容自然撑高)。
- 粘贴:**所有**粘贴 `preventDefault`,只取 `text/plain` 插入(避免富 HTML);长/多行粘贴沿用 `shouldPromoteToTag` 转成 file/paste chip(由父组件 `onPaste` 拦截)。
- 禁用态:`editable={!textareaLocked}`。

### 2. `components/chat/ChatPane.tsx` — 接入新编辑器
- `<textarea>` → `<ComposerEditor>`。
- `textareaRef`(HTMLTextAreaElement)→ `editorRef`(自定义类型,暴露 focus/getEditor)。
- `recomputePicker` / `handleChange` / `clearTriggerToken`:从 `e.target.value` + `selectionStart` 改为从 Tiptap editor 读取 `editor.getText()` + 选区位置(Tiptap 的 `editor.state.selection.from` 直接给文档坐标,比裸 contenteditable 的 Range 换算简单得多——这正是用 Tiptap 的核心收益)。
- `handleSlashPick`:不再 `addSkillTag` + `clearTriggerToken`;改为调用 editor 的 `insertSkillNode(skill)`:由 Suggestion 给的 range 删掉 `/query`,插入 skill 节点 + 一个空格。
- **删除** skill 相关的 chip 逻辑(addSkillTag / appendUniqueSkillTag 在 composer 不再用;`tags` 数组只保留 file/paste)。
- `handleSend` / `handleEnqueue`:
  - 序列化改为遍历 editor 文档:文本段照常,skill 节点 → `/name`,拼接成 `prompt` 和 `displayText`(此时两者相同)。
  - `attachments` 只含 file/paste tag(不变)。
  - 新增提取 `skillsUsed: string[]`(skill name 列表),传给 `sendPrompt`。
- `@` mention 触发检测:复用 editor 的文本+光标,逻辑与原 `recomputePicker` 的 `@` 分支一致。

### 3. `stores/sessionStore.ts` — sendPrompt 携带 skill 信息
- `sendPrompt` / `editAndResendMessage` 签名新增可选参数 `skillsUsed?: string[]`。
- 构造用户消息的 `Block[]` 时:不再单独发 skill attachment 块(那是旧方案);改为把 skill 信息记入 text 块或一个轻量新字段。**最简方案**:给 text 块新增可选字段 `skillNames?: string[]`,记录这条消息内联了哪些 skill。消息渲染时据此把对应 `/name` 渲染成胶囊。
  - `Block` 的 `text` 分支:`{ kind: "text"; text: string; skillNames?: string[] }`。

### 4. `components/chat/Markdown.tsx` — 渲染内联 skill 胶囊
- 给 `<Markdown>` 增加可选 prop `skillNames?: string[]`。
- 在 Markdown 管线里加一个**预处理**:如果 `skillNames` 非空,把文本中的 `/skillname`(精确匹配列表里的名字)包裹成自定义标记(如占位 token),再用一个 `components` 自定义渲染器把它渲染成 `<span>` 胶囊(accent 色 + `IconSparkles`)。
  - 用 react-markdown 的 `components` 自定义渲染:文本节点里识别 `/name` 模式,拆分渲染(参考现有 `splitTextByPathTokens` 的 FileLink 处理模式)。
- `MessageBlocks.tsx` 的 text 分支调用 `<Markdown>` 时,把 `block.skillNames` 透传进去。

### 5. `components/chat/MessageBlocks.tsx` — 透传 skillNames
- `BlockView` 的 `case "text"`:`<Markdown projectPath={...} skillNames={block.skillNames}>`。
- 删除上一轮加的 skill attachment 分支(`AttachmentCard` 的 skill 分支)—— skill 不再以 attachment 卡片形式存在。

### 6. 清理上一轮的过渡代码
- `lib/contentTag.ts`:删除 `makeSkillTag` / `appendUniqueSkillTag`,`ContentTagKind` 回退为 `"paste" | "file"`(skill 不再走 tag 体系)。
- `components/chat/ContentTagChip.tsx`:删除 skill 分支。
- `components/chat/ChatPane.tsx`:删除上一轮加的 skill chip onToggle no-op、addSkillTag。

## UserMessageEditor(编辑已发消息)
本轮**不动**(保持纯 textarea 编辑 + 附件只读 chip)。编辑含 skill 的消息时,skill 信息会在 text 里以 `/name` 纯文本回填(`userMessageText` 已提取 text 块),重发后由 Markdown 的 skill 预处理再次渲染为胶囊。这意味着编辑态不显示胶囊样式,但语义不丢(重发仍带 /name)。完整编辑态胶囊留作后续迭代。

## 不改动的部分
- `SlashCommandPicker` / `FileMentionPicker`:接口 editor 无关(anchorRect + open + query + onPick),保持原样。键盘导航由它们自己的 capture-phase 全局监听处理。
- `composePromptWithTags`:只处理 file/paste(skill 已不在 tags 里)。
- 队列排空路径(`drainPromptQueueIfIdle`)自动透传。
