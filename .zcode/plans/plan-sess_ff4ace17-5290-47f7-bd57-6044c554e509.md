## 背景

当前从 `/` 菜单选中 skill 后，是**纯文本** `/skillName ` 插入 textarea:可以删半个字、与其它文本混在一起,发送后在消息流里也只是一段 Markdown 文本。用户希望:**选中 skill 后它是一个不可拆分的原子块**——在输入框里整体删除,在消息流里也作为独立块渲染。

## 设计思路:复用现有 ContentTag / attachment 块架构

代码库已有一套成熟的"原子块"机制 —— 文件(@引用)和粘贴内容已经实现了"composer 里是 chip、消息流里是卡片"的完整链路:

```
composer tag (ContentTag)  →  sendPrompt attachments  →  user message Block(kind:"attachment")  →  MessageBlocks 的 AttachmentCard
```

skill 沿用这条链路即可,只需新增一个 `kind`:`"skill"`。这样能最大程度复用既有逻辑(去重、组合 prompt、清空、重建等),改动集中在"注册一个新类型",而不是另起炉灶。

## 改动清单(5 个文件,全部在 renderer)

### 1. `lib/contentTag.ts` — 新增 skill tag 类型
- `ContentTagKind` 联合类型追加 `"skill"`(当前是 `"paste" | "file"`)
- 新增 `makeSkillTag(skill: SkillInfo): ContentTag` 工厂 —— `preview` 为 skill 名,`content` 为 `/name`(发给 SDK 的 skill 调用形式)。skill 不像 file/paste 需要大量上下文,因此**不参与** `composePromptWithTags` 的分隔块拼接,而是在该函数里特殊处理:skill tag 的 content 作为**裸行**直接插入(类似 file 的 `@path` 裸行),放在 typed text 之前,保证 SDK 在最前面看到 `/name` 指令。
- 新增 `appendUniqueSkillTag(prev, skill)` 去重(同名 skill 不重复添加)。

### 2. `components/chat/ChatPane.tsx` — 选中 skill 时创建 tag 而非插入文本
- 改 `handleSlashPick`(783 行):从"插入 `/name ` 到 textarea"改为"调用 `clearTriggerToken()` 删掉触发 token + `setTags` 添加 skill tag",镜像现有 `handleMentionPick` 的做法。
- 新增 `addSkillTag(skill)` 辅助(镜像 `addFileTags`)。
- `handleSend`(912)、`handleEnqueue`(950)、`handleEditSubmit`(987):tags 转 attachments 的逻辑已通过 `t.kind` 通用映射,无需改动 —— skill tag 会自动带上 `attachmentKind: "skill"`,沿用现有通路。

### 3. `components/chat/ContentTagChip.tsx` — skill chip 视觉
- 识别 `tag.kind === "skill"`:用 `IconSparkles` 图标(与 SkillsPanel 一致),preview 显示 `/skillName`。skill chip **不可展开预览**(它没有像 paste 那样的长内容),点击 body 无操作,只有 × 删除。

### 4. `components/chat/MessageBlocks.tsx` — 消息流里的 skill 卡片
- `AttachmentCard`(515 行)新增 `attachmentKind === "skill"` 分支:`IconSparkles` 图标 + `/name` 文本,不可展开(无内容可展开)。视觉与 composer chip 保持一致(accent 主题色),复用现有的 chip 样式。

### 5. `components/chat/TagPopover.tsx` — 跳过 skill
- skill tag 不触发 popover:在 ChatPane 的 chip 点击逻辑里,skill tag 的 `onToggle` 为 no-op 即可,不会调用 `setOpenTagId`,TagPopover 自然不出现。无需改 TagPopover 本身(它只为 paste/file 设计)。

### 类型联动(无需改 contracts / IPC)
- `Block` 的 `attachment` 分支(`sessionStore.ts:61`)`attachmentKind?: "paste" | "file"` → 追加 `| "skill"`。
- `PromptAttachment`(`sessionStore.ts:163`)同上。
- `sendPrompt` / `editAndResendMessage` 签名的 `attachmentKind` → 追加 `| "skill"`。
- 这些都只存在于 renderer,**不跨进程、不经 zod 校验**,无 IPC 合约风险。

## 不改动的部分(确认安全)
- `slashCommands.ts` 顶部注释说"插入 `/name ` 到 textarea"会过时,顺手更新为"创建 skill tag"。
- 队列排空路径(`drainPromptQueueIfIdle` → `sendPrompt`)原样透传 attachments,自动支持新类型。
- `composePromptWithTags` 是唯一需要改 prompt 组装逻辑的地方。

## 验证
- `npx tsc --noEmit -p tsconfig.json` 通过(类型联动完整)。
- 手动验证:`/` 选 skill → 出现 chip,点 × 整体删除,textarea 里无残留;发送后消息流里出现 skill 卡片(独立块),用户输入的文本作为另一个 text 块正常渲染。
