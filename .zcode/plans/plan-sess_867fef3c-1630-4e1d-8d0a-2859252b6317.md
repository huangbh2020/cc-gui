# 让聊天输出中的文件路径可点击打开

## 目标
模型在回复里提到的文件路径(绝对路径、项目相对路径、甚至不完整的文件名/部分路径)在聊天正文和工具卡片里都可点击,点击后在右侧 IDE 面板打开该文件。路径由模型生成、形态不确定,因此解析放在**点击时**(异步),而非渲染时。

## 解析策略(点击时)
新增 `apps/desktop/src/renderer/lib/fileLink.ts`,导出 `resolveFilePathToken(token, projectPath): Promise<string[]>`:

1. **绝对路径**(`token` 以 `/` 或盘符开头):若落在某个已知项目根内(`projects[].path` 前缀匹配),直接返回 `[token]`;否则不识别。
2. **项目相对路径**:用 `joinPath(projectPath, token)` 拼成绝对路径 → 调 `api.file.search({ projectPath, query: basename(token), limit: 50 })` 取候选,从中找 `relativePath` 等于 `token`(去 `./` 前缀)的项 → 返回该绝对路径。命中即返回单元素数组。
3. **不完整/部分路径**:调 `api.file.search({ projectPath, query: token, limit: 50 })`,对返回的 `FileSearchEntry[]` 客户端排序(精确 basename 优先 → 其次 basename 以 token 结尾 → 最后按 `relativePath` 长度升序),去重后返回(最多保留前 ~12 条)。

返回的每条候选都是**绝对路径**。调用方(链接组件)拿到候选后:
- 0 条 → 内联 toast/提示"未找到文件";
- 1 条 → 直接 `useSessionStore.getState().openFileInIde(abs)`;
- >1 条 → 弹出候选菜单让用户选,选中后 `openFileInIde`。

解析全程点击触发、异步、带 loading 态;不阻塞渲染,不影响流式性能(`useDeferredValue` 仍在外层生效)。

## 改动清单

### 1. 新增 `apps/desktop/src/renderer/lib/fileLink.ts`(解析逻辑 + 复用层)
- `PATH_TOKEN_RE`:识别路径式 token 的正则。匹配:`/abs/path.ext`、`./rel/path`、`rel/path.ext`、`path/to/File.tsx`、以及裸 `File.tsx`(至少含一个 `/` 或带扩展名的 `.xxx`)。边界设计上排除纯单词、URL(已有 `a` 渲染)、邮箱。带扩展名要求扩展名在常见白名单或长度 ≤ 8 字符,避免把"v1.2"误判成路径。
- `resolveFilePathToken(token, projectPath): Promise<string[]>`:上述三段式解析,纯函数 + 调 `api.file.search`。
- `splitTextByPathTokens(text): Array<{text} | {path}>`:把一段文本按 `PATH_TOKEN_RE` 切成片段,供 Markdown `text` 渲染器消费。

### 2. 修改 `apps/desktop/src/renderer/components/chat/Markdown.tsx`
- `Markdown` 组件签名新增**可选** prop `projectPath?: string | null`,向下传到 `components`。缺省时文件链接只尝试绝对路径解析(安全降级)。
- 在 `components` 里新增 `text({ children, ... })` 覆盖:对字符串子节点用 `splitTextByPathTokens` 切分,普通片段原样返回,路径片段渲染成 `<FileLink token={...} projectPath={projectPath} />`。非字符串 children 透传(react-markdown 的 text 节点恒为 string,但防御性处理)。
- **不改** `a` 覆盖:已是 `target="_blank"` 的外链,与文件链接区分。
- `components` 当前是模块级常量;为注入 `projectPath`,改为在组件内用 `useMemo(() => buildComponents(projectPath), [projectPath])` 构造(或用闭包)。注意保持 `pre` 内 shiki 高亮逻辑不变。

### 3. 新增 `apps/desktop/src/renderer/components/chat/FileLink.tsx`(可点击链接 + 候选菜单)
- props: `{ token: string; projectPath?: string | null }`。
- 渲染为内联 `<span>`(语义上更像文本里的高亮 token,而非导航链接),样式:`text-accent underline decoration-dotted hover:bg-surface-hover/60 cursor-pointer`,符合 AGENTS.md 的语义 token + `cn()` 规范。
- 点击(键盘 Enter/Space 同样支持,`role="button" tabIndex=0`)→ 进入 loading,调 `resolveFilePathToken`:
  - 1 候选 → `openFileInIde(abs)`(`useSessionStore.getState()`);
  - >1 候选 → 打开 base-ui `Menu` 候选列表(锚定到点击的 `<span>`,复用 `OpenTabsBar` 的 `MENU_POPUP_CLASS`/`MENU_ITEM_CLASS` 样式 + `Menu.Positioner` 自带翻转/键盘导航),每项 `FileTypeIcon`(来自 `@renderer/lib/fileIcon.js`)+ 相对路径,选中 `openFileInIde`;
  - 0 候选 → 短暂显示"未找到"(就地小气泡或 Menu 内一条禁用项"未找到匹配文件")。
- 锚定方式:用 `useRef` 拿到 span 元素,`Menu.Positioner` 的 `anchor` 传该 ref(base-ui 支持元素 ref 作为 anchor)。

### 4. 修改 `apps/desktop/src/renderer/components/chat/MessageBlocks.tsx`(工具卡片路径可点击)
- `EditToolCard`、`WriteToolCard` 头部的 `{filePath}` `<span>` 改为 `<FileLink token={filePath} projectPath={...} />`。工具卡片的 `file_path` 来自 SDK、是绝对路径,`FileLink` 的解析路径 1 会直接命中,不走 search。
- `GenericToolCard` 头部 `toolSummary(...)` 返回值:当 `toolName ∈ {Read, Write, Edit}` 且 `input.file_path` 为 string 时,同样包成 `<FileLink>`;其它工具(Bash/Grep/Glob 等)保持纯文本(它们的 summary 是 command/pattern,不是路径)。
- 给 `ToolCard`/`EditToolCard`/`WriteToolCard`/`GenericToolCard` 透传 `projectPath` prop(来源见第 5 步)。新增一个工具函数 `extractToolFilePath(toolName, input): string | null` 复用 `isEditInput`/`isWriteInput` + Read 的 `file_path` 判断。

### 5. 透传 `projectPath`(保持会话级正确性)
- `Markdown` 的 `projectPath` 必须是**会话所属项目**(非 `activeProjectId`),否则后台 tab 解析到错误项目根。因此:
  - `ChatPane.tsx` 已有会话级 `projectPath` 选择器(line 492)→ 经 `renderListItem` → `<MessageRow>` → `<MessageBlocks>` → `<BlockView>` → `<Markdown>` 逐层透传(新增 prop)。
  - `MessageBlocks`、`BlockView` 签名加 `projectPath?: string | null`,透传到 text 分支的 `<Markdown projectPath={projectPath}>` 和工具卡片的 `<FileLink>`。
- 非聊天调用方(`FileEditor` 的 md 预览、`PlanViewer`、`PlanStreamBlock`):这些是 active-project 作用域,直接按现有 `App.tsx:317` / `TerminalPanel.tsx:64` 的 `useMemo(projects.find(activeProjectId))` 模式就地解析后传给 `<Markdown projectPath={...}>`。`FileEditor` 已有 `filePath`,可用其项目根(`projectPath` prop)直接传。

### 6. (可选)hover 提示
`FileLink` 上加 `title="点击打开文件"` 帮助用户发现可点击性。

## 不做的事 / 边界
- **不新增 IPC 通道**:复用现有 `file.search`(已含项目根校验、路径穿越防护)。解析纯渲染端,不碰安全边界。
- **不在渲染时批量解析**:每个文本节点只在用户点击该 token 时触发一次 `file.search`,避免流式时几十个 token 同时打 IPC。
- **不解析目录**:`file.search` 不返回目录;若 token 解析为目录(无扩展名且 search 0 命中),点击仅提示未找到(后续可扩展为 `shell.showItemInFolder`)。
- **URL/外链不接管**:仍走 `a` 覆盖。
- **保持流式性能**:`text` 覆盖只是对已 markdown 化的字符串做正则切分,无 IPC、无异步;`useDeferredValue` 在 `BlockView` 外层依旧生效。
