# Git 拉取冲突 → AI 解决冲突 实施方案

## 概述

在 `git pull` 发生合并冲突时,自动弹出确认对话框,提示用户「检测到冲突,是否用 AI 解决?」。用户确认后,后端用 Claude Agent SDK(一次性 query 调用,与 `git.generateCommitMessage` 同一模式)读取冲突文件、解决冲突、写回文件并 `git add` 暂存。解决后**保留 merge 状态,预填一条 merge 提交信息,由用户手动提交**完成合并(最安全、控制力最强)。解决冲突的模型可在「设置 → Git」面板配置(独立于提交信息生成模型,未配置时回退到内置 Claude 模型)。

## 设计决策(采用与现有代码最一致的默认值)

- **提交行为**:AI 解决冲突 + `git add` 暂存,**保留 merge 状态**,在 GitRepoCard 提交框预填一条 merge 提交信息(如 `Merge branch 'x': conflicts auto-resolved by AI`),由用户检查后手动提交。不自动 commit。
- **模型回退**:未在设置选择时,用 SDK 内置模型(Claude),与「提交信息生成」一致。

**b) 新增 IPC schema**(放在 `GitGenerateCommitSchema` 之后,约 L630):

```ts
/** Input for git.resolveConflicts: resolve all unmerged files in a repo via AI.
 *  `customModelId` + `customModelRole` select the model; null = built-in. */

  repoPath: z.string(),
  customModelId: z.string().nullable(),
  customModelRole: z.string().nullable(),

```
**返回类型**:`{ ok: boolean; resolvedFiles?: string[]; error?: string }`(可选额外返回 `summary` 给前端做预填提交信息用)。

### 2. `apps/desktop/src/main/ipc/git.ts`(后端:冲突检测增强 + AI 解决 handler)

**a) 导入新 schema**:在顶部 import 块加 `GitResolveConflictsSchema`,类型加 `GitResolveConflictsInput`。

**b) 增强 `git:pull` handler**(L287-302):拉取后检测冲突状态。若 `git.status()` 中存在 `conflicted` 文件(simple-git 的 `StatusResult.conflicted` 数组),在返回值中带上 `conflict: true` + `conflictedFiles: string[]`。**需扩展 `GitOpResult` 或新增返回字段**——为最小侵入,在 `git:pull` 的返回里增加可选 `conflict?: boolean` 与 `conflictedFiles?: string[]`(直接在 handler 返回对象上扩展,不改 `GitOpResult` 类型,因为 RpcMap 里 `git.pull` 的返回类型是 `GitOpResult`,所以需要给 `GitOpResult` 增加可选字段 `conflict?` 和 `conflictedFiles?`)。

**c) 新增 `git:resolveConflicts` handler**(仿照 `git.generateCommitMessage`,L535 后):
1. 路径安全校验 `findContainingProject`;
2. `git.status()` 取 `conflicted` 文件列表;为空则返回 `{ ok:false, error:"未检测到冲突文件" }`;
3. 读取每个冲突文件的**完整内容**(含 `<<<<<<<`/`=======`/`>>>>>>>` 标记),逐个拼进 prompt;
4. 用与 commit-gen 相同的一次性 query 模式(`maxTurns:1`、`includePartialMessages:false`、`settingSources:["project","local"]`、`AbortController`+60s 超时)调用 SDK;
5. **系统提示**要求 AI 输出 JSON,形如 `[{ "path": "...", "content": "解决后的完整文件内容" }]`,确保能解析回写多个文件;
6. 解析 JSON → 逐个 `fs.writeFile` 写回 → `git.add(path)`;
7. 返回 `{ ok:true, resolvedFiles:[...] }`;
8. 错误映射同 commit-gen(401/503 等给出友好中文)。

**d) 新增常量** `CONFLICT_RESOLVE_SYSTEM_PROMPT`(放在 `COMMIT_GEN_SYSTEM_PROMPT` 附近,L545 后):固定指令——读取冲突标记、保留双方必要改动、输出干净文件、严格 JSON 输出。

## 风险与边界

- **大文件/多文件冲突**:prompt 可能很长。后端 handler 中对单文件大小设上限(如 100KB),超限的文件跳过并在返回值标注(避免 prompt 爆炸);AI 输出 JSON 解析失败时返回明确错误,不破坏工作区。
- **不自动 commit**:保留用户对 merge commit 的最终控制权,符合「安全边界」原则。
- **AI 可能解决不完美**:所以预填而非提交,用户可检查 diff 后再决定提交。
