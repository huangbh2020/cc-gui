# Pi 模型 API Key 在设置中直接维护(替代 $ENV_VAR)

## 一、目标

把之前的 `$ENV_VAR` 引用改为:**用户在 GUI 设置面板中填入明文 API Key,Mcode 加密存储,turn 时通过 Pi SDK 的 `AuthStorage.setRuntimeApiKey` 注入到当前 Node 进程**。用户不再需要手动 export 环境变量,也不需要在 models.json 里写 `$ENV` 引用。

## 二、核心机制

Pi SDK 提供 `AuthStorage.setRuntimeApiKey(provider, key)`(`auth-storage.d.ts:66`),CLI 的 `--api-key` flag 就是用这个 API。`createAgentSession` 接受 `authStorage` 选项(`sdk.d.ts:17`)。

**Mcode 集成路径**:
1. 用户在 PiModelsPanel 填明文 apiKey
2. Mcode 走 safeStorage 加密 → 存 settings 表 `piProviderKeys` (KeyMap: `{[name]: ciphertext}`)
3. turn 时 `PiAgentSdkProvider` 调 `resolveApiKey(providerName)` 取明文 → 调 `authStorage.setRuntimeApiKey(providerName, key)` → 传 `createAgentSession({authStorage})`
4. SDK 读 key 优先级第 1 步命中(覆盖 env fallback)→ 模型请求正常发出

**models.json 不再存 apiKey 字段**——只存 baseUrl / api / models 等元数据。merge 时如果旧条目有 apiKey 字段(以前手写或旧版 GUI 写入),保持不删除但不强制。

## 三、文件改动

### P1 契约层

**`packages/contracts/src/piModel.ts`**:
- `PiProviderConfig.apiKey` 改为可选 string(还是 models.json 字段名,只是"在我们的 UI 流程下不写入"——保留类型让 legacy 兼容)
- `validateApiKeyRef` 移除(不再需要)

**`packages/contracts/src/ipc.ts`**:
- `SavePiProviderSchema`:`config` 字段加一个独立的 `apiKey?: string`(顶层 schema,不入 config 子对象,走加密路径)
- `PiProviderPublic`:新增视图类型,带 `hasApiKey: boolean`(masked 不显示,只标记是否有 key),给 renderer
- 新增 RpcMap 签名 `"piModels.getApiKey": (input: { name: string }) => Promise<{ apiKey: string | null }>` — 编辑时**只在新输入非空时**才更新存储,空字符串=保留旧值。编辑模式 UI 需补回填显示。

### P2 主进程 store(新设计)

**`apps/desktop/src/main/lib/piModelsStore.ts`** 改造:
- 加密凭证映射 `piProviderKeys: Record<name, encryptedBase64>` 用 SettingRepo 存储(仿 `customModelKeys` 模式)
- 明文 models.json 写入不含 apiKey(merge 保留旧字段是 OK 的)
- 新增 API:
  - `listPublic()`:返回 `Record<name, PiProviderPublic>`(带 `hasApiKey` 标记)
  - `saveProvider(name, config, apiKey?)`:写入 models.json(merge);若 apiKey 非空则加密存;为空且 provider 已存在**保留旧 key**;为空且 provider 新建**抛错**(新建必填)
  - `deleteProvider(name)`:删 models.json 条目 + 删 key
  - `resolveApiKey(name)`:主进程专用,解密返回明文(给 PiAgentSdkProvider turn 时用)
- 复制 `secretStore.ts` 的 `encrypt`/`decrypt`/`maskToken` 工具(共用 safeStorage)

### P3 PiAgentSdkProvider 改造

**`apps/desktop/src/main/providers/pi-sdk/PiAgentSdkProvider.ts`** 的 `startTurn`:
```ts
// 1. 解析 provider name:从 req.model 或 req 中的某个字段取(待定,见下)
// 2. 取 key: const apiKey = PiModelsStore.resolveApiKey(providerName) ?? ""
// 3. 创建 in-memory authStorage,注入 key
const authStorage = sdk.AuthStorage.inMemory();
if (apiKey) authStorage.setRuntimeApiKey(providerName, apiKey);
// 4. 传给 createAgentSession
const { session } = await sdk.createAgentSession({ cwd, authStorage, ... });
```

**关键问题**:`providerName` 从哪取?
- `StartTurnRequest` 当前没有 providerName 字段
- 方案:从 `req.model`(如 "deepseek/deepseek-v4-pro")解析,取 `/` 前缀作为 providerName
- 或者在 `Session` 上新增 `piProviderName` 字段(类似 customModelId 的存法),新建 pi 会话时由前端选定

最简单:让前端在选择模型时,**用户为 pi 配置的每个 provider 在 ModelDropdown 标 provider 名,选中即把 providerName 写到 session 行**。但这要再加字段。**更简单**:解析 `req.model`(已经在那里)。如果 model 形如 `providerId/modelId` 自动用 providerId,否则报错提示用户先在设置中配。

我倾向**简化路径**——如果 `req.model` 没有 `/`,就**对所有已配 key 的 provider 全部注入**(`authStorage.setRuntimeApiKey(p, k)` 多次),Pi SDK 内部按需取。这避免了"必须先在 settings 选好模型"的前置约束,与 pi CLI 默认行为一致。

### P4 渲染面板

**`apps/desktop/src/renderer/components/settings/PiModelsPanel.tsx`**:
- `apiKey` 字段从"环境变量引用"改为"普通密码框",placeholder `"sk-..."` 
- 编辑模式:input 留空 = 保持现有 key(显示提示 "留空保持现有 Key")
- 创建模式:必填
- 列表显示 `已配置 Key` / `未配置 Key` 标记(从 `hasApiKey` 字段)
- 移除 `$ENV_VAR` 校验和提示文字
- 移除 `validateApiKeyRef` 引用

### P5 文档

**`docs/pi-sdk-integration.md` §4.4** 改写"API Key 在设置中维护"部分,说明:
- Key 走 safeStorage 加密存 settings 表
- turn 时通过 `AuthStorage.setRuntimeApiKey` 注入
- 不再需要 `$ENV_VAR` 引用
- models.json 不含 apiKey 字段
