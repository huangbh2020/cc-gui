## 目标

turn 进行中时,按现在的风格展示过程数据(流式文本 + 折叠的"思考 + N 个操作"卡片 + 实时操作 ticker);turn 完成后,过程数据收敛成一行紧凑摘要(如"✓ 完成 3 步操作"),点击仍可展开查看细节。最终回答的 Markdown 文本成为主角。瞬间切换,无动画。

## 改动范围

只改 2 个文件,改动很小:

### 1. `apps/desktop/src/renderer/components/chat/ChatPane.tsx`

**改动点:把 `turnMeta` 传给 `ProceduralGroup`**

在 `renderListItem` 的 proceduralCluster 分支(`:975-979`),把 `item.turnMeta` 传给 `ProceduralGroup`:

```tsx
<ProceduralGroup
  blocks={blocks}
  beforeMap={beforeMap}
  turnActive={item.isStreamingTail}
  turnMeta={item.turnMeta}          // ← 新增
/>
```

`item.turnMeta` 已经在 `groupMessagesForRender` 里计算好了(`ChatPane.tsx:247`),无需额外逻辑。

### 2. `apps/desktop/src/renderer/components/chat/MessageBlocks.tsx`

**改动点 A:`ProceduralGroup` 接收 `turnMeta`,推导 `completed` 信号**

- 新增可选 prop `turnMeta?: TurnMeta`(从 `@renderer/stores/sessionStore.js` 导入类型)
- 推导 `const completed = turnMeta?.endedAt !== undefined`(turn 已完成)
- 注意:`turnActive` 是"流式尾部",`completed` 是"turn 已结束"。一个 turn 中间的 proceduralCluster 既非 `turnActive` 也非 `completed`;流式尾部的 cluster 是 `turnActive && !completed`;完成后的尾部 cluster 是 `!turnActive && completed`。

**改动点 B:turn 完成后强制折叠**

用 `useEffect` 监听 `completed`,从 `false -> true` 时 `setOpen(false)`:

```tsx
useEffect(() => {
  if (completed) setOpen(false);
}, [completed]);
```

这样用户过程中即使手动展开了,turn 完成的瞬间也会自动收起。重新展开仍然可以(用户点击即可),不锁死。

**改动点 C:完成后改变摘要行样式**

当前摘要行(`:213-225`):
```tsx
<StatusIcon status={aggregateStatus} />     // error 才有图标,否则空
<IconActivity size={14} />                   // 活动图标
<span>{label}</span>                         // "思考 + 3 个操作"
{breakdown && <span>{breakdown}</span>}      // "Bash ×2 · Read ×1"
<CurrentOpTicker op={runningTool} turnActive={turnActive} />  // 实时操作
<Chevron open={open} />
```

完成后改为更收敛的样式:
- `StatusIcon`:`completed && aggregateStatus !== "error"` 时显示绿色 ✓ (`IconCheck`),代替空状态
- `label`:完成后改为"完成 N 步操作"(N = toolBlocks.length;纯思考则"思考完成")
- `breakdown`:完成后保留(让用户知道做了哪些操作),但用更淡的颜色
- `CurrentOpTicker`:完成后不渲染(`!turnActive` 时它本就清空,但显式 `!completed &&` 更清晰)

```tsx
{!completed && <CurrentOpTicker op={runningTool} turnActive={turnActive} />}
```

具体 label 逻辑:
```tsx
let label: string;
if (completed) {
  label = toolBlocks.length > 0 ? `完成 ${toolBlocks.length} 步操作` : "思考完成";
} else if (thinkingCount > 0 && toolBlocks.length > 0) {
  label = `思考 + ${toolBlocks.length} 个操作`;
} else if (toolBlocks.length > 0) {
  label = `${toolBlocks.length} 个操作`;
} else {
  label = "思考";
}
```

**改动点 D:导入 `useEffect` 和 `TurnMeta` 类型,`IconCheck` 图标**

- 文件顶部 React 导入加 `useEffect`(已有 `useState, useMemo, useDeferredValue`)
- 导入 `TurnMeta` 类型(from `@renderer/stores/sessionStore.js`)
- `IconCheck` 已在导入列表中(`:6` 行已有)

## 不改动的部分

- **text 块渲染**:不变,始终用 `<Markdown>` 渲染。过程中流式,完成后自然收敛(已有 `useDeferredValue` 限流)。
- **store / 数据层**:不改。`turnMeta.endedAt` 已经在 `turn.done` 时由 store 打上(`sessionStore.ts:3178`),信号已存在。
- **EditToolCard / WriteToolCard / GenericToolCard**:不改。它们在 `ProceduralGroup` 展开后的内部折叠态不变(仍默认折叠)。
- **单条消息路径**(`MessageBlocks` 组件里的 `ProceduralGroup`):这里不传 `turnMeta`,因为单条消息路径(非 cluster)没有 turnMeta 可用,保持现状即可。实际上这个路径在当前架构下几乎不会触发(cluster 合并已覆盖绝大多数 procedural 消息),即使触发,不传 `turnMeta` 就走原来的逻辑,不会出错。
- **groupBlocks / 分组逻辑**:不改。分组规则不变,只是完成后的视觉收敛。
- **`turn-files` 卡片 / `plan` 卡片**:不改。它们有自己的折叠逻辑,与 procedural 收敛无关。

## 边界情况处理

1. **没有 turnMeta 的 cluster**:`completed = false`,走原来的逻辑,不会强制折叠。(理论上少见,因为 procedural 消息通常是 turn 开头,会携带 turnMeta。)
2. **error 状态的 turn**:如果 turn 以 error 结束,`turnMeta.endedAt` 仍会被打上(`sessionStore.ts:3143-3148`),`completed = true`,但 `aggregateStatus` 可能是 "error",此时 `StatusIcon` 显示红 X 而非绿 ✓,让用户一眼看到出错了。
3. **用户完成后重新展开**:`useEffect` 只在 `completed` 变 true 的瞬间折叠一次,之后用户的点击操作正常生效。用户可以随时展开回看过程细节。
4. **虚拟列表回收重挂载**:`ProceduralGroup` 的 `useState(false)` 初始值仍然是 false(折叠)。重挂载后 `completed` 为 true,`useEffect` 会确保折叠态(虽然初始就是 false)。已展开的情况在回收时会丢失(虚拟列表的固有行为,可接受)。
