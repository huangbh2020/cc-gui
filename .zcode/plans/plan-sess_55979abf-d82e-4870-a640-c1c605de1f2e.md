## 问题根因

Skill 选中后发送，模型回复"当前环境中并没有这个"，**在所有情况下都会出现**（不仅是自定义模型场景）。

**根因（已通过 SDK 源码确认）**：`query()` 用 `--input-format stream-json` 启动内置 claude 二进制。在 stream-json 输入模式下，CLI 把 prompt 当作**已格式化的 API 消息**透传给模型（`sdk.mjs` 的 `dO()` 函数直接构造 `{type:"user", message:{role:"user", content:[{type:"text", text: r}]}}` 写入 stdin），**完全不解析斜杠命令**。因此 prompt 里的 `/gstack` 被模型当成普通字面文本，`Skill` 工具从不被触发，模型自然回复"没有这个"。

GUI 的设计假设（见 `ipc/skills.ts` 顶部注释与 `ClaudeAgentSdkProvider.ts:107-112`）是"SDK 会识别 `/name` 并运行 skill"，但这个假设只对**交互式 CLI**（`--input-format text`）成立，对 stream-json 输入不成立。

> 次要问题：自定义模型场景下 `settingSources = ["project","local"]` 排除了 `"user"`，可能进一步隐藏 `~/.claude/skills/` 全局 skill。但主因是上面这条，所以全场景都会复现。

## 修复方向：显式传递 skill 名单

GUI 已精确知道用户选中了哪些 skill（`skillNames`），只在 IPC 边界丢弃了。修复方法是把它贯穿 4 层，最终在 provider 里用 SDK 官方的 `Options.skills: string[]` 白名单把选中 skill 注入模型上下文。这样模型能通过其 `Skill` 工具真正调用到选中的 skill，不再依赖 `/name` 文本被 CLI 解析。

### 修改清单（7 个文件，全部小改）

**1. `packages/contracts/src/provider.ts`** — `StartTurnRequest` 加可选字段
```ts
/** 用户在输入框选中插入的 skill 名单（不含 "/"）。空/缺省 = 不启用 skill 白名单。 */
skills?: string[];
```

**2. `packages/contracts/src/ipc.ts`** — `SendTurnSchema` 加可选字段
```ts
skills: z.array(z.string()).optional(),
```
`SendTurnInput` 由 `z.infer` 自动带上。

**3. `apps/desktop/src/main/ipc/claude.ts`** — `sendTurn` handler 透传字段（line ~107）
```ts
await runtimeManager.sendTurn(updated, {
  prompt: input.prompt,
  cwd: project.path,
  skills: input.skills,
});
```

**4. `apps/desktop/src/main/claude/RuntimeManager.ts`**
- `sendTurn` 签名 `input` 类型加 `skills?: string[]`（line 138）
- 构造 `StartTurnRequest` 时带上 `skills: input.skills`（line 217-226 的 req 对象）

**5. `apps/desktop/src/main/providers/claude-sdk/ClaudeAgentSdkProvider.ts`** — 核心（line 94-120 的 options）
当 `req.skills` 非空时，用精确白名单替代 `"all"`：
```ts
skills: req.skills && req.skills.length > 0 ? req.skills : "all",
```
> 注：SDK 的 `skills: string[]` 是**上下文过滤器**（sdk.d.ts:1903-1905 明确：未列出的 skill 对模型隐藏但文件仍在磁盘上）。精确传选中名单既保证这些 skill 可见，又不影响其它 turn。保留 `"all"` 作为兜底（用户没插 skill pill 时仍让模型自主发现/调用 skill）。

**6. `apps/desktop/src/renderer/stores/sessionStore.ts`** — 两条发送路径透传
- `sendPrompt`（line 2986）：签名第 4 参 `skillsUsed` 已存在，只需在 `api.claude.sendTurn({...})` 里加 `skills: skillsUsed && skillsUsed.length > 0 ? skillsUsed : undefined`
- `editAndResendMessage`（line 3089）：同样把第 6 参 `skillsUsed` 加进 sendTurn 调用

**7. 验证 + 不破坏现有约定**
- prompt 里仍保留 `/name` 文本（**不删**）：skill pill 的渲染依赖它，且对未来若改用交互式输入无害。`skillNames` 字段是"带外"权威通道，`/name` 文本退化为纯展示。
- 兜底逻辑：`skillsUsed` 为空数组/undefined 时不传字段，provider 保持 `skills: "all"` —— 行为与现状一致，零回归风险。

### 不做的事
- **不改 `settingSources` 排除 "user" 的逻辑**：那是为了防 cc-switch 覆盖 env（ClaudeAgentSdkProvider.ts:166-193 有详尽注释），与本 bug 主因无关。改它会引入回归。若后续验证全局 skill 在自定义模型场景仍不可见，再单独处理。
- **不调用 `Query.supportedCommands()`**：`ipc/skills.ts` 注释已说明它需要运行中的 query 句柄，而本项目每 turn 重开 query，无法跨 turn 调用。磁盘扫描策略保留。

### 验证步骤
1. `cd apps/desktop && npx tsc --noEmit -p tsconfig.json` 类型检查
2. 启动 dev，在输入框 `/` 选一个全局 skill（如 chrome-cdp），发送"解释下这个 skill 干啥"，确认模型能识别并运行该 skill（不再回"当前环境中并没有这个"）
3. 测一个不带 skill pill 的普通 turn，确认无回归（`skills: "all"` 兜底生效）
4. 测 editAndResend 路径（编辑带 skill pill 的历史消息重发）
