# 中间面板 Tab 体验优化实施计划

## 目标
解决 SessionTabs 当前三大痛点：① tab 过多被遮挡找不到；② 无法拖动重排；③ 缺少快速跳转入口。同时做一致性打磨。

覆盖方案 A（滚动+导航+自动定位）+ B（拖拽）+ C（溢出菜单）+ D（细节），滚动条采用"隐藏原生+左右箭头按钮"。

## 现状关键结论（已验证）
- `SessionTabs.tsx`（110 行）纯手写，无 DnD，`<Tab>` 容器缺 `shrink-0`（第 64 行）。
- `sessionStore.ts` 中 `openTabs` 为纯内存态，不持久化；无 `reorderTab` action。
- `syncConfigFromSession`（:621-641）只读 session 行 config 字段，与 openTabs 顺序完全解耦——reorderTab 零副作用。
- 项目已装 `@base-ui/react`，提供 `Menu` 原语（`@base-ui/react/menu`），参考 `PermissionModeDropdown.tsx` 写法。无需引新库做菜单。
- React 19；拖拽需新增 `@dnd-kit/core` + `@dnd-kit/sortable`（React 19 兼容）。

## 实施步骤

### Step 1：store 新增 `reorderTab` action（方案 B 基础）
文件：`apps/desktop/src/renderer/stores/sessionStore.ts`
- 接口声明：在 `closeTab`（:351）后加 `reorderTab: (from: number, to: number) => void;`
- 实现：在 `closeTab` 实现（:1767）后、`deleteProject`（:1771）前插入：
  ```ts
  reorderTab: (from, to) => set((s) => {
    if (from === to || from < 0 || from >= s.openTabs.length || to < 0 || to >= s.openTabs.length) return {};
    const next = [...s.openTabs];
    const [moved] = next.splice(from, 1);
    next.splice(to, 0, moved);
    return { openTabs: next };
  }),
  ```
- 纯顺序调整，不动 activeSessionId、不调 syncConfigFromSession、不持久化（与现状一致）。

### Step 2：新增依赖 @dnd-kit（方案 B）
- `cd apps/desktop && pnpm add @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities`
- 验证 React 19 兼容性（这两个库均支持 React 18+，与 19 兼容）。

### Step 3：改造 SessionTabs 组件（核心，A+B+C+D 全在此）
文件：`apps/desktop/src/renderer/components/layout/SessionTabs.tsx`（重写）

**结构变化**（当前只有一层 `overflow-x-auto` div + `<Tab>` 列表 → 改为）：
```
<div 外层 flex 容器>
  <左箭头按钮 IconChevronLeft>      ← 仅可左滚时显示
  <div ref=scrollRef 隐藏滚动条的横向滚动容器>
     <DndContext>                    ← @dnd-kit 上下文
       <SortableContext items=tabIds>
         {tabs.map → <SortableTab>}   ← 每个可拖拽 tab
       </SortableContext>
     </DndContext>
  </div>
  <右箭头按钮 IconChevronRight>     ← 仅可右滚时显示
  <OverflowMenu 触发按钮 IconDots>   ← 方案 C，仅 tab 数 > 可见数时显示
  <右边缘 fade 蒙层>                 ← 方案 D
</div>
```

**方案 A 要点**：
1. 滚动容器 className 去掉 `overflow-x-auto`，改为 `overflow-x-auto` + 新增工具类 `no-scrollbar`（在 `styles.css` 加 `::-webkit-scrollbar{display:none} scrollbar-width:none`，只作用于带该 class 的元素，不污染全局）。
2. 滚动容器 `useRef<HTMLDivElement>`，监听 `onScroll` 计算 `canScrollLeft`/`canScrollRight` 两个 boolean state（`scrollLeft>0` / `scrollLeft < scrollWidth-clientWidth`）。
3. 左右箭头按钮根据 `canScrollLeft`/`canScrollRight` 显示（不可滚方向隐藏而非置灰，保持简洁），点击 `scrollBy({ left: ±clientWidth*0.8, behavior: "smooth" })`。
4. `onWheel`：`e.preventDefault(); scrollRef.current.scrollLeft += e.deltaY;`（鼠标竖向滚轮转横向）。
5. 激活 tab 自动定位：`useEffect` 监听 `activeId`，给当前激活 tab 元素加 ref（用 ref map 或 `data-active` 选择器），`scrollIntoView({ inline: "nearest", behavior: "smooth" })`。

**方案 B 要点**（@dnd-kit sortable）：
1. `DndContext` 包裹，`onDragEnd` 里 `arrayMove(oldIndex, newIndex)` 后调 `reorderTab(oldIndex, newIndex)`。
2. `SortableContext` 用 `horizontalListSortingStrategy`。
3. `<SortableTab>` 用 `useSortable({ id })`，给容器加 `setNodeRef`/`style`（含 transform/transition）+ `attributes`/`listeners`。
4. `listeners` 挂在 tab body 上，但**排除关闭按钮区域**（关闭按钮不响应拖拽，避免误触）——用 stopPropagation。
5. 拖拽中视觉反馈：被拖 tab 加 `opacity-50`/`shadow-lg`，用 `isDragging` 判断。
6. 注意：`@dnd-kit` 的 pointer sensor 默认有 `activationConstraint: { distance: 6 }`，避免与点击切换冲突（小于阈值视为点击）。

**方案 C 要点**（溢出菜单）：
1. 触发按钮 `IconDotsVertical`，用 `@base-ui/react/menu` 的 `Menu.Root`/`Menu.Trigger`/`Menu.Portal`/`Menu.Positioner`(side="top" align="end")/`Menu.Popup`/`Menu.Item`。
2. 菜单项渲染所有 tab：左侧运行指示点（复用现有圆点逻辑）+ 标题，点击调 `selectSession(id)` 并 `scrollIntoView`。
3. tab 数量 ≤ 一定阈值（如不溢出时）隐藏触发按钮——用 `scrollWidth <= clientWidth` 判断 `overflowing` state。
4. （可选）菜单内顶部加搜索框过滤，tab 特别多时快速定位。初版可不加。

**方案 D 要点**：
1. 关闭按钮 `×` 字符 → `IconX`（size 12），与 `OpenTabsBar`、AGENTS.md 图标规范一致。
2. 两侧 fade 蒙层：滚动容器左右各一个 `pointer-events-none` 绝对定位 div，`bg-gradient-to-r from-surface to-transparent`（左）/ 反向（右），根据 `canScrollLeft`/`canScrollRight` 显示。
3. 中键关闭：`<Tab>` 的 `onMouseDown` 判断 `e.button === 1` → `e.preventDefault(); closeTab(id)`。

## 不做的事
- 不持久化 tab 顺序（openTabs 当前纯内存态，保持一致；持久化是独立需求）。
- 不改动 selectSession/openTab/closeTab 现有逻辑。
- 不动 ChatPane、LegendList（拖拽仅限 SessionTabs）。
- 全局滚动条样式不改（仅对 tab 容器加 `no-scrollbar` 工具类）。

## 风险
- @dnd-kit 与 React 19 严格模式双调用的潜在告警：已知的兼容性良好，若 typecheck/运行有问题则回退用原生 HTML5 drag API（draggable + dragstart/dragover/drop）自研，store 的 reorderTab action 不变。
- 横向滚动 + drag 的交互可能冲突：用 @dnd-kit 的 `distance` activation constraint 区分滚动（touch/trackpad）与拖拽。
