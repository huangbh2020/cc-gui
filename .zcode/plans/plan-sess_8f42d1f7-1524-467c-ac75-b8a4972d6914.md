## 优化操作集合卡片：去掉中间层，扁平化渲染

### 问题
一个回合的工具操作要穿过三层折叠（TurnPanel → ProceduralRunCard → 单个工具卡）才能看到细节，而中间层 `ProceduralRunCard` 折叠时只显示一个计数（`Bash ×2 · Read ×1`），信息增量低、点击成本高，还把 thinking 和动作混算成一组。同时头部全灰小字、历史态只剩计数，视觉"太泥"。

### 目标结构（两层，去掉中间层）
```
TurnPanel  [14:02:11 · 8.3s  ⟳Bash npm test  ›]   ← ticker 上移到回合头部
  ├─ 💡 Thinking · 我先看一下这个文件…      ← 平级折叠项
  ├─ 📄 Read  src/foo.ts                    ← 平级折叠项
  ├─ $  Bash  npm test                      ← 平级折叠项
  └─ ✓ Bash  npm run build
```

### 改动范围
**仅一个文件**：`apps/desktop/src/renderer/components/chat/MessageBlocks.tsx`
（`ChatPane.tsx` 的 TurnPanel props 签名不变；`CurrentOpTicker.tsx` 接口不变，均无需改动）

### 具体步骤

**1. 删除 `ProceduralRunCard`（约 193-271 行）**
- 无外部引用（未 export），安全删除。
- 仅 `runningTool` 的 useMemo 逻辑需要迁移（见步骤 3），其余（`aggregateStatus`/`label`/`breakdown`）随删。

**2. 删除 `PanelBody`（约 283-323 行），逻辑内联进 TurnPanel**
- PanelBody 原本做 `groupBlocks` → procedural 段喂 ProceduralRunCard、single 段喂 BlockView。
- 去掉中间层后，TurnPanel body 直接遍历 `blocks` 逐个 `<BlockView>` 渲染：
  ```tsx
  {open && (
    <div className="space-y-1.5 py-2">
      {blocks.map((b, i) => (
        <BlockView key={i} block={b} beforeMap={beforeMap}
          onOpenPlan={onOpenPlan} projectPath={projectPath} />
      ))}
    </div>
  )}
  ```
- thinking → `Collapsible`，tool_use → `ToolCard`（含 Edit/Write 专用卡），穿插 text → `Markdown`，均走 BlockView 现有分支，行为一致。

**3. ticker 上移到 TurnPanel header**
- 复用 TurnPanel 第 381 行已存在但当前未使用的 `toolBlocks`（死代码激活）。
- 把 `runningTool` 的反向扫描逻辑从 ProceduralRunCard 搬进 TurnPanel。
- 在 header button 内、duration 之后、chevron 之前，插入 `<CurrentOpTicker op={runningTool} turnActive={turnActive} />`（chevron 保留 `ml-auto` 靠右）。
- 更新第 405-409 行过时注释（ticker 不再"live on each ProceduralRunCard's header"）。

**4. header 文案精简（回应"视觉太泥"）**
- 当前：`开始 14:02:11 · 用时 8.3s` → 改为 `14:02:11 · 8.3s`
- 去掉"开始""用时"两个 label，靠 tabular-nums + `·` 分隔已足够直观，减少灰色小字噪音。

**5. 保留 `groupBlocks`（约 131-156 行）**
- MessageBlocks 第 82 行的 defensive 路径（legacy/orphan 无 turnMeta 数据）仍需要它把碎片 procedural blocks 合并塞进一个 TurnPanel。
- TurnPanel 不再调用它，但函数保留，docstring 更新说明"仅供 defensive 兜底"。

**6. typecheck 验证**
- `cd apps/desktop && npx tsc --noEmit -p tsconfig.json`

### 不改的部分
- `ChatPane.tsx`（TurnPanel 挂载方式、props、`isProceduralBlock` 边界判定均不变）
- `CurrentOpTicker.tsx`（`op` + `turnActive` 接口不变）
- `BlockView` / `Collapsible` / `ToolCard` 等子组件（扁平化后直接复用）
- Edit/Write 的 `isInlineFileBlock` 逻辑随 groupBlocks 保留在 defensive 路径；正常路径下它们作为 tool_use 直接走 ToolCard，渲染与现状一致

### 预期效果
- 看某个工具结果：从 3 次点击（TurnPanel→ProceduralRunCard→工具卡）降到 2 次（TurnPanel→工具卡）。
- thinking 不再被算进"操作计数"，作为独立折叠项与工具卡平级，想看思考/想看动作各自独立。
- 回合头部一行承载时间+时长+当前操作 ticker，去掉中间层冗余计数行，视觉更干净。
