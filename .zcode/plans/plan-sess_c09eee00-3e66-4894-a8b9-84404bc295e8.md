## 目标

把同一轮对话（turn）内连续的「思考 + N 个操作」过程性消息，在渲染层合并成**单个紧凑卡片**，消除多个卡片纵向堆叠造成的冗余空间占用。

## 根因（已确认）

- `SdkMessageAdapter.ts:506` 每个 `content_block_start` 生成新 `messageId`
- `sessionStore.ts:1357-1383` 中 `tool.use` 落到"最后一条 assistant 消息"，而 `thinking`/`text.delta` 按 messageId 路由 → 同一 turn 通常被拆成多条「纯过程性」（只含 thinking+tool、无 text）的 assistant 消息
- `ChatPane.tsx:399` 的 `messages.map(m => <MessageRow>)` 逐条渲染 → 每条经 `MessageBlocks` → `groupBlocks` → 各成一个 `ProceduralGroup` 卡片（`MessageBlocks.tsx:102`）
- 结果：一个 N 步 turn 产生 N 个独立卡片堆叠

## 改动范围（最小，仅渲染层）

只动两个文件，数据层（`Block` / `ChatMessage` / 持久化 / `sessionStore` ingest 逻辑）**完全不改**。

### 1. `apps/desktop/src/renderer/components/chat/MessageBlocks.tsx`

**导出一个新的纯展示组件** `ProceduralGroupCluster`（或导出现有 `ProceduralGroup` 并扩展其接收多消息能力）。该组件接收**一组**纯过程性 block 数组（来自多条被合并的消息），渲染为**一个**合并卡片：

- **折叠态标题**（复用现有 `ProceduralGroup` 逻辑）：
  - 聚合状态图标：任一 running → running；否则任一 error → error；否则 done
  - 标签：`思考 + N 个操作`（N = 该组所有消息的 tool_use 总数）
  - breakdown：`Grep ×2 · Read ×2 · Edit ×1`（所有消息的工具名汇总）
  - chevron 箭头
- **展开态**：把该组所有消息的 block 按**消息间顺序拼接后平铺**渲染，每个 thinking → `Collapsible`、每个 tool_use → `ToolCard`（全部默认折叠，用户逐个点开深入）。即把多条消息的 blocks 逻辑上 concat 成一条 stream，复用现有 `BlockView` 渲染。

  → 直接复用现有 `groupBlocks` 的"连续 thinking+tool 合并"语义：因为被合并的各条消息都是纯过程性的，拼接后整体仍是连续的 thinking+tool 序列，可直接当作一个超大 `procedural` segment 渲染。

**关键实现**：把 `ProceduralGroup` 组件从"接收 `blocks: ProceduralBlock[]`"重构为可直接消费合并后的 block 列表。它原本的 `groupBlocks` 输出 `{kind:"procedural", blocks}` 里的 `blocks` 就是平铺的 procedural block 数组——我们只要让聚合层把多条消息的 procedural blocks 拼成同一个数组传入即可，`ProceduralGroup` 内部逻辑（标签计算、breakdown、展开渲染）**无需改动**，天然支持。

### 2. `apps/desktop/src/renderer/components/chat/ChatPane.tsx`

在 `messages.map(...)` 渲染循环**之前**，对 `messages` 做一次**纯渲染分组**（`useMemo`，不改 store）：

```
type RenderItem =
  | { kind: "single"; msg: ChatMessage }          // 用户消息 / 含 text 的 assistant 消息
  | { kind: "proceduralCluster"; msgs: ChatMessage[]; turnMeta?: TurnMeta };
```

分组规则（线性扫描 `messages`）：
1. 维护一个 `run: ChatMessage[]` 缓冲区
2. 遇到**纯过程性 assistant 消息**（`role === "assistant"` 且 `blocks` 全部是 `thinking` 或 `tool_use`，无 `text`/`error`）→ push 进 `run`
3. 遇到其他消息（用户消息 / 含 text 的 assistant 消息 / error 消息）→ flush `run`（若非空，作为一个 `proceduralCluster` 项，`turnMeta` 取 run 中**第一条**带 `turnMeta` 的消息的 turnMeta），再把当前消息作为 `single` 项推入
4. 末尾 flush `run`

渲染：
- `single` → 现有 `<MessageRow>`（不变）
- `proceduralCluster` → 新的轻量包装：渲染 `turnMeta`（若有）的 `<TurnStatRow>` + 一个合并后的 `<MessageBlocks blocks={concatAllProceduralBlocks(msgs)} />`

  实际上更简洁：cluster 项直接渲染 `<TurnStatRow>` + `<ProceduralGroup blocks={flattened} />`（导出 `ProceduralGroup` 或新增一个接收 `msgs` 的薄封装）。

**注意点**：
- `isStreamingTail` / `isLastCompletedAssistant` 判定要相应迁移到新的渲染项维度（cluster 项的"是否最后一条"看它是否代表 messages 末尾）。`isStreamingTail` 的 loader 仍要在 cluster 末尾显示（当 turn 正在运行且 cluster 是最后一项时）。
- `MessageTimeline`（`MessageTimeline.tsx:62`）只过滤 `role === "user"` 消息做时间线高亮，纯过程性 assistant 消息不在其中 → **不受影响**，无需改动。
- `blocksToText`（复制按钮）只针对含 text 的消息，纯过程性消息本就无复制按钮 → 合并不影响复制功能。
