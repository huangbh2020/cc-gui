## 目标

让集成终端支持**复制选中内容**（用户的核心诉求）和**粘贴**（顺带补齐，对用户更友好）。交互方式对齐 VS Code / Windows Terminal / iTerm2 的事实标准。

## 三处改动（全在 `apps/desktop/src/renderer/components/ide/TerminalView.tsx`）

### 1. 右键菜单（主交互入口）
用项目已有的 base-ui `ContextMenu`（`FileTree.tsx` / `GitRepoCard.tsx` 的同款范式）包裹 xterm 的 host div：

- `ContextMenu.Trigger render={<div ref={hostRef} .../>}` —— xterm 仍 `term.open(hostRef.current)`，base-ui 只注入 contextmenu 事件处理器，不破坏 DOM 结构
- 菜单项：
  - **复制**（`IconCopy`）—— 无选中时禁用（灰显）。复用 xterm `term.getSelection()`
  - **粘贴**（`IconClipboard`）—— 从 `navigator.clipboard.readText()` 读，走 `api.terminal.write` 写进 PTY，行尾归一化复用 `TerminalPanel.runCommand` 同款的 `replace(/\r\n|\n|\r/g, "\r")`
- 样式 class 直接抄 `FileTree` 的 `MENU_POPUP_CLASS` / `MENU_ITEM_CLASS`，视觉一致

### 2. 快捷键（快速通道）
`term.attachCustomKeyEventHandler(handler)` 注册：
- **复制**：macOS `Cmd+C`（有选中时复制；无选中时让 xterm 默认处理，避免吃掉 shell 的输入）、Win/Linux `Ctrl+Shift+C`
- **粘贴**：`Cmd+V`（macOS）/ `Ctrl+Shift+V`（Win/Linux）
- 关键：`Ctrl+C` / `Ctrl+D` 等绝不拦截，留给 shell 发 SIGINT / EOF
- handler 返回 `false` 表示"我处理了，别传给 xterm"，`true` 表示放行

### 3. 选中状态追踪
`term.onSelectionChange(() => setHasSelection(term.hasSelection()))` 维护一个 `hasSelection` state，驱动右键菜单「复制」项的 disabled 状态。

## 粘贴的剪贴板读取策略（关键技术点）

renderer 的 `navigator.clipboard.readText()` 在 Electron contextIsolation 下**通常可用**（Electron 把 renderer 视为 trusted，不弹权限）。项目里 `writeText` 已大量使用且带 try/catch fallback，`readText` 用同样模式：

```ts
const text = await navigator.clipboard.readText();  // try
// catch → 静默 no-op（与项目其他 clipboard 用法一致）
```

**不新增 IPC 通道**。理由：① 减少改动面（加 IPC 要动 contracts/ipc.ts + preload + main handler 三处）；② Electron renderer 环境下 `navigator.clipboard.readText` 大概率可用；③ 如果实测不行，后续再加 `clipboard:readText` IPC 作为 fallback，届时范围清晰。复制（`writeText`）则已被项目充分验证可用，零风险。

## 不做的事

- **不加工具栏复制按钮** —— 用户得先鼠标选中文本再去点工具栏，不如右键/快捷键；且要把选中状态从子组件提到父组件，增加耦合，收益低
- **不碰 `TerminalPanel.tsx`** —— 所有逻辑自洽在 `TerminalView` 内（它已有 api 访问 + terminalIdRef + writingRef），父组件零改动
- **不加 IPC** —— 见上
