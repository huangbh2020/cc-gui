## 功能优化：更新下载进度显示与状态持久化

### 问题分析
当前"关于"面板的更新流程有两个体验缺陷：
1. **无下载进度**：主进程已监听 `download-progress` 事件（`updater.ts:89`），但只打日志，没推给前端；UI 只显示静态转圈"正在下载更新…"，没有百分比/字节数。
2. **状态不持久化**：`updateState` 是 `AboutPanel.tsx` 组件内的 `useState`（第 63 行），纯内存。重新打开设置页（组件卸载重挂载）或重启应用后状态丢失，`update-downloaded` 是一次性事件不会重发 → 用户会被迫再次"检查更新"，体验割裂。

### 实现方案

复用现有的 settings 表 + `SettingRepo` + `setting.get/set` RPC 持久化机制（项目已有完整脚手架），新增一个 `update:downloadProgress` 推送通道传递实时进度。

#### 第 1 步：IPC 契约（`packages/contracts/src/ipc.ts`）

1. 在文件顶部 setting key 区域（约第 25 行 `THEME_SETTING_KEY` 附近）新增：
   ```ts
   export const UPDATE_STATE_SETTING_KEY = "update.state";
   ```
   并定义持久化的状态类型 `PersistedUpdateState`（status: `"downloading"` | `"downloaded"`，带 percent/transferred/total/version/updatedAt）。

2. 新增推送消息类型 `UpdateDownloadProgressMessage`（channel: `"update:downloadProgress"`，含 version/percent/transferred/total/bytesPerSecond），加进 `MainToRendererMessage` 联合（第 917-923 行）。

3. 在 `IPC` 常量对象（第 1200 行 `UPDATE_DOWNLOADED` 后）新增：
   ```ts
   UPDATE_DOWNLOAD_PROGRESS: "update:downloadProgress",
   ```

#### 第 2 步：主进程 `updater.ts`（核心改造）

1. import `SettingRepo`（`@main/store/repositories.js`）。
2. 新增模块级变量 `downloadingVersion: string | null`，记录正在下载的版本，供 `download-progress` 回调使用。
3. `update-available` 回调：持久化 `{ status: "available", version }` 到 settings（可选，主要持久化 downloading/downloaded 两个关键态）。
4. `download-progress` 回调：改为 `sendToRenderer(IPC.UPDATE_DOWNLOAD_PROGRESS, {...})` 推送进度给前端，同时持久化 `{ status: "downloading", percent, transferred, total, version, updatedAt }`。
5. `update-downloaded` 回调：持久化 `{ status: "downloaded", version, updatedAt }`。
6. `error` 回调：清除持久化状态（写空或删除标记），避免卡在下载中。
7. 新增 `getPersistedUpdateState()` 导出函数，供 IPC handler 读取持久化状态返回给前端。
8. 新增 `clearPersistedUpdateState()` 导出函数，在"已下载并安装"或出错后清除。

#### 第 3 步：IPC handler（`apps/desktop/src/main/ipc/updater.ts`）

- 新增 `APP_GET_UPDATE_STATE`（或复用 `app.info`，但语义不同，建议新增 RPC）handler，调用 `getPersistedUpdateState()` 返回持久化状态。
- 在 `app.quitAndInstall` handler 前调用 `clearPersistedUpdateState()`（安装后状态清零）。

> 实际上更简洁的做法：复用通用 `setting.get(UPDATE_STATE_SETTING_KEY)` 在前端直接读，无需新增 RPC。**采用此方案**——前端通过 `api.setting.get` 读取持久化状态，避免新增 RPC 通道。

#### 第 4 步：preload 桥接（`apps/desktop/src/preload/index.ts`）

在 `api.on` 中新增 `updateDownloadProgress` 订阅（参照 `updateAvailable` 第 233 行的写法），监听 `IPC.UPDATE_DOWNLOAD_PROGRESS`。

#### 第 5 步：前端 `AboutPanel.tsx`（UI 改造）

1. **扩展 `UpdateState` 类型**：`downloading` 态增加 `percent`/`transferred`/`total` 字段。
2. **挂载时还原状态**：新增 `useEffect`，调 `api.setting.get({ key: UPDATE_STATE_SETTING_KEY })` 读取持久化状态并还原 `updateState`：
   - `status === "downloading"` → `{ kind: "downloading", percent, ... }`（同时主进程仍在下载，progress 事件会持续刷新）
   - `status === "downloaded"` → `{ kind: "downloaded", version }`
   - 否则 → `{ kind: "idle" }`
3. **订阅进度推送**：在现有的 `useEffect`（第 82 行）中新增 `api.on.updateDownloadProgress` 订阅，收到时 `setUpdateState({ kind: "downloading", percent, transferred, total })`。
4. **下载完成持久化**：`updateDownloaded` 回调里调 `api.setting.set` 写入 `{ status: "downloaded", version }`（与主进程双写，保证前端关闭再开也能还原；主进程侧已写，但前端写更直接）。
5. **`UpdateBanner` UI**：`downloading` 态渲染进度条（百分比 + transferred/total 可读字节），不再只是静态转圈。

#### 第 6 步：进度条 UI 组件

在 `UpdateBanner` 的 `downloading` case 中，渲染一个细进度条 + 百分比文字（如 `正在下载更新… 45% · 12.3 / 27.5 MB`），用语义 token（`bg-accent`/`bg-surface`/`border-edge`）。字节格式化用一个小工具函数（`formatBytes`）。

### 涉及文件清单
| 文件 | 改动 |
|------|------|
| `packages/contracts/src/ipc.ts` | 新增 setting key、Progress 消息类型、IPC 通道常量、`MainToRendererMessage` 联合 |
| `apps/desktop/src/main/updater.ts` | 持久化状态 + 推送进度 + 导出读/清函数 |
| `apps/desktop/src/preload/index.ts` | 新增 `on.updateDownloadProgress` 订阅 |
| `apps/desktop/src/renderer/components/settings/AboutPanel.tsx` | 还原状态 + 订阅进度 + 进度条 UI |

### 验收点
1. 点击"检查更新"发现新版本 → 点"立即下载" → 显示实时百分比进度条（如 45% · 12.3/27.5 MB）。
2. 下载中切换到其他设置 tab 再切回"关于" → 进度条继续显示当前进度（不回到 idle）。
3. 下载完成后 → 显示" vX.X.X 已就绪，重启后安装" + 重启按钮。
4. 下载完成/下载中**重启应用**再打开"关于" → 还原为对应状态（下载中显示进度、下载完成显示就绪），无需再次检查更新。
5. `npx tsc --noEmit` 通过。
