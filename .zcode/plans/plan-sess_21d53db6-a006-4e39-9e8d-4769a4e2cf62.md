
# 上下文统计逻辑重构(对齐 `docs/claude-context-usage-tracking.md` §2-§5)

## 目标
把上下文 token 统计从「renderer 端启发式 + 单次 `UsageEvent`」重构为「adapter 端归一化 + provider-neutral `token-usage.updated` 事件携带 `ContextSnapshot`」,修正 token 数学、用 SDK 上报的真实窗口上限、补齐三类警告,并接入 StatusBar 显示。

**范围**: 核心 §2-§5。**不含** §6(activities 表/按天聚合/历史)与路径 B(`getContextUsage` 控制信道 — Agent SDK stream-json 不暴露,按文档 §7.2 优雅退化)。

## 架构变化(核心):归一化下沉到 adapter
现状: adapter 发原始 `UsageEvent`(input/output/cache...)→ renderer 的 `contextWindow.ts` 算快照。
重构后: adapter 用 `claudeTokenUsage.ts` 归一化 → 发 `token-usage.updated` 事件,载荷是已算好的 `ContextSnapshot`(含 `usedTokens/totalProcessedTokens/maxTokens/pct/warning/warnings`)→ renderer 只存+渲染,下游 provider-neutral。

## 文件改动清单

### 1. `packages/contracts/src/runtime.ts`(契约改动)
- 删 `UsageEvent`;新增 `ContextUsageEvent`:
  ```ts
  type ContextWarning = "ok" | "near-window" | "critical";
  type ContextWarningKind = "uncached-ingestion" | "near-window" | "large-prompt";
  interface ContextSnapshot {
    usedTokens: number;            // input+cache_creation+cache_read, clamp 到 maxTokens
    totalProcessedTokens: number;  // input+output+cache_read+cache_creation
    maxTokens: number;             // 优先 SDK 上报,回退启发式
    outputTokens: number;
    cacheReadTokens?: number;
    cacheCreationTokens?: number;
    costUsd?: number;
    model?: string;
    pct: number;                   // [0,100] clamp
    warning: ContextWarning;
    warnings: ContextWarningKind[];// 文档 §5 三类(本 turn 触发的)
  }
  interface ContextUsageEvent {
    type: "token-usage.updated";
    sessionId: string;
    snapshot: ContextSnapshot;
  }
  ```
- `RuntimeEvent` 联合替换 `UsageEvent` → `ContextUsageEvent`。
- 类型从此共享给 main+renderer(原 renderer `contextWindow.ts` 的 `ContextSnapshot` 类型迁入此处)。

### 2. `apps/desktop/src/main/providers/claude-sdk/claudeTokenUsage.ts`(新建,纯函数)
镜像 Synara 命名,放归一化/窗口/警告的唯一来源:
- `claudePromptTokensFromRawUsage(raw)`: `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`(文档 §3 — 缓存读取按相同权重占窗口)。
- `resolveContextWindowMaxTokens({model?, reported?, configured?, lastKnown?})`: 优先 `reported`(SDK `modelUsage[model].contextWindow`),回退 `resolveContextWindow` 启发式(Opus→1M, 否则 200k),`Math.max(reported, lastKnown)` 永不降级(文档 §4)。
- `normalizeClaudeTokenUsage(raw, opts): ContextSnapshot | undefined`: 算 `usedTokens`(clamp 到 max)、`totalProcessedTokens`、`pct`、`warning`(>=90 critical / >=70 near-window / else ok);`totalProcessedTokens <= 0` 返回 `undefined`(不 emit)。
- `decideClaudeContextUsageWarnings(raw, maxTokens): ContextWarningKind[]`: 三类阈值(文档 §5):
  - `uncached-ingestion`: uncached input >50k **或** prompt >20k 且 cache-read 比 <20%
  - `near-window`: prompt > maxTokens * 0.8(无 autoCompactThreshold,退化用 maxTokens,文档 §7.2)
  - `large-prompt`: prompt > 200k
- `mergeClaudeTokenUsageSnapshot(lastKnown, accumulated, maxTokens)`: 路径 C 合并 — `usedTokens` 用 accumulated clamp,`totalProcessedTokens` 用 accumulated 全量(文档 §2 路径 C 关键设计)。

### 3. `apps/desktop/src/main/providers/claude-sdk/SdkMessageAdapter.ts`
- `state` 增字段: `lastKnownTokenUsage?: ContextSnapshot`、`lastKnownContextWindow = 0`、`emittedWarnings: Set<string>`(跨 turn 去重 key)。
- **路径 A**(新,`handleAssistant`): 读 `message.message.usage`,调 `normalizeClaudeTokenUsage` → emit `token-usage.updated`(给中途窗口读数)。
- **路径 C**(改写 `handleResult` 的 usage 段, L466-498): 读 `result.usage` + `modelUsage` 聚合 fallback(保留现有 subagent 合并逻辑),从 `modelUsage[model].contextWindow` 取 `reported` 窗口,调 `normalizeClaudeTokenUsage` + `decideClaudeContextUsageWarnings` → emit **单个** `token-usage.updated`(载荷含 snapshot + warnings)。更新 `lastKnownTokenUsage/lastKnownContextWindow`。`turn.done` 等其它 emit 不变。
- 删除原 `UsageEvent` 字段拼装代码。

### 4. `apps/desktop/src/main/claude/RuntimeManager.ts`(L40-53)
- `emit` 拦截 `e.type === "token-usage.updated"` → `SessionRepo.updateSnapshot(session.id, e.snapshot)`(直接持久化归一化快照,而非原 raw usage 字段)。

### 5. `apps/desktop/src/renderer/lib/contextWindow.ts`(瘦身)

## 与文档的偏差(在 plan 内显式记录)
1. **路径 B 跳过**: Agent SDK stream-json 不暴露 `SDKControlGetContextUsageResponse`,无法拿实时 `autoCompactThreshold`/原生 `usedPercent`。退化:`usedPercent = usedTokens/maxTokens`,`near-window` 阈值用 `maxTokens*0.8`。文档 §7.2 把这列为预期的退化路径。
2. **§6 持久化/聚合不做**: 只保留现有的 session 行 `context_snapshot` 列(存归一化快照),不新增 activities 表/按天聚合。
3. **警告折叠进快照**: 用 `snapshot.warnings: ContextWarningKind[]` 而非文档的独立去重事件流(单 renderer 场景更简单,阈值/语义一致)。
